# 形状收口手术 · 验收方

> **读者：验收的人，不是改代码的人。**
> 配套 `形状收口手术_执行方.md`（那份给执行方，讲怎么做）。这份只讲**怎么判**。
> 两份不合并：一份文件同时干两件事，就是"一个函数干两件事，必然长出可忽略字段"。

## 一句话

**你不看它做了什么。你只看：它说的事，你复算得出来吗。**

## 为什么必须复算

执行方只有「我做了什么」的记忆，没有「应该是什么」的独立来源。所以它必然：

- 用记忆替代真相（凭记忆重建文件，而 `git show` 就有原文）
- 用估算替代实测（"47 行"、"约 160 行"）
- 用「看起来合格」替代「真的合格」（"超集所以没弱化"）

**自查永远绿。你的唯一价值是：拿同一份材料、同一组命令，自己算一遍。**

## 一、先要口径，再照它的口径重数

它给任何一个数，先问三件：

1. **数的是什么**（单位）
2. **怎么数的**（命令）
3. **排除了什么**（注释 / 定义行 / 生成物）

**然后你照它的命令自己跑一遍。** 数对不上，它就是在估。

| 这一场真实发生 | 它说 | 复算结果 |
| --- | --- | --- |
| 调用点数 | 47 行 | **60 行** |
| 债的区号 | 19 区 | **AREAS 只到 18** |
| 假桥处数 | 4 处 | **11 个文件** |
| 函数体是否夹对 | "在区间内" | **169 < 763 < 830** |

## 二、六个数：不验收数，验收「有没有口径」

形状收口要交六个量：形状份数 / 判别语法种类 / 可忽略字段 / 自由文本失败 / 入口数 / Decoder 的 null 通道。

**你不验收这六个数准不准，你验收它有没有给口径。** 答不出口径 ⇒ 这六个数是编的。

## 三、四问：问它，不听它主动说

1. **你说 N 现在是 1，你的「怎么数」别人照着能数出同一个数吗？**
2. **你说没打坏，哪一处会红？红在具体哪一行？**
3. **你说改的是这一层，说得出一件它现在不该知道的事吗？**
4. **哪些没验？**

## 四、不合格答案对照（这一场它真的这么答过）

| 它说 | 判 |
| --- | --- |
| 「断言集合是原文的超集，没有弱化」 | **超集 ≠ 没弱化**。同名用例的断言行可能被参数化了。要**断言行原文**，不要用例名 |
| 「6 条红 = 基线那 6 条」 | 断言不是证据。要**这轮 6 条的名字**，逐条对 |
| 「逻辑上等价 / 类型保证了」 | 没有会红的东西 ⇒ 只能写 `UNVERIFIED` |
| 「已修」（只复跑了同一个文件） | 修的是症状范围。要**触发条件的全集**跑一遍 |
| 「我承认没做完」 | **零交付**：没有动作、没有决定、没有债号 |
| 「没摸清 X」 | 脚本就在仓库里。没查就写「我没查」 |

## 五、你自己动手核的三件事

1. **破坏之后怎么恢复的** —— `git show HEAD:<path>` 取原文，比对 `git diff`。**「整文件重建」一律打回。**
2. **测试红了先动谁** —— 它动过断言吗？动了就给断言行原文，且集合必须是原集合的超集。
3. **守卫锚的是行为还是结构** —— 锚点跟着函数名走（`userDir()` → `hostAppDataRoot()`）⇒ 结构一变守卫就废。

## 一句话

**它说什么不重要，重要的是你照着它的话，能不能算出同一个数。**
