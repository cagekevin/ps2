# UI 细节 8 查（界面验收 SOP · 一票否决）

> **定位**：任何"看得见的东西"（页面 / 面板 / 弹窗 / 组件改样式）在说"做完了"之前，**必须过这 8 查**。
>
> **一票否决**：**任何一查没过 ⇒ 整份不许打勾**。不许"部分通过"、不许"这条以后再改"、不许用"看起来没问题"当凭证。
>
> **效力边界**：用户裁定 > 仓库根 `AGENTS.md` 硬约束 > `src/styles/tokens.css` > 本文件。用户明确否过的东西直接进红线，不必再讨论。

---

> ### ★ 本 SOP 的分工：**底线交给机器，判断留给人**
>
> 本仓机器闸主要有 `npm run lint`（转型禁令 / 层边界 / 页面白名单）与 `npm run lint:css`；完整 `npm run check` = typecheck → lint → lint:css → check:templates → check:nav → test 六道关。
> **样式没有守卫**（`style:guard` / `style:fix` / `style:baseline` / `template:guard` / `dispatch:check` 都不存在）：
> 裸色值 / 裸字号 / 裸圆角 / 图标裸尺寸一律靠 `src/styles/tokens.css` + 评审。
>
> **所以 8 查只管机器管不了的判断**：
> ① 守卫只能判"裸值"，**判不了"这个值对不对"**（对比度够不够、基色覆不覆盖全、语义有没有混用）；
> ② 守卫**判不了"该不该复用"**（自造了一个近似的组件 / 控件）；
> ③ 守卫**判不了"看起来挤不挤"**（同排等高、最坏情况撑不撑爆）；
> ④ **视觉验收本身只能在 PS 里人工看**（本仓禁 e2e / 浏览器自动化 / 截图回归）。
>
> **取证纪律**：每条判据都写清「**怎么验**」（Grep 什么 / 看哪里 / 量什么），由**人**跑、**人**判、**人**写结论。Grep 只是"帮你看全"，不是"替你决定"。

> ### 取证纪律（本仓血泪）

| # | 纪律 | 为什么 |
|---|---|---|
| ① | 一律用 **Grep 工具（ripgrep）**，不许用 shell `grep` | shell 下 `--include=*.ts` 被 zsh 当 glob 报错、`\|` 交替**静默返回空** —— **空结果 = 最危险的假证据** |
| ② | 每查都要**能复算**：把命令 + 输出贴进记录 | 别写"已检查" |
| ③ | 目标是**会动的文件**（并行会话常见）⇒ 下结论前核 mtime | 结论一律标"**截至 HH:MM**" |
| ④ | **改完再扫一遍，直到扫描结果为空** | "我改完了"不可信 |
| ⑤ | **"扫过 = 0"不等于"这族没问题"** | 扫 `z-index: <数字>` → 0 处就收工，**漏了查"规范里有没有写这一层"**（见查 5.1）|
| ⑥ | **份数 >1 ≠ 违规；同名 ≠ 同物** | 必须**读内容**，不能只看数字（见查 7.1）|

---

## 用法（三步）

1. **逐查逐子项跑一遍**，每条填 `✅ / ❌ + 证据`（命令输出或"看了哪一行"）。
2. **❌ 就改**，改完**重跑那一查**（不是只改那一处就算过）。
3. 8 查全绿 ⇒ 才允许在「验收栏」打勾。

# 查 1 · 颜色：**一处定义，按意图引用**

## 1.1 没有裸色值

**判据**：字面量色值**只允许出现在 `src/styles/tokens.css` / `global.css` / `motion.css`**（这三个文件是守卫的白名单）。组件 / 页面 scoped CSS 里出现 `#6366f1` / `rgb(99 102 241)` 即违规。

**怎么验**：

```
Grep  "#[0-9a-fA-F]{3,8}\b|\brgba?\("   → 只允许命中 src/styles/ 三个文件
```

**机器兜底**：无（`style:guard` / `style:fix` 不存在）——裸值全靠人工按 `src/styles/tokens.css` 改。

**允许的例外**（必须**逐个登记理由**，不是"忘了"）：占位素材渐变、第三方图标内置色、原版还原时写在页面 scoped CSS 里且已在页面清单登记的特例。

## 1.2 不越层引用

**判据**：本仓 token 分层 —— **原始值层**（`--c-*` / `--fs-*` / `--icon-*`）与**语义层**分开：语义层可引原始值，原始值层**不许引语义层**（会成环）。

**怎么验**：

```
Grep  "var\(--c-|var\(--fs-|var\(--icon-"   → 语义变量里应为 0
```

**违规形态**：语义变量直接写 `var(--c-nav)`（跳过语义层）—— 换主题时就它不变。

## 1.3 ★ 对比度（WCAG AA）

**判据**：文字 / 底色 ≥ **4.5:1**（正文）、≥ **3:1**（大字：≥18.66px bold 或 ≥24px）。本仓面板是深色基底（`--c-bg` #363636 / `--c-nav` #535353），**浅字压深底**是常态，**深底上的暗字是最容易踩的坑**。

**怎么验**：逐对核心组合算 —— 正文/页底、弱文字/卡片、按钮文字/主色底、反馈文字/卡片。
**本仓主色要算全**：基色表见 `src/styles/tokens.css` §零（`--c-nav` `#535353`、`--c-bg` `#363636`、`--c-header` `#424242`、`--c-surface` `#363636`、`--c-input` `#2c2c2c`、`--c-surface-raised` `#4b4b4b`、`--c-float` `rgba(64,64,64,.96)`、`--c-star` `#ffb400`）。

**违规形态**：

| 形态 | 表现 | 修法 |
|---|---|---|
| **深底上的暗字** | 弱文字 / 禁用态用比底色更暗的灰 ⇒ 整行"糊"进背景 | 整体下移一档（提亮），或加"文字版"语义变量 |
| **反馈色当文字** | 警告色直接当字色用 | 加"**文字版**"语义（`--c-*-text`），比底色版**深/亮一档**；**别改底色**（那会改观感）|
| **半透明底在深底上消失** | `rgb(ch / 0.08)` 压在深底上几乎看不见 | 把 α 提到 ~1.8× |

> ⚠️ **算对比度时注意**：本仓面板基色来自原版取样，**同一语义有新旧两套**（原版 CSS 里新旧类名并存，见 `src/styles/tokens.css` §零的两处修正）。**判断依据是"新版面板用哪套"**，不能只看命中就抄 —— 抄错就是 `#222` 那种旧版底色。

## 1.4 ★ 原版基色与"三处故意不照抄"

**判据**：本仓视觉不是原版 1:1 复制：`ADR · 视觉规范：三处故意不照抄原版` 已定案 —— **间距用 `gap`（不靠 margin 凑）· 阶梯只有 4/6/8 · 图标着色用 `fill: currentColor`**。除此之外的基色按 `src/styles/tokens.css` 走。

**怎么验**：逐条比对本页用的色值与 `src/styles/tokens.css` §零的表；**不在表里的色值 ⇒ 要么进表（写理由），要么改回表里的值**。

**有意不跟原版的**（要能说出理由）：`--c-star` 用 `#ffb400`（原版 `#b3b3b3`）—— 收藏态需要可见性。

## 1.5 底色与文字色不混用

**判据**：同一个语义变量**不在两个对立角色上复用**。
`--c-danger` 当**底色**用（红底）、又当**文字色**用（红字）⇒ 必然有一边不对。

**怎么验**：`Grep "color: var(--c-(danger|success|warning))\b"` —— 当**文字**用的地方，应走文字版语义。

# 查 2 · 尺寸与间距：**来源唯一，档位在册**

## 2.1 间距来源唯一

**判据**：同一段间距**只许有一个来源**。外层给了 padding，子项就不许再写同方向的值；**不许用负 margin 打补丁**。

**三种"重复来源"**：

| 形态 | 长什么样 | 怎么抓 |
|---|---|---|
| ① **散落** | 同一个 8px 写在 `.header` / `.banner` / `.drop` / `.container` 四处 | 数出现次数 |
| ② **叠加** | `.grid{margin-bottom:8px}` + 下一块 `.header{padding-top:4px}` ⇒ 实际 12px，两个来源 | 看相邻容器 |
| ③ **与父容器 `gap` 重复** | 父 `.panel{gap:4px}` + 子项 `margin-top:4px` | **查父选择器有没有 `gap`** |

**怎么验**：

```
Grep  "margin:\s*-|margin-(top|left|right|bottom):\s*-"        → 0（负 margin 补丁）
```

**修法**：外层一处 padding；区块间距交给**一个**选择器（首项 `:first-child` 归零）；父容器有 `gap` 时，**子项删掉同方向的 margin**（这就是 ADR「间距用 gap」的落点）。

## 2.2 间距 / 尺寸走 token

**判据**：间距（padding / margin / gap）一律 `var(--space-*)`，**不写裸 px**。本仓阶梯**只有 4 / 6 / 8**（`ADR`）—— 需要别的值 ⇒ **先改 `src/styles/tokens.css` 加档并写理由**，别就地写值。

**怎么验**：

```
Grep  "^\s*(padding|margin|gap)[^;]*:[^;]*[0-9]+px"
```

**实录教训**：曾经大量 2px —— 根因是间距尺度**缺 2px 这一档**，大家只能写裸值。⇒ **档位不够就加档（改 tokens.css），别就地写值。**

## 2.3 同排必须等高

**判据**：同一排的控件**高度必须相等**（差 1px 就能看出来）。

**怎么验**：量同一排各控件的高度来源（是 `--btn-height`？`--field-height`？还是 padding 撑出来的？）。

**实录反例**：顶栏三个控件三种高度；弹窗按钮靠 inline `height` 单独调。

## 2.4 圆角规格在册

**判据**：圆角走 `--radius-*`，不写裸值。

**怎么验**：

```
Grep  "border-radius:\s*(50%|[0-9]+px)"
```

> ⚠️ **下沉判断**：不是"每处都该用同一档"，而是**每处都该走档位**。
> 圆点用 `--radius-full`、chip 内小图标用 `--radius-xs` 是对的 —— 错的是写 `50%` / `2px`。

# 查 3 · 排版：**字号有阶，行内有高**

## 3.1 字号在阶内

**判据**：`font-size` 只走 `--fs-*`，且**只用 `src/styles/tokens.css` §一 登记的那几档**（`--fs-xs` 10 / `--fs-sm` 11 / `--fs-md` 12（正文默认）/ `--fs-lg` 13 / `--fs-base` 14 / `--fs-xl` 15 / `--fs-name` 16 / `--fs-2xl` 18）。字体预览另有 `--preview-sm/md/lg/xl`（24/38/50/72），**只给预览模式用**。

**怎么验**：

```
Grep  "font-size:\s*[0-9]+px"     → 0
```

**机器兜底**：无——裸字号没有检查，只能按 `src/styles/tokens.css` 的字号档写。

## 3.2 字重与行高在册

**判据**：`font-weight` 走 `--font-weight-*`；`line-height` 走 `--line-height-*`。

**怎么验**：

```
Grep  "font-weight:\s*[0-9]|line-height:\s*1\.[0-9]"
```

**实录**：字重 / 行高散落多处 —— **这两族的 token 当时根本不存在**，所以只能写裸值。⇒ **先建族，再收口。**

## 3.3 图标 + 中文必须 `line-height: 1`

**判据**：图标与中文**同一排**的按钮，必须 `line-height: 1`
（中文在 flex 里默认 `normal`，会**多出 2~3px 行距**，字看着往下掉），图标加 `flex: none`。

**怎么验**：找"图标 + 汉字"同排的控件，看它的 `line-height` 和图标是否 `flex: none`。

## 3.4 长文本有截断

**判据**：可能超长的文本（字体名、路径、错误信息）必须有 `overflow: hidden` + `text-overflow: ellipsis` + `white-space: nowrap`（或 `min-width: 0` 配合 flex）。

**怎么验**：逐个"会显示用户数据"的标签看有没有这套；父容器是 flex 时**还要看有没有 `min-width: 0`**（否则 ellipsis 不生效）。

# 查 4 · 布局：**不写死，不撑爆**

## 4.1 同排不写死宽度

**判据**：**菜单 / 下拉 / 提示条**不许写死宽度（用 `width: max-content` + `min-width` + `max-width`）。

**怎么验**：

```
Grep  "width:\s*1[0-9][0-9]px"
```

> ⚠️ **网格列宽、缩略图尺寸**写死 px 是**正常**的；查的是"**内容长度不可预知**却写死宽度"。

## 4.2 不撑爆

**判据**：任何面板 / 浮层 / 行，在**最长的真实内容**下都不能溢出容器、不能被压变形。

**怎么验**：**逐个浮层看"最坏情况"**：
- 字体家族名的**最长**那条
- 错误信息的**最长**那条
- 路径的**最长**那条

**常见根因**：`flex` 子项缺 `min-width: 0`；把**互斥的状态元素同时渲染了**（原版是三选一，全画就会挤爆）。

## 4.3 窄屏不挤压

**判据**：窗口变窄时，**要么横滚，要么布局自然收窄** —— 不许压成一坨、不许浮层盖住内容。

**怎么验**：把面板拉到很窄，看主区（**在 PS 里看**；本仓禁 e2e / 截图回归）。

# 查 5 · 层级与动效：**档位有册，动画不抖**

## 5.1 z-index 走档位

**判据**：不写 `z-index: 999`，走 `--z-*`（浮层 / 菜单 / 弹窗 / toast 各有档）。

**怎么验**：

```
Grep  "z-index:\s*[0-9]"
```

**规矩**：新浮层先问**"它属于哪一档语义"**，不是"我要比谁高"（后者是军备竞赛）。
**档不够就加档**（改 tokens.css + 写理由），别就地写 999。

> ★ **陷阱实录**：扫 `z-index: <数字>` → **0 处就收工**，以为这族没问题。
> **漏了查"规范里有没有写这一层"** —— 结果规范里根本没有层级阶梯表，
> 看规范的人不知道有 `--z-*`、也不知道该选哪档。
> **⇒ 对每个 token 族，除查"有没有违规"，还要查"它的档位表进规范了没"**（`src/styles/tokens.css`）。

## 5.2 阴影走阶梯

**判据**：走 `--shadow-*`，不写裸值。

**怎么验**：

```
Grep  "box-shadow:\s*[^v][^;]*[0-9]+px"
```

> ⚠️ `box-shadow: 0 0 0 Npx var(--x)` 是**选中光环**（描边），不是投影，不受此约束。

## 5.3 过渡只用合成属性

**判据**：`transition` / `@keyframes` 只用 **`transform` / `opacity`** —— 用 `left` / `top` / `width` / `height` 会触发 **layout**，掉帧。

**怎么验**：

```
Grep  "transition:[^;]*\b(left|top|right|bottom|width|height|margin|padding)\b"
```

**例外**：进度条的 `width` 过渡 —— 它本来就是"宽度"的语义。**这类例外要写清理由。**

## 5.4 动效时长在册

**判据**：`transition` / `animation` 时长走 `--duration-*`；旋转类周期（spinner）用专门旋钮。

**怎么验**：

```
Grep  "(transition|animation)[^;]*[0-9]+(\.[0-9]+)?m?s"
```

> 本仓动效 token 落在 `src/styles/motion.css`（守卫白名单之一）。

# 查 6 · 交互态：**可点必须有反馈**

## 6.1 可点元素有 `:hover`

**判据**：凡 `cursor: pointer` 的元素都该有 `:hover` 反馈（**走公共件的算过**，`src/components/` 的 `G*` 基础件已提供）。

**怎么验**：列出所有带 `cursor: pointer` 的规则，逐条看有没有 `:hover`。

## 6.2 按下反馈（`:active`）—— **按需**

**判据**：`:active` **不是"每个可点元素都要"**。有更贴切的状态表达时，硬加位移反而怪。

**有意不加的**（要能说出理由）：开关的 label（点击反馈就是控件自身状态变化）、颜色选择器（选中态本身就是反馈）、可点行（按下反馈可选）。

## 6.3 disabled 态真实可见

**判据**：按钮 / 输入框被 `disabled` 时，视觉上要**看得出不能点**（变淡 / 灰底 / `cursor: not-allowed`）。

**判据细节**：**主按钮** disabled 宜用"整体半透明"、**次要按钮**宜用"文字变淡" —— 两种策略并存是**有意**的，不算不统一。

**怎么验**：`Grep ":disabled"`，逐条看它作用于哪种按钮。

## 6.4 键盘可达（focus）

**判据**：所有可点元素**键盘 Tab 能到、能有可见 focus 环**。
focus 环颜色走 `--color-focus-ring`。

**怎么验**：Tab 走一遍主要流程；看 focus 环有没有被 `outline: none` 掉而没补替代。

# 查 7 · 组件与令牌：**一份真源，一名一物**

## 7.1 ★ 复用现有件（不许自造）—— 这是本查最难的一步

**判据**：已有公共件就照它，不另造近似的。
- **UI 基础件真源** = `src/components/`（`G` 前缀：`GButton` `GInput` `GCollapse` `GDropdown` `GMenu` `GPopover` `GRadio` `GSegment` `GTooltip` `GAnchorGrid`；非 G 前缀的通用件如 `CheckBox` `SelectBox` `BaseGroup` `EmptyState` `PageShell` `PageBottomBar` `ToastHost` `ErrorBoundary` `ConfirmHost` `Icon`）
- **控件现状与缺口** = `src/components/`（直接看组件目录）· `docs/CONVENTIONS.md`
- **视觉 token 真源** = `src/styles/tokens.css`（**SSOT**，ADR）

**★ 怎么找"有人自造了"**（自造不会自己招认）：

```bash
cd src
for c in btn button input group row item cell card chip tag menu popover modal dialog empty spinner radio checkbox segment collapse; do
  n=$(grep -rhoiE "\.${c}[A-Za-z0-9_-]*[ ,{]" --include="*.tsx" . | wc -l | tr -d ' ')
  [ "$n" -gt 1 ] && printf "%-10s %s\n" "$c" "$n"
done
```

**命中 >1 的族逐个读**：

| 读出来是 | 处置 |
|---|---|
| 形态**相同**（逐字或近乎逐字）| **收口**：删私有件，改用 `src/components/` 里的公共件 |
| 形态**不同**（如按钮 vs 卡片）| 在 `src/components/` **注明"为什么它不复用"** —— 不收也要有理由 |

> ⚠️ **份数 >1 不等于违规**：`.emptyTitle` / `.emptyIcon` / `.emptyDesc` 是**不同用途**的类。
> 一个族里有十几个定义很正常。**必须读内容判断，不能只看数字。**
> ⚠️ **新增控件要过准入**：真要新造一个按钮 / 勾选框 / 输入框 / 菜单 / 弹窗 / 折叠行 / 页面级 Section ⇒ 走 `docs/CONVENTIONS.md`（原版出处 + 现有控件排查 + ASCII 结构图 + 数据流 + 用户明确批准"同意新增 \<控件名\>"），**不许先写再补报备**。

## 7.2 ★ 同名不同物 —— 最危险的一类

**实录**：`.spinner`（**文字型**："生成中…"）与 `.spinner`（**旋转圆环**）——
**名字相同，实现完全无关**。

**判据**：两个类**同名**但**实现不同** ⇒ 必须**改名**。
名字要**说明它的形态**（`.spinnerText` / `.spinnerRing`），不是说明它的时机。

**怎么找**：扫各族份数时，命中 >1 就**必须读内容** —— 同名不同物**只有在读的时候**才会露出来。

**另一类同名冲突**：**布局容器**与**浮层卡片**都叫 `.panel` ⇒ 前者改名 `.column`，让 `.panel` 只表示浮层。

## 7.3 每条线都要说得出职责

**判据**：每一条线（border / 分隔线）都必须能回答"**它分隔了哪两种东西**"。答不出 ⇒ **删**。

**怎么验**：

```bash
for f in $(find src -name "*.tsx" -o -name "*.css"); do
  awk '/^[^ \t].*\{$/{sel=$0; sub(/ \{$/,"",sel)}
       /border-(top|bottom|left|right):|^[ \t]*(height|width):[ \t]*1px/{
         gsub(/^[ \t]+/,""); printf "%s:%d | %s | %s\n", FILENAME, FNR, sel, $0}' "$f"
done
```

**该留的**：容器边框、拖拽区虚线、头部 `border-bottom`、底部 `border-top`（仅限确认框）、栏边界。

**该删的**：卡片本身已有边框 + 红字图标已说明"这张有问题"，再画一条是**重复表达同一件事**。

> ⚠️ `border-*: Npx solid transparent`（三角箭头）**不是分隔线**。

## 7.4 令牌体系完整

**四个子项，逐个验**：

| 子项 | 判据 | 怎么验 |
|---|---|---|
| **无悬空** | 引用的变量都有定义 | 比对"引用的" vs "定义的" |
| **无自引用** | `--x: var(--x)` = **无效值**（不报错、像别名）| 看 tokens.css 里有没有同名自指 |
| **无 `!important`** | 出现即违规 | `Grep "!important"` |
| **死变量先分类** | 见下 | 比对"定义的" vs "引用的" |

**死变量分类**（**别一看"没人用"就删"**）：

| 类 | 处理 |
|---|---|
| **枚举型**（色板 / 字号 / 图标档 / 间距 / 圆角 / 层级）| **保留** —— 完整刻度是资产 |
| **语义型**（`--c-danger-text` 这类）| 有定义就该有用途；没有就该删 |

> ★ **自引用的阴**：`--ease-out: var(--ease-out);` —— 看着像别名，实际是**无效值**，
> 导致**所有 `transition` 的缓动失效**（落到浏览器默认 `ease`）。**不报错、不警告。**

## 7.5 选择器结构干净

**判据**

1. **不用元素选择器写组件样式**（`.head button` / `.row input`）—— 作用域失控；例外要写明理由。
2. **选择器深度 ≤ 2 层后代**；再深就是耦合。
3. **不用三层以上复合类**（`.a.b.c`）。
4. **同一规则里同一属性不写两遍**（笔误检测）。

**怎么验**：`Grep` 出所有规则头，逐条看。

## 7.6 无死类

**判据**：CSS 里定义了但**既没被模板引用、也没被别的规则继承**的类 ⇒ 删（或写明"未接线，保留待对齐"）。

**怎么验**：比对 CSS 类名 vs 模板里的类名引用。

> ⚠️ **必须处理动态拼接**：`styles[`st_${status}`]` 这类静态扫不出来。
> 扫描报出来的"死类"要**逐个回读模板**，确认是动态拼接再放行。

**"未接线"的处理**：原版有、重写还没接的样式（如 `.groupLabel`）——
**保留 + 注释写明"未接线"**，别当死代码删。

# 查 8 · 语义与文案：**正常零状态，异常带出口**

## 8.1 正常态零状态

**判据**：**正常态不显示** 徽章 / 状态 / 版本 / 计数 / 时间。

**怎么验**：逐个"状态显示"看它在**一切正常时**会显示什么。

> ⚠️ **要区分"冗余状态"与"有用指示"**：
> 有用：字体收藏态、字数计数（用户需要知道）。
> 冗余：绿点写"连接正常"、版本号、"已就绪"。

## 8.2 异常带出口

**判据**：**异常才多说一句**，且**必须带一个动作**（不许只描述不给出口）。

**怎么验**：找所有错误 / 失败 / 空态，看它有没有"重试 / 去某处 / 换一条路"。
本仓已有出口件：`src/components/ErrorBoundary.tsx`（重试渲染）、`ToastHost.tsx`、`ConfirmHost.tsx`。

## 8.3 读不到 ≠ 没有

**判据**：读盘 / 取数失败**不许渲染成空态** —— 必须**保留已读到的内容 + 重试**（承 `ADR · 读可降级但必须标记`：读要返回 `Result` 的 error 分支）。
本仓典型反面：`src/repo/sys-font.ts` 读不到时返回 `[]`，与"真的没有系统字体"混成一件事。

**怎么验**：找"catch 之后渲染空列表"的分支。

## 8.4 文案不出现实现黑话

**判据**：用户可见文案里**不许出现**：磁盘 / 目录 / 索引 / 注入 / 预算 / 兜底 / **尚未落地** / **序列化** / 命令 id / 事件 stringID。

**怎么验**：

```
Grep  "尚未落地|未落地|磁盘|索引|注入|预算|兜底|序列化"
```
（**只查字符串**，注释里的术语不影响用户。）

**实录反例**：

| 原文案 | 问题 |
|---|---|
| `工程数据序列化失败，未保存` | 黑话「序列化」，且是**自造**非源版 |
| `（分组功能尚未落地）` | 开发术语「落地」 |

**修法**：改成用户语 + **补出口**（"尚未实现。可先在字体框选素材，再点「加入选中素材」"）。

> ⚠️ **区分"源版原文"与"自造"**：源版带黑话的文案**保留**（忠实还原）；
> **本仓自造**的带黑话的文案**必须改**。判据是**来源**，不是"有没有黑话"。
> 本仓文案真源：失败文案与错误码语义在 `src/types/result.ts`（**SSOT**），页面私有文案放页面内。

## 8.5 动作语义单一

**判据**：同一个动作不许有两个入口（组级「全开全关」与行开关同时存在 = 违规）。

**怎么验**：列出所有"能触发同一件事"的入口。

# 三条不许

1. **不许分批打勾**：这不是"完成度进度条"，是**闸门**。
2. **不许用截图代替取证**：截图表象，判据要**可复算**；本仓也**禁**自动截图回归。
3. **不许把"某个位置不好"写成"这个机制不许用"**
   ⇒ 立判据前先自检：**用户否的是实例还是规则？** 否实例 ⇒ 判据写成"**约束条件**"，不写"禁止"。

**已确认的用户裁定**（可直接引用，不必再讨论）：

- **读失败不许说成空态**（承 `ADR`）
- **能力不许砍**
- **规范要能自生长**（发现更好做法 ⇒ 改规范 + 写理由，而不是绕过它自己造一份）
- **样式数值只有一个来源**（`ADR`，`style-guard` 强制）
- **原版不是标准答案**（线上 PS 应用缺陷，非本仓文档：视觉照搬可以，工程别照抄）

# 附录 · 陷阱清单（最容易骗人的九条）

| # | 陷阱 | 教训 |
|---|---|---|
| A | **"扫过 = 0" ≠ "这族没问题"** | 扫 `z-index: <数字>` → 0 就收工，漏了查"**规范里有没有写这一层**" |
| B | **份数 >1 ≠ 违规** | `.emptyTitle` / `.emptyIcon` 是不同用途。**必须读内容** |
| C | **同名 ≠ 同物** | `.spinner` 文字 vs 圆环 —— 只有读的时候才会露出来 |
| D | **"我改完了"不可信** | **改完再扫，直到为空** |
| E | **死变量 ≠ 死代码** | 枚举型（色板 / 字号 / 图标档）保留完整刻度，一个都不该删 |
| F | **自引用不报错** | `--x: var(--x)` 看着像别名，实际是无效值 |
| G | **量具会骗人** | 对比度算错底色（拿了旧版那套）差点误判 —— **工具的输出要交叉验证** |
| H | **原版文案带黑话要留，自造的黑话要改** | 判据是"**来源**"，不是"有没有黑话" |
| I | **先建族，再收口** | 字重 / 行高 token 不存在时，只能写裸值 —— 收口前先看**族建了没** |
| J | **守卫绿 ≠ 界面过关** | `npm run lint` 只管转型 / 层边界 / 白名单；对比度、复用、撑爆、语义它一条都不管 |
