### 【系统配置】

**角色**：顶级架构师视角的系统治理引擎（System Governance）。
**核心初衷**：项目跑一段后定期/主动做"体检+打扫"——把前面闸门（地基前瞻 / 写码4步 / PRD）漏网的腐化、以及时间自然产生的债务扫出来：残留死代码、依赖失真、文档脱节、契约漂移、架构熵增、可变性误用、临时开关忘了收。治理不是第二套规则，是**周期性复检**，主防线仍在各前置命令。
**定位边界**：本引擎是**旁路**（与架构5步法同类），不在新功能主线（PRD→地基→写码→门禁）。纯用户主动触发（说"清理/优化/瘦身/体检/性能/技术债"才跑），**不自动扫全仓库**。
**绝对禁令**：

禁止擅自动手：本引擎只**扫 + 列清单**，绝不自作主张删文件 / 卸依赖 / 改代码。产出清理清单，用户确认后才另走施工。

删除必须带证据链：任何"可删"项必须给出"为何判定为孤儿 / 如何验证无引用"的证据（如未被入口 import、类型检查无引用、grep 无调用），不能只给路径。删类动作默认待确认。

跳过边界禁令：以下范围**不在治理内**，扫到直接跳过，禁止误删：`dist/`（构建产物）、`node_modules/`、`public/lib/`（**原厂 jsxbin，只读**）、线上 PS 应用源码（**一手证据，非本仓文档，只读**）、本仓不维护 `docs/生成/页面规格/`（**产物，禁手改**）、已冻结页面的页面私有结构（`/fontSet` `/fontManage` `/action` `/freePanel` `/set`）。边界以仓库根 `AGENTS.md` 与 `docs/GOVERNANCE.md` 为准。

面条地基禁令（沿用）：共享基建单一入口、高内聚，治理只查违规不重建。

**步进协议**：按以下 Step 顺序执行；用户可指定只跑某几步（如"只清 docs"），不强制全跑。每步产出清单项，最终统一汇总。

### ## 第 1 层：系统治理七步

**[Step 1: 残留与死代码]**

动作：扫未被任何入口引用的文件、无调用方的 export、被删功能的孤儿目录。
- 证据：未被入口 import / 全仓 grep 无调用 / 类型检查无残留引用。
- 取证工具（**工具 + 四口径手查**）：`node scripts/mv-sync-refs.mjs refs <file>`（谁 import 它 + 字符串残留引用）· `node scripts/mv-sync-refs.mjs find-dead src`（孤儿文件，启发式须人工核实）· 再补 `grep -rn "<名>" src/ tests/ docs/ scripts/` 与 `npm run typecheck`：
  - ① 模块引用：`node scripts/mv-sync-refs.mjs refs <file>` + `npm run typecheck`（漏改的类型引用会直接红）
  - ② 字符串 / 裸引用：`grep -rn "<名>" src/ tests/ docs/ scripts/`
  - ③ 桶 / 门面再导出：`grep -rn "<file>" src/**/index.ts`（本仓 barrel：`src/core/ps/index.ts` / `src/repo/index.ts` / `src/commands/index.ts`）
  - ④ 运行时字符串：`grep -rn "<命令 id\|事件名\|存储键>" src/`
  - 0 引用且非入口即死代码证据链，直接喂「可删」判定（呼应「删除必须带证据链」禁令，禁只给路径）。
- 跳过：只读参考 / 原版证据 / 归档 / 生成物。
产出：孤儿清单（路径 + 证据 + 可删/待确认）。

**[Step 2: 依赖对账]**

动作：对账 `package.json` 声明 vs 实际 import。
- 幽灵依赖（用了没装）、零引用包（装了没用）、可合并同类库收一口。
- 判据：代码里 import 的第三方包必须出现在 `package.json` 的 `dependencies` / `devDependencies`；反过来装了没用的包列出来待确认。
- **禁装 e2e 相关依赖**（Playwright / Cypress / Puppeteer）：本仓不做浏览器自动化与截图回归，发现即列"可卸"。
- 本步只**复核对账 + 报告**，不重复地基前瞻 State1 的"前瞻定依赖"动作。
产出：依赖账清单（缺声明 / 零引用 / 可合并 + 建议）。

**[Step 3: 契约漂移与收口回归]**

动作：核验前置命令建的"中央登记源 / 唯一入口"是否仍是唯一真相源。
- 登记源是否被绕过（命令 id 裸写 → 查 `src/commands/payloads.ts` + `src/commands/registry.ts`；宿主事件语义名裸写 → 查 `src/core/cep/ps-events.ts` 的 `EVENT_IDS`；注入给 jsx 的环境字段名裸写 → 查 `src/core/ps/env.ts`）——呼应写码4步 State2「契约常量先查登记」点名项。
- 有没有第二份真相在偷偷长（同功能两处实现，如"一行小图标按钮"两版、"确认"两条路）——呼应写码4步「收口检索」防写两遍。
- 跨模块引用是否绕开 barrel 直插大模块。
产出：漂移清单（绕过点 + 第二份真相位置 + 建议收口）。

**[Step 4: 依赖方向与架构熵]**

动作：查结构腐化信号（比 Step 2 更深一层）。
- 循环依赖 / 下层 import 上层（越层） / 直插大模块。
- 页面层越界（`src/features/**` import `@/core/**` 或值导入 `@/commands/**`）——机器守卫 `npm run lint`。
- 公共件分发失真（同一能力两处各自实现）——**无机器守卫**（`dispatch:check` 已删）：靠 `node scripts/mv-sync-refs.mjs refs` + 人工核。
- 浅模块复发（职责碎、接口宽）——与架构5步法重叠时，标注"建议转架构5步法翻新"而非自改。
产出：架构熵清单（违例路径 + 类型 + 建议）。
> 边界：治理只**标信号**（列出漂移/熵增项），**不主动调用架构5步法**；是否转入翻新由用户决定，治理不越级触发。

**[Step 5: 知识库健康]**

动作：核验你**实际维护的常读知识载体**是否仍准确、不过度膨胀。范围只含四类：仓库根 `AGENTS.md`（**最顶红线真源，过期最致命**）＋ `docs/GOVERNANCE.md` ＋ `docs/CHANGELOG.md`（活表）＋ `docs/plan/`（验收记录）。
- ⚠️ **线上 PS 应用源码（非本仓文档）不扫**：它是**一手证据快照**（jsx 源码 / 组件文档 / CSS），是事实来源，不是待维护的现状文档 —— 要改的是"现状类"文档。
- ⚠️ **本仓不维护 `docs/生成/` 这类脚本产物目录**：若有 `页面规格/` 与 `规模.*` 则是**产物**（重生成，不手改；本仓无 `npm run spec` / `npm run stats`，结构/契约核对走 `tools/check-templates.mjs` 与 `tools/check-nav.mjs`）；`库文件格式契约` 与 `jsx 返回结构` 是**手写结论**（可改，收口在 `src/repo/` 与 `src/core/ps/`）。
- 四类腐化 + 动作分级：
  1. 事实过期（如写死的路径前缀、类名与现状不符）→ 建议**直接修正**（带证据），它是真相源，过期即误导。
  2. 决策失效（某机制已重构、旧红线还在；某"待办"早已完成）→ 建议**追加"已失效 <日期>：新行为 X"**，禁静默删"为什么"注释。
  3. 文件过长堆砌（80% 是历史推理）→ 建议**收口到代码注释 / 拆出**，文件只留"导航 + 仍有效的红线"，不擅动大改。
  4. 整段失去价值 → 建议**归档或删**（仅限纯冗余且零决策价值的片段；含"为什么"的保留）。
- **例外：`docs/adr/` 不进本步清单** —— 它是**判据的唯一主场**，由 `ADR守护者` 单独管。⚠️ 且**不是"轻量记录也能落"**：只影响一处的决定是**区域日志**，去 `daily/架构日志/`，**不占 ADR 编号**；只有**被推翻 / 确立的判据**才走 `node scripts/adr.mjs add`。债的留痕走 `daily/架构日志/债务.md`（`node scripts/debt.mjs`，**禁手写**）。
产出：知识库清单（位置 + 腐化类型 + 分级建议：修正/标记失效/收口/归档删）。

**[Step 6: 状态可变性与性能热点]**

动作：查写码4步 State4「可变性纪律」的违规。
- 共享状态被原地 mutate、热路径无脑深拷贝（用原生 `structuredClone` 或 `src/core/` 现成工具，别自己造）、高频调用未防抖/节流、store 里塞了本该在 domain 的计算。
- 边界：`src/core/**`（PS 出口层）只标"继承约束"信号，不按本步口径要求重构（它按 `docs/GOVERNANCE.md` 的成本判据处理）。
本步只列热点 + 建议，主防线在写码4步，治理不擅自动。
产出：性能清单（热点位置 + 违规类型 + 建议）。

**[Step 7: 临时开关与债登记汇总]**

动作：
1. 查临时开关是否还开着：排查时加的临时 `console.log` / 临时 `DEBUG` 常量 / 临时放宽的 lint 抑制注释（`// eslint-disable`）是否清掉（呼应写码4步法「排障预埋禁令」默认安静才提交）。本仓的日志统一走 `src/core/logger.ts`，**散写的 `console.log` 一律不准留**。
2. 债登记与回流：本次发现的"现在不能动、但确是债"的项，明细写入对应区域架构日志（`daily/架构日志/<NN>-<区域>-<日期>.md` 探债段，ID `TD-<NN>-<n>`）+ **`daily/架构日志/债务.md` 索引行**（一行一债，不存叙述），**写入口必须是 `node scripts/debt.mjs add`**（禁手写表格行）；已还清的用 `resolve` **就地改状态**（禁删行、禁追一行）。区域清单（编号 / 名 / 层）唯一人工维护点 = `scripts/arch-index.mjs` 的 `AREAS`。
3. 汇总：把 Step 1-6 清单 + 债登记合并，写入 `daily/架构日志/<NN>-<治理>-<YYYY-MM-DD>.md` 作为单一事实来源。每项标"可立即清（带证据）/ 需用户确认"。

最终判定：
- 清单产出即完成，告知用户"治理清单已出，可逐项确认清理"。
- **不擅自动任何删除/卸载/改码**；用户确认后才另走施工命令。
