# 删+做（删除操作 SOP）

> **一句话**：**删只有一个理由 —— 清障**：删掉**挡着正确架构的旧结构**，让正确形态长出来。**答不出"删了它降哪一项复杂度"就不删**；**"为了删而删"不存在**。
>
> **效力边界**：仓库根 `AGENTS.md` 的硬约束（页面契约 / 控件准入 / 三个动作 / 已完成页面冻结）> `docs/GOVERNANCE.md` > 本文件。

---

## 一、删 = 清障（唯一动机）

**删不是独立目标，是"做对"的副产品**：先写正确形态 → 照它写 → 旧结构自然作废 → **同批**删掉、不留半态。

**只有三类可删**（都是"挡着正确架构的旧结构"）：

1. 被新实现**取代**的旧实现；
2. 与正确架构**相冲突**的结构（第二份真相 / 绕过唯一入口的旁路）；
3. **幽灵预留**（零消费、为将来铺路的空壳）。

> ⚠️ **"东西太多想清一清"也属于本条** —— 那些"多出来的东西"之所以该删，是因为它们**挡路 / 是第二份真相 / 是空壳**，不是因为"多"。**删的理由永远是结构错，不是数量多。**
> **没有"为删而删"这种事** —— 凡是为了"变少 / 好看 / 清爽"去删，都是错的。

---

## 二、准入判据（动刀前必答）

**第一问（答不出 ⇒ 不删）**：**「删了它，哪一项复杂度真的降了？」**

- ✅ 可接受：判据份数 **N → 1** · 链路**环节数**减少 · 兜底数**净减** · 改动半径变小 · 接口宽度变窄。
- ❌ 不可接受：「少一个文件」「少一层」「少一个同步点」「看着多余」「没人用」—— 这些是**次要收益，不足以单独构成删的理由**。

**白删信号（出现即停手）**：

- 删完**接口宽度没变**（只是把列表从两处并成一处）；
- **少了一层却没少一个真相**；
- 你删的东西**没有替代者**（删完功能就没了，而不是换了个更好的实现）。

**绝对不许删**（动了就是砍功能 ⇒ **停下来问用户**）：

- 命令 / 入口 / 功能 / 能力 / 对外契约 / 持久化格式。
  - 本仓对应：命令入口（`src/commands/registry.ts` 的 `defineCommand` 注册项）· PS 出口契约（`src/core/**` 与 `docs/CONVENTIONS.md`）· 云同步契约（`docs/CONVENTIONS.md`）· 库文件格式（`.kux/.kuc/.kug/.kuf/.kus`，判据见 `src/repo/（库文件格式收口在 repo 层，详见 docs/CONVENTIONS.md）`）· `src/core/ps/env.ts` 的 `PS_ENV` 字段名（注入给 jsx 的环境契约）。
- 已冻结页面的页面私有结构：`/fontSet` `/fontManage` `/action` `/freePanel` `/set` 只允许修 bug / 数据错误 / 安全问题。
- `docs/生成/` 里**手写**的两份（`库文件格式契约` / `jsx 返回结构`，本仓收口在 `src/repo/` 与 `src/core/ps/`）与**产物**的边界（产物不许手改、手写的那两份可改；本仓不维护 `docs/生成/` 这类脚本产物目录）。
- 判据一句话：**「删了它，用户能做的事变少了吗？」** 变少 ⇒ 不许删，摆 A/B/C 选项交用户。

## 三、怎么删（顺序）

1. **先写正确形态**：这段代码正确落地时该长什么样（一屏以内）。写不出 ⇒ 回去读代码，**不许动手**。
2. **照正确形态写 / 收口**（同一判据 **N → 1**）。
3. **旧结构作废 ⇒ 同批删**：列出被取代 / 相冲突 / 空壳的清单，逐个**判死** —— 四口径，缺一不算查清：

   | # | 口径 | 命令（本仓口径） |
   | --- | --- | --- |
   | ① | 模块引用（谁 import 它） | `node scripts/mv-sync-refs.mjs refs <file>` ＋ `npm run typecheck`（漏改的类型引用会直接红） |
   | ② | 字符串 / 裸引用 | `grep -rn "<名>" src/ tests/ docs/ scripts/`（refs 的第二段也列，但只是原始命中，需人判） |
   | ③ | 桶 / 门面再导出 | `grep -rn "<file>" src/**/index.ts`（本仓 barrel：`src/core/ps/index.ts` / `src/repo/index.ts` / `src/commands/index.ts`） |
   | ④ | 运行时字符串 | `grep -rn "<存储键\|事件名\|命令 id>" src/`（命令 id 在 `src/commands/payloads.ts`；事件语义名在 `src/core/cep/ps-events.ts` 的 `EVENT_IDS`） |

   ⚠️ **单一 grep 命中 0 不单独算证据**（模式选错就查不到）→ **四口径交叉**，再补机器守卫：
   `npm run lint`（页面层越界 / 断言禁令）、`npm run typecheck`。
   > **搬移 / 改名**用 `node scripts/mv-sync-refs.mjs rename|move|move-dir [--dry]`（自动全库改写 import，含 `.tsx` 文件）——
   > ⚠️ **它改 import，不改字符串** ⇒ `docs/` 与 `scripts/` 里的字符串引用必须手工同步；搬完照样跑 `npm run typecheck` + `npm run lint` 复核。**禁止手写 mv 后不查引用。**

4. **逐条定性（三选一，每条给依据）**：
   - **真死** ⇒ 删；
   - **被取代 / 断链** ⇒ **接上**（不是删）；
   - **是能力 / 契约** ⇒ **停，走用户确认**（不许删）。
5. **清剿尾巴**：删字段 → 同步删接口 / 解构 / 死分支；加新注释 → 删被取代的旧注释。**不留"以防万一"的旧实现**。
6. **收尾对账（半径外孤儿）**：删完再问「这次改动让**谁**失去了消费者」—— 那些在本次 diff **之外**、因我退役了上游而变零引用的符号 ⇒ **逐条处置**（真死删 / 接上 / 是能力留痕）。
7. **只删不做 = 半态 = 不合格** —— 删和做必须**同一批完成**（写代码4步法的"动作 2：建文件 = 一次替换"是同一条纪律的另一面）。

---

## 四、验收口径（全中才算删对了）

| # | 口径 | 判据 |
| --- | --- | --- |
| 1 | **功能不变** | 改前能做的，改后一样能做，**一个入口都不许少** |
| 2 | **代码更少** | **是结果，不是目标** —— 禁止以「行数下降」为由删任何东西 |
| 3 | **复杂度实降** | 能指出降在**哪一项**（份数 / 环节 / 兜底 / 半径） |
| 4 | **有凭证** | 删了什么、为什么、四口径输出，**逐条说得出** |

---

## 五、速查

```
想删东西
  ├─ 唯一动机：它挡着正确架构吗？（被取代 / 相冲突 / 空壳）── 不是 → 不删
  ├─ 准入闸：「删了它，哪一项复杂度真的降了？」──── 答不出 → 不删
  ├─ 是不是命令 / 入口 / 功能 / 能力 / 契约 / 持久化格式？──── 是 → 停，问用户（砍功能）
  ├─ 撞上已冻结页面的私有结构？──── 是 → 只许修 bug / 数据错误 / 安全问题
  ├─ 白删信号？（接口没变窄 / 没少一个真相 / 无替代者）── 是 → 停
  └─ 顺序：先写正确形态 → 照写 → 四口径判死 → 同批删旧 → 不留半态 → 半径外对账
```

> **一句话**：**先把正确形态写出来，收口到一份真相，顺手删掉挡路的旧结构 —— 删是清障，从来不是目的。**
