# 横切排查派活 · 操作手册

## 一、派活
- **一个 AI 只查一个横切**，查什么自定（剩余没查过的）。
- 结构照 `.codebuddy/commands/形状收口手术_执行方.md`。
- 产出：`daily/架构日志/<NN>-跨区-横切-<主题>-<日期>.md` —— `NN` = **主责区号**，取 `scripts/arch-index.mjs` 的 `AREAS`（只有 `01`–`13`）；带 `-跨区-` 的轮次不占区域行，`node scripts/arch-index.mjs --write` 会收进「跨区轮次」列表。
- 查完**自己登记债务**：`node scripts/debt.mjs add --area <NN> ...`（`NN` 同上）。**区号只有 01–13**：写不存在的区号不会报错，但区名会退化成裸数字，且 `index.md` 扫不到该轮次。
- 判据 = 执行表 + **当前代码实测**（**代码是唯一判据**）。**不引用别的报告**；`daily/架构日志/` 是过程日志，只当线索，数字自己复算。

## 二、查完之后：同一句话发 5 遍
```
还有可能漏的地方吗？还有出错的地方吗？薄弱地方再查一遍。
```
- 一字不改，一遍一遍发；它回完一遍再发下一遍。
- **查什么、怎么查，不归你管**，不要指定、不要提示、不要补充。

## 三、落盘规则
- 每遍**原位修正**报告：改对应章节，**不追加新章节**。
- 文件不随遍数变长。读者只看最终结论，不翻历史。
- 修了什么不进正文，直接改对的地方。

## 四、禁区
- 只查不改：`src/` `scripts/` `docs/` 一字节不动（本仓没有 `tests/` 目录，测试在 `src/**/*.test.ts`）。
- 不 revert / stash / commit / clean。
- 唯一写操作：自己的轮次文件 + `debt.mjs add`。

## 五、卡住时
- 长文件一次写会被截断 ⇒ 分小段写，每段不超 80 行。
- 账本被多个 AI 同时写 ⇒ 每次 `add` 后 `show <新ID>` 回读，行丢了重跑。
