# 形状收口手术

> **读者：改代码的人。**
> 配套 `架构师改码7步法.md`（全集）。冲突以全集为准。
> 这份只留**判据 + 操作骨架**（十五刀落点表 + 前置量 + 验收）。论证与反例已剥离，判据原样保留。

## 这是什么（一句话）

把 N 份混乱收成 1 份秩序。同一件事（读文件 / 判数据 / 写盘）在仓里长出 **N 种形状、N 个入口、N 种判别语法、N 个字段名**时用它。前九刀收形状，10–14 收写法，最后收可抄性。七步法管「改对」，这套管「改得完」。

## 四条根本判据

| #   | 判据                       | 一句话                                                                         |
| --- | -------------------------- | ------------------------------------------------------------------------------ |
| 1   | **层数 = 形状数 = 入口数** | 三个数对不上 ⇒ 有层在兼职。                                                    |
| 2   | **失败在类型上取不到值**   | 坏了就拿不到值；`ok:false` 那一臂上不许有 `.value`。                           |
| 3   | **一个函数只干一件事**     | 兜底 / 归一化 与 判断好坏 同函数 ⇒ 必拆。                                      |
| 4   | **合法不是理由**           | 两种写法都能跑、都过测照样是债；判据是「**这个概念还能不能写出第二种样子**」。 |

**唯一可以不收的三种情况**（其余「合法 / 历史 / 麻烦」都不算）：

| 可以留     | 判据                                                                |
| ---------- | ------------------------------------------------------------------- |
| 不同语义   | 名字相同但答不同问题 ⇒ 必须在文件头写明区别，否则下一个人当成一回事 |
| 外部形状   | DOM / Node / 宿主给的签名，改不了                                   |
| 跨进程边界 | 已发布的序列化格式不能动                                            |

## 优先级：底层失败原因 > UI 文案

- **P0 底层失败原因**：任何层不许丢「为什么失败」，也不许改写成自己的话。错误对象原样上抛，或只带 `code` + 观测（字段 / 期望 / 实际 / errno）。
- **P1 UI 文案**：可不写、可先顶码、可后补。
- **判据一句话**：删掉所有 UI 文案，用户还能知道失败在哪吗？不能 ⇒ 补原因不是补句子；能（难看）⇒ 合格。
- 推论（只约束新写与正在改的）：先「失败可上抛」再补 UI；文案不齐写码不造句；存量不追溯。

**中文只有两个合法位置**（别把这条当成「中文全禁」）：

| 位置 | 判据 | 例 |
| --- | --- | --- |
| `msg`（用户看的话） | 最终会出现在界面 / toast / 失败提示里 | `msg.data.fn.libFileNotJson(kind)` |
| **开发者断言**（不上 UI） | 目标是**写代码的人**：注入缺失、装配顺序、mock 拒绝参数、环境不支持 | `throw new Error('extractImageColors: image 源需要注入 createCanvas')` |

除这两处之外的中文一律违规 —— 最典型的是**数据层自己造句**（`return { status:'error', reason:'字体设置不是对象' }`）：
它既不是 `msg`（改文案要动逻辑），也不是开发者断言（用户会看到）。收法是换成码 + 观测，或调 `describeDecodeFail`。

**判据一句话**：这段中文的**读者是谁**？写代码的人 ⇒ 断言，可以留；用户 ⇒ 必须来自 `msg`；两者都不是 ⇒ 它在掩盖一个该被分类的失败。

## 开工前置：0 号前提 + 九个量 + 一件凭据

**0 号前提（域锁定，决定后面的数能不能成立）**

- 同一棵树同时只许一个写入者。
- 开工第一行声明占用：`本次只动：<目录 / 文件清单>`。
- 别人在动的文件不许碰。
- 在途半态禁止：改了形状不跟消费点，哪怕剩 1 处也要当轮跟完。

**九个量（1–6 形状 / 7–9 写法；只报 1–6 就开始动手 ⇒ 形状对写法散）**

| #   | 必须报               | 怎么数                                                                       |
| --- | -------------------- | ---------------------------------------------------------------------------- |
| 1   | **形状有几个**       | 表 A：形状名 / 判别位 / 失败表达 / 生产函数 / 消费点数                       |
| 2   | **判别语法几种**     | 表 C：去重后的种数，不是行数                                                 |
| 3   | **载体有几个**       | 逐处列 `useRef` / `props` / 条件渲染 / 字段 / 返回值；只报「有 8 处」不算数 |
| 4   | **入口有几个**       | 表 B：谁写 / 谁判 / 谁关 各几条                                              |
| 5   | **分几层、谁兼职**   | 四层各归谁；对不上点名哪层兼职                                               |
| 6   | **改前改后 N→1**     | 拿不出可比数 ⇒ 先让它有名字，不许宣称收口                                    |
| 7   | **字段名几个**       | 每概念一个数字 + 逐名列出（`fail`/`code`/`issue`/`why`；`reason`/`message`） |
| 8   | **可选失败字段几个** | 失败臂带 `?` 的字段数，>0 ⇒ 没分类                                           |
| 9   | **构造点几个**       | 形状字面量 `{ status:'error', … }` 的个数，>1 且不在构造函数 ⇒ 绕过          |

**凭据（第十件不是数）**：哪一处会红 —— 单测 / 探针 / 临时断言，三选一。答不出 ⇒ 全文写 `UNVERIFIED`，禁写「已完成 / 正常 / 应该没问题」。

**落点**：九个量 + 凭据写进轮次文件（`daily/架构日志/<NN>-*.md`）。没落盘 = 没数。

## 十五刀（顺序不可换）

0–9 收形状，10–14 收写法；两轮都跑；刀 9 跑两次（收尾 + 复核新拆出的臂 / 构造函数）。

| 刀     | 动作                         | 判据                                                                                     |
| ------ | ---------------------------- | ---------------------------------------------------------------------------------------- |
| **0**  | 画**形状地图**（不是调用图） | 判别语法 > 1 种 ⇒ 一定还有形状没收                                                       |
| **1**  | 按**职责**分四层（不按文件） | 层数 = 形状数 = 入口数                                                                   |
| **2**  | 砍**可忽略字段**             | `ok:false` 臂上还有 `.value` / `.groups` / `.stars` ⇒ 还是裸形状                         |
| **3**  | 砍**自由文本失败**           | 生产者不写用户文案；文案收口到 `msg`，失败才可穷举、可测                                 |
| **4**  | **拆兜底**                   | **兜底数量净减**（X → Y，Y < X），不是「症状消失」                                       |
| **5**  | 拆**职责混装**               | 兜底 / 归一化 与 判断好坏 同函数 ⇒ 必拆（刀 2 根因）                                     |
| **6**  | **收路** + 方向互斥守卫      | 判据唯一 ≠ 收口，还要问「到判据的路有几条」                                              |
| **7**  | **一次替换：删旧实现**       | **diff 必须有删除行**；只加不删 ⇒ 新结构是死代码                                         |
| **8**  | **同步化与错误通道同批换**   | 只换同步不换通道 = 用静默吞换锁                                                          |
| **9**  | **焊死：绕过在结构上不可能** | 删注释文档后违规还写得出来 ⇒ 只是约定，不是结构                                          |
| **10** | **字段名收口**               | 失败码 / 用户文案 / 技术现场 / 底层原文 **四张词表**，各只一个名字；一个名字只装一种语义 |
| **11** | **可选失败字段 = 未分类**    | 失败臂 `?` ⇒ 拆两臂用子码当判别位；读它之前必须**先判子码**                              |
| **12** | **构造点收口**               | 字面量只许在唯一构造函数；别处只调，不许 `{ status:'error', … }`                         |
| **13** | **同一判据不许两个函数**     | 两函数答同一问题 ⇒ 一张表 + 一个总函数，另一个变推导（或删）                             |
| **14** | **层间传递不许丢字段**       | 重包形状必须**逐字段声明**；「只挑一个字段重建」= 静默降级                               |

### 刀 0 落点：三张表 + 先查再画

- **表 A 形状清单**：形状名 / 判别位 / 失败表达 / 生产函数 / 消费点数
- **表 B 入口清单**：入口名 / 谁在用 / 有无守卫 / 能否绕过判据
- **表 C 判别语法**：`grep -rn "\.status\b\|\.value\b\|\.code\b\|\.reason\b\|\.detail\b" src/`
- **硬规矩**：必须先看已有形状地图（`daily/架构日志/18-横切-*.md`）并当场复算数字；不许重画；跨文件类型（`types/` / `tests/` / `scripts/` / `.tsx`）一起数。

### 刀 1 落点：四层

| 层         | 职责          | 知道                   | 不知道       |
| ---------- | ------------- | ---------------------- | ------------ |
| ① 观测     | 外部 → 三态   | 在不在 / 读得到 / 字节 | 内容对不对   |
| ② 判据     | 折成**结论**  | 能不能当 T 用 / 坏因   | 用户看什么话 |
| ③ 纯解析   | 不可信 → 可信 | 哪个字段不对           | 文件在不在   |
| ④ 业务结论 | 业务判断      | 域特有三态             | 通用读细节   |

- **分层判据**：问「失败说不出原因会不会伤人」。① 可（只报 errno），②③④ 不可。
- **处置**：① 只许两个（文本 / 字节）；② 只许一个入口 + 一个形状；③ 只许一个契约，不许 `null`、不许 `throw`；④ 必有判别位、不许可忽略字段。

### 刀 2 落点：四种裸形状（砍形状）

| 形态           | 长相                           | 为什么是吞                                     |
| -------------- | ------------------------------ | ---------------------------------------------- |
| 裸 `ok` + 空值 | `{ ok; stars: {} }`            | `{}` 同表「没有」和「读不到」                  |
| 裸 `degraded`  | `{ value; degraded: string }`  | 空串正常非空坏，但 `.value` 永远可取           |
| 裸 `note`      | `{ groups: []; note }`         | 同上                                           |
| 自由文本当码   | `{ fail: '台账顶层不是对象' }` | 码位写人话 ⇒ 不可穷举、不可测，人话归 `reason` |

### 刀 4 落点：六种兜底形态（砍「让旧路继续能跑」的东西）

| 形态               | 长相                      | 处置                                |
| ------------------ | ------------------------- | ----------------------------------- |
| 静默吞             | `catch {}` · 空 catch     | 删；改抛 / 告警 / 用 `detail` 带观测     |
| 失败归一空值       | 返回 `[]` / `{}` / `null` | 改 `Result` 的 error 分支（带 `code`/`reason`/`detail`）或判别联合 |
| 占位对象 + 事后补  | 先塞空等回调              | 一次性拿真值再入状态                |
| 默认值兜底         | `?? 默认值` 掩缺失字段    | 缺失要**看得见**                    |
| UI 层提前宣告成功  | 点了就显「已保存」        | 改「处理中 → 成功 / 失败」两态      |
| 只在一入口补的补偿 | 某页多调一步才看得到      | 补偿收进唯一入口，删调用点补丁      |

- **共同判据**：读可降级但必须标记；写不可降级必须抛。
- **两条例外（必须先裁定，否则刀 4 会被执行成一律抛）**：
  - 文件本不存在（`ENOENT` / `notSeen`）⇒ 正常态，给默认，**不抛、不算降级**。
  - 回滚 / 清理路径（导入回滚、删仓库回收、日志 dump、写前读本地）⇒ 允许尽力而为：不抛、跳过、`log` 留痕，但**不许返回业务值**；每处文件头写清为何可不抛。

### 刀 6 落点：五个收路手段

入口数 = 层数；路径守卫方向互斥；原语消费者收窄到底座；`decode` 必填（不给 decode 调不了）；`| null` 从契约删掉（「失败说不出原因」编译不过）。**做不到** ⇒ 退到刀 9 二档（文件头写清用法 + 抄不错），不许宣称做到结构。

### 刀 7 落点

同次改动必须删掉替代的旧实现。只加不删 ⇒ 旧路还在、新结构死代码；删了没改调用点 ⇒ 编译红（好事）。标准：**diff 有删除行**。

**删字段也算删实现。** 字段消失后真正的活是三件：① 编译器列出全部读点（白送）② 读点改成从 `error` 臂 / `detail` 取
③ 它占着的**文案键与旧概念名参数**一起清（`staleFlag: string` 这类、0 使用的死键）。
判据：**grep 那个概念名，还有活着的引用吗？** 有 ⇒ 只删了类型，没删实现。

### 刀 9 落点：结构上不可能（不是加闸）

**两个档位，都算达标。** 达不到一档就退到二档，**不用硬撑，也不许把二档说成一档**。

- **一档（首选）：结构上不可能** —— 违规**写不出来**。
  手段：不导出内部实现；只给窄接口（字面量联合）；类型层挡住（无 `| null`）；`import` 边界拦（`no-restricted-imports`）；漏改即编译失败。
  判据：删掉注释和文档，违规还写得出来吗？写不出来 ⇒ 一档。

- **二档（退到这，算达标）：「抄不错」** —— 结构挡不住（TS 表达不了新文件里的字段名 / 要留实现级导出 / 跨进程边界），
  就退到「**仓里只有一种写法可抄**」：字面量收进唯一工厂（刀 12）+ 文件头四段 + 样板收尾（每域指定唯一范本文件）。
  文件头四段：`// 是什么` / `// 唯一入口` / `// 替代了什么` / `// 谁在用` / `// 禁止`（少一段 = 没声明）。
  判据：**删掉样板和注释，仓里同类写法还剩几种可抄？= 1 ⇒ 达标；> 1 ⇒ 没做。**

  两档的门槛不一样，别混：

  | 档   | 门槛           | 能做到吗                              |
  | ---- | -------------- | ------------------------------------- |
  | 一档 | **写不出来**   | 常常做不到（TS 管不了新文件的字段名） |
  | 二档 | **抄不到错的** | 总能做到（删到只剩一处就行）          |

  ⇒ **「他写不错」做不到，「他抄不错」必须做到。** 只交一档不交二档 = 没做；只交二档不交一档 = 合格，但要写明是哪几条退的。

- **⛔ 禁止加闸**：不加 lint 规则 / `check` 步骤 / grep 断言 / 「必须遵守」文档条目。

### 刀 10 落点：一张词表，一个名字

先数字段名去重，按概念分**四张表，各只一个名字 —— 一个名字只装一种语义**：

| 概念                 | 只许      | 里面只放                                  | 常见错名                             |
| -------------------- | --------- | ----------------------------------------- | ------------------------------------ |
| 失败码（为什么失败） | `fail`    | 字面量联合码                              | `code` · `issue` · `why` · `failure` |
| 用户文案（给人看）   | `reason`  | 可直接展示的一句话（来自 `msg`）          | `message` · `text` · `note`          |
| 技术现场（错误对象） | `failure` | 错误对象本身                              | `error` · `cause`                    |
| 底层原文 / 观测      | `detail`  | 机器话：`HTTP 403` / errno / 字段期望实际 | 塞进 `reason`                        |

- **判据一句话**：同一名字不许同时装「给人看的话」和「给机器看的原文」（典型：`reason` 里既放中文又放 `HTTP 403`）。说不清差别 ⇒ 一件事合成一个。
- 选名取引用数多数派；成功臂 `message?` 例外（非失败文案，文件头写清）。
- 一个名字装两种语义 ⇒ 拆成两个名字，各只一份（刀 10 验收项）。
- **落地手段：用工厂强制**（见刀 12）——一种语义一个工厂（`failWithReason` / `failWithDetail`），
  别用一个工厂加可选参数兼职两种；参数名连起来要能当这个失败的说明书，否则只是搬运。

### 刀 11 落点：`?` 就是第二个形状

失败臂 `xxx?:` ⇒ 没分类，下游两种写法都编译。收法：拆两臂用子码当判别位；`failure` 从 `?` 变必填那一刻，编译器列出全部绕过字面量（即刀 12 入口）。读可选字段前**必须判子码**。

### 刀 12 落点：字面量只许在唯一构造函数

这个形状的字面量 `{ status:'error', … }` 出现在**几个文件**？1 个（= 该形状的唯一构造点/工厂）= 收口；>1 个文件 = 绕过。

> 数**文件**不是数字面量：两臂形状在工厂里必然有两个字面量，那是构造函数的实现，不是绕过。

收法（唯一有效顺序）：先加必填字段（刀 11）→ 编译器逼出 → 补字段或改调构造函数。**不许用 grep 定范围**（混进别的类型），只用 typecheck 报错列表。

#### 「工厂」就是那个构造函数，**用工厂是合法解**

刀 10「一个概念一个名字、一个名字一种语义」最省事的落地是**工厂函数**（`makeFailure` / `failWithReason` / `failWithDetail`），它属于刀 12 的「唯一构造函数」，**不是加闸、不是包装**（合规点：调用方只能给参数、给不了形状，绕路在结构上写不出）。

**工厂要成立，四条必须满足**（缺一条就退化成搬运，等于没做）：

| #   | 判据                                                                                 | 违反长什么样                                                           |
| --- | ------------------------------------------------------------------------------------ | ---------------------------------------------------------------------- |
| 1   | **形状只许在工厂里出现**，别处一个字面量都没有                                       | 有人在调用点手搓 `{ status:'error', … }`                               |
| 2   | **每个参数是一个语义槽**，不是 `any` / `unknown` / 整块 payload 透传                 | `makeFailure(code, rest)` 里 `rest` 随便塞                             |
| 3   | **一种语义一个工厂**（话一个、原文一个），不许用一个工厂 + 可选参数兼职两种          | `makeFailure(code, reason?, detail?)` —— 两个都可选 ⇒ 两种写法又回来了 |
| 4   | **工厂不吞字段**：源形状有 5 个字段，工厂参数就得能表达 5 个（刀 14 的判定同样适用） | 工厂只收 3 个，另 2 个在调用点被丢掉                                   |

**判据一句话**：**把工厂的参数名连起来读，能不能当这个失败的说明书？** 能 ⇒ 是工厂；只能读出「码 + 一堆东西」⇒ 是搬运。

**识别特征**：工厂建好之后，全仓还能 grep 到**同形状**的字面量落在别的文件 ⇒ 绕过还在（工厂有了、调用点没走）。

**本仓现状（实测）**：失败形状已统一收口到 `src/types/result.ts` 的 `Result<T>`——构造只走 `ok()` / `fail()` / `failWithDetail()`，`grep -rn "status: 'error'," src` 仅命中 `result.ts`（两处工厂）与测试。新增失败只加 `ErrorCode` 枚举值，不再新建形状 / 新构造文件。
**1 个形状 / 1 个构造文件（result.ts）**。> 1 个构造文件就是新长出来的绕过。

### 刀 13 落点：两个函数答同一问题 = 两个入口

两函数答同一问题 ⇒ 判据互相矛盾。收法：一张表 + 一个总函数；`isX()` 必须是 `kindOf(x) !== 'other'` 的**推导**，不许自己再写正则 / switch。

### 刀 14 落点：重包形状 = 重新声明全部字段

从另一失败重建形状 ⇒ 源字段全带过去。能透传就 `return read`（只换 payload 类型）；不能就逐字段显式列全。**判据**：每个重包点能说清「故意丢了哪个字段、为什么」，说不出就是漏。

## 样板收尾（刀 14 之后）

每个域指定**一个**文件当样板，文件头写 `// 本域形状以此为准：<文件>:<入口函数>`。**判据**：删掉样板，仓里还剩几种写法可抄？>1 ⇒ 没指定。样板只能是底层唯一入口那个文件。

## 收口验收：形状六 + 写法八 + 五个净减

答不出数 ⇒ 没做。每条贴命令 + 改前改后数字。

```
—— 形状（刀 0–9）——
形状份数              N → 1
判别位名字种数        1（只许 status）
可忽略字段            3 → 0
自由文本失败          N → 0
入口数                每层 1 个
Decoder 的 null 通道  有 → 无

—— 写法（刀 10–14）——
失败码名字种数        N → 1
用户文案名字种数      N → 1
底层原文名字种数      N → 1
一个名字装两种语义    N → 0
可选失败字段数        N → 0
形状字面量构造点      N → 1（只剩构造函数）
同判据的函数对数      N → 0
重包丢失字段          N → 0

—— 净减 ——
兜底数量              X → Y（Y < X）
diff 里的删除行        有
约定条数              X → Y（写成注释/文档才算约定）
新增闸数量            0（禁）
做不到结构的条目      已退二档（抄不错），逐条点名 + 哪几条退的
```

**写法八条答不出「N → 1」一律按没收口算。**

**口径自检（先做，再报数）**：每个数字写清「分子 / 分母 / 口径命令」。**判据本身可以是错的**，本仓已证伪三处（改卷可以，但不许为凑 0 把合法的收掉）：

| 被证伪                  | 为什么错                                                                               |
| ----------------------- | -------------------------------------------------------------------------------------- |
| 判据 4「grep 命中 0」   | 失败臂与失败记录**本该**带原因。真目标是「`ok` 臂上 0」                                |
| 判据 5「字段名种数 1」  | 判别位与失败子码是两回事；并成一个会让 `{status:'notJson'}` 与 `{status:'error'}` 同形 |
| 判据 1「处数 = 该迁数」 | 解码实现、判据层、唯一通道也是解析点，**不该迁**。真目标是「每处能说出它属哪一类」     |

## 七种偷懒信号（出现任意一条，本轮作废重来）

1. 只给「做法」不给数（没数就没有 N→1）。
2. 用「我判断 / 我认为」代替证据（判断不是判据）。
3. 拿别处结论当本处理由（别处 0 处 ≠ 本处合理）。
4. 收一半就报收口（判据唯一 ≠ 收口，要交「入口数 = 层数」对照）。
5. 「它是合法的」（合法只说明不报错，不说明不会被照抄）。
6. 「先收形状，写法以后再说」（写法不收 ⇒ 两周后又变 N 份）。
7. 用脚本做语义改写（`sed`/`perl` 一次扫全仓 ⇒ 业务载荷 / 字符串 / mock 协议一起改且全绿，错被静默固化）。
