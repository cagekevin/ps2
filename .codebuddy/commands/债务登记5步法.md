# 债务登记 5 步法（低脑力 SOP）

> **一句话总结**：读 index 看灯定起点 → 深挖取证 → 五问 + 速查表找债（重深度、找母体）→ 明细进轮次（线索全 · 解法从简）、摘要进账本、覆盖表增量 → 收口「1 份必改 + 1 按需 + 1 自动」→ 下一区。
>
> **效率总纲（精力分配）**：本流程的「贵」在**找债深、线索全**；「省」在**解法从简、落盘轻**。
> - 精力 **80% 投在取证与找债**（Step 2/3）：深挖链条、母体、证据——这是质量的唯一来源，不许省。
> - 精力 **20% 投在登记**（Step 4）：只留「可复现线索」，不写「解决方案」。
> - **不写解法**：偿债方向 = 一句话（如「收口到命令层并加机器守卫」），不展开步骤、不写伪代码、不给论证；业务债的 A/B/C 只给**选项标题**，不写比选。
> - **线索给全**：每笔债自带「位置 + 证据 + 归属 + 根因 + 爆炸半径」，缺一项 = 没审，不是省时间。
> - **落盘轻**：轮次文件只写「探债」表 + 覆盖度表 + 状态行，不写叙述 / 论证 / 沿革。账本一行交给 `debt.mjs`。

## 零、核心准则与边界

### 1. 基础定位

只管一件事：把一笔债登记下来，并让这块区域越审越清楚、不被反复重审。

- **触发**：用户说「审计 `<区域>` / 排查架构 / 维护架构日志 / 数据流过期了 / 登记债务」
- **分工（别混）**：
  - `本文件` = 审（发现 + 登记，只读）
  - `架构师改码7步法.md` = 改（施工还债）
  - `系统治理5步法.md` = 旁路复检
- **效力边界**：仓库根 `AGENTS.md`（硬约束）+ `docs/GOVERNANCE.md` 物理红线 > `架构师心法.md` > 本步骤
- **精简留痕**：只留可执行步骤，不写论证 / 沿革 / 案例

### 2. 审查方向：从最底层出发

```
src/core/ps/ 各域契约 + src/repo/types.ts（契约与数据真相）
  → src/domain（纯函数，零 IO 零 UI 框架）
  → src/commands（编排与唯一执行入口）
  → src/core/cep/bridge + src/core/cep/ps-events（宿主边界：唯一 PS 出口）
  → src/store（只读投影）
  → src/hooks
  → src/components（跨页基础件）
  → src/features（11 页 + _atoms / _probe / _placeholder）
```

> 从 UI / 功能往下钻只能看到症状；债的根几乎总在更底层。**底层一条债，抵上层十条。**
> ⚠️ **已冻结页面**（`/fontSet` `/fontManage` `/action` `/freePanel` `/set`）只审"只允许修 bug / 数据错误 / 安全问题"的那类债；视觉迁移类诉求不是债，是范围变更。

### 3. 三大铁律与禁令

> 🚫 **禁令：只读，不改一行代码**
> 为什么：债往往同源（同一条规则 / 契约生出来的），逐条就地改易改错 / 改重 → 统一交决策架构师一次收口。

> 🚫 **禁令：不准拿全量测试当取证手段**
> 审计 / 登记债时，不跑 `npm test` 全量（也不准起浏览器、不装 Playwright / Cypress / Puppeteer）。债只靠 `grep` / `文件:行号` / 页面规格取证。
> 允许的两处例外：① **点跑单文件**确认可疑行为（`npx vitest run <路径…>`，不跑全量）；② 当场修工具债（`scripts/**` / `.codebuddy/commands/**` / `package.json` scripts）—— 修完可测作回归。

> **动作限制**：审计时手只准碰 `grep` / `node scripts/debt.mjs` / 轮次文件 / `docs/CONVENTIONS.md` / `docs/adr/README.md` 索引。本流程唯一产出 = 轮次文件（探债 + 覆盖度表）+ 账本一行。

> 🔒 **铁律：任何"描述"都只是线索，不是结论**
> 债登记、注释、issue、上一轮结论、覆盖表里的"深审"都可能是错的。动手前必须重新取证（`grep` + 读真实代码 + 查线上 PS 应用源码（非本仓文档））。把描述当"去哪儿看"，不当"是什么"。

> 🔒 **铁律：诚实优先，禁止静默兜底（兜底必留痕）**
> 任何失败 / 降级 / 取不到值 / 走到异常分支的情况，**必须显式留痕**（抛错、打日志 / 告警、或在结果里显式标记），绝不允许静默兜底——即：`catch {}` 吞掉、`return []` 假装成功、`.catch(() => …)` 静默化、`?? <默认值>` 无条件兜默认值、`未来再说` 式跳过。
> **本仓判据**：`ADR · 读可降级但必须标记，写不可降级`（读返回 `Result` 的 error 分支，写必须抛）+ `ADR · 读原语只报观测、不丢区分`（语义映射放数据层）。**本仓已知典型**：`commands/font.ts:44` 丢弃缓存读的 `error` 分支，`CORRUPT` / `IO_ERROR` 与「首次运行没有缓存」混为一谈（TD-01-4）。
> **为什么**：静默兜底让债「看不见」，是本仓头号伪装型债。看不见 = 没人还 = 越滚越大，比明面债更贵。
> **兜底也须留痕**：若因客观限制确要兜底，必须在该处**显式记录**——打日志 + 行内标注 `兜底` + 写明原因与责任方，**并据此登记一债**（归类 增债 / 利息高）。**任何「无任何痕迹的兜底」= 违约，审计发现即登记一债。**
> **错误必须当场抛，不许转嫁（本流程只揪不改）**：失败应在**发生点**抛出，不该靠一个不相干的外层去"顺便吸收"。凡把错误甩给一个**本不负责此事**的通道去兜底，**审计时即登记为一笔债**：标「转嫁兜底」、归属到真正的责任域、挂 `文件:行号` 证据。**"拆掉转嫁、做对"是 `架构师改码7步法` 的活——本流程（只读）只负责把它揪出来、指归属、记下来。**
> 审计动作：对每个捕获点 / 默认值点读上下文，问"失败时调用方知情吗？有痕迹吗？"；无痕迹即债，记「静默兜底」并指出该补上抛 / 告警 / 标记。

> **一句话内核**：**「一段代码失败了、却没任何人知道，那就是债。」** 判定不看严重程度，只看"失败是否可见"。可见（抛错 / 告警 / 标记 / 日志）就不算债；不可见，就是债——无论它当下"看起来没出事"。

> 🔒 **铁律：首判为债、复核翻非债 = 它仍是债（横跳即证据）**
> 找债时，**第一次判断是债、第二次"复核盘"又改成非债**的情况，直接以「债」定论，不许顺手把复杂度合理化掉。
> **为什么**：一个真正"处于正确位置"的复杂逻辑，判断是**稳定**的，不会让人反复横跳。能让人从"债"改判到"非债"，恰恰说明**复杂度没放对位置**。**横跳本身 = 错位的证据，故判债。**
> **动作**：判债后若要"复核推翻"，必须先能说清"复杂度在哪、为何位置正确"；说不清就保留债，账本标 `[首判债·复核疑非债→维持债]`。

## 二、前置准备：覆盖度账与灯图

> "不重复查"的唯一机制。开审前，须在轮次文件里按本表登记每个文件的覆盖状态。

### 1. Step 0 · 维护覆盖度表

| 文件层 | 覆盖状态灯 | 轮次/日期 | 证据(grep/行号/页面规格) | 债/裁定 |
| --- | --- | --- | --- | --- |

**5 种合法状态**：未审（会再查）、抽审（欠一轮深审）、深审（只有代码变了才回查）、已裁定非债（禁再当 bug 补）、有债待还(TD-xx)。

- **开审规则**：只审 未审 / 抽审 / 回查；深审 不重查（除非代码被改过 → 标 回查）。
- **完备性判定**：表里还有 未审 行，就不许写"该区审完"（已还清 ≠ 覆盖完备）。
- **增量账原则**：只登记本轮新纳入 / 状态变化的行，未变的原样保留、不重抄。

### 2. 数据流覆盖地图（灯的定义）

> 细粒度（文件→灯）写在轮次文件的覆盖度表里；粗粒度（区域→灯）由 `index.md` 自动派生。

| 灯 | 含义 | 对应覆盖状态 |
| --- | --- | --- |
| 🟢 | 已审、无债 | 深审（无债）/ 已裁定非债 |
| 🟡 | 已审、有持平 / 待裁定 | 深审 + 持平债 |
| 🔴 | 有债待还 | 有债待还(TD-xx) |
| ⚪ | 未审 / 抽审（欠深审） | 未审 / 抽审 |

**读起点的两步**：先看 `index.md` 的灯选"该动哪个区" → 再看该区最新轮次文件的覆盖度表选"该动哪个文件"。已被改动过的 🟢 文件 → 在覆盖度表里标 回查。

## 三、标准审计 5 步法

### Step 1 · 定起点

**目标**：确定登记哪个区、起手第一个文件，以及本轮不审哪些。

- 读 `daily/架构日志/index.md` 取 待审计 / 审计中 的区（如无，按「层」自底向上选）。**它始终是最新的**（幂等刷新，无需任何前置动作）。
- 先读 `docs/CONVENTIONS.md` 该区链路。
- 再读 `docs/adr/README.md` 索引对应条目（该区判据的**真源 + 载体数 + 跨板块副本落点**）—— 与 dataflow 同级必读，防把别人已收口的判据又抄一份。
- 🔴 **这两步合起来才是"定起点"，禁只做一半**：dataflow 定「这条链上有哪些文件」；ADR 索引定「这些文件里哪些判据已有真源 / 有几份副本」。缺一张 = 半张地图，探债必漏。
- 细粒度进度看该区最新轮次文件的覆盖度表（🔴⚪ 优先）。
- 找出该区最底层文件（契约 / 类型定义 / 仓库层 / 纯函数）。
- 按层从底到顶列出文件清单，对照覆盖度表筛出本轮要审的（不审的写明原因）。
- 查历史旧债：`node scripts/debt.mjs area <NN>` 及 `search "<词>"`。防重审、看是否复发（复发 = 没治根）。

> **不过关**：找不出"底层文件" → 边界没定清，先定边界再开审。

### Step 2 · 取证

**目标**：确定链路真实面貌，验证 dataflow 与 ADR 索引是否过期。

- 对起点文件跑 `node scripts/mv-sync-refs.mjs refs <file>`，看 fan-in（谁 import 它）。
- 读真实代码：找出类型 / 契约 / 不变式 / 唯一入口。**优先拿去 `docs/adr/README.md` 索引与 `src/components/` 对账**（该文件 / 该判据的真源、载体数、跨板块副本是否如表所述）—— 这是「找第二份真元」最快的入口。
- 沿 fan-in 逐级向上核实，标出 dataflow 与实际不符处；ADR 索引不符处**用 `node scripts/adr.mjs index --write` 重生成**并记入探债。
- 疑似死代码 → `node scripts/mv-sync-refs.mjs find-dead src` + `refs <file>` 双证（0 引用且非入口）+ `npm run typecheck` 无残留引用。
- 页面类疑点 → 查 `（本仓不维护原版页面规格；结构对照以线上 PS 应用为准）`（结构树 + class + CSS 实测值）；要确认某元素有没有事件，回 `线上 PS 应用源码（非本仓文档）` 的 render 看 `on:`（jsx 派发表）。

> **不过关**：拿不出可复现证据（grep 输出 / `文件:行号`）→ 自证式审计 = 没审（必须能让别人独立复现）。

### Step 3 · 找债（只读分析，不动手）

**目标**：定性孤例还是母体？是债还是设计？属于哪类？

#### 3.1 归因判定

- **判据**：某个修复能同时消灭 ≥3 个债 → 它是母体（多在契约层 / 数据层）。
- **⚠️ 母体分两类，别混**：
  - **病因母体**：改完**症状真消失**（如「同一真相抄多份」→ 收口到一处，副本真没了）。
  - **检测母体**（闸盲区 / 守卫缺位）：改完**只防新增，既有症状不消失**
    （例：给 `src/features/**` 加一条新守卫**不会**让「两个页面各有各的滚动容器」消失 —— 它的病因是那两处该合并）。
  ⇒ **检测类母体的「症状数」= 它放过的债数，不是可偿还量**，**别相加当工作量**；
  ⇒ 排优先级时：**病因批先做**（真消症状），**检测批并行**（只防新增）。
  ⇒ 症状会被多个母体重复计入 ⇒ 收益 < 症状数之和。
- **三问**：是否某条规则出错？缺机器守卫（红线只在注释）？同一真相被抄多份？
- **产出**：母体 登记一债全消，症状挂其名下；无母体不强行编造，独立登记 N 个债。

#### 3.2 找债速查表（基于本仓历史形态，先 grep 扫一遍）

> 高频形态先用 grep 扫一遍，再进五问，比逐行读快一个量比。
>
> ⚠ **计数≠重要性**："条数"只是历史里被**捞到**的数量。凡是 grep 抓不到的（需语义推断 / 跨轮比对），计数必偏低，但**越难查的形态越是母体根因、价值越高**。下表"AI 怎么挖"列是硬动作，必须逐条执行。

| 形态 | 快扫（grep / 命令） | AI 怎么挖（硬动作） |
| --- | --- | --- |
| 注释/文档漂移（最高频） | grep 注释里提到的符号名 / 文件名 / 路径，查是否已改名 / 删改。 | 抽取本文件注释中所有引用的符号 / 路径 → 逐个 grep 验证存在 → 不存在即漂移。 |
| 静默吞 / 失败伪装成功 | grep 空 `catch {}` · `.catch(() =>` · `?? <默认值>` · `return []` · `return null`。 | 对每个捕获点读上下文：失败是否被吞、调用方是否知情、是否该上抛 / 告警；对照 ADR（读必须返回 Result 的 error 分支，写必须抛）。 |
| 死代码 / 幽灵预留 | 四口径 grep 0 引用；grep `将来\|预留\|暂不\|备用\|后续用`。 | 四口径双证 0 引用且非入口；对称 API 只实现一半的判定为幽灵。 |
| 绕过唯一入口（高价值 · 重点项） | `npm run lint`（层边界 / 断言禁令 / 页面白名单 / 裸契约串）——公共件分发无守卫，靠 `mv-sync-refs.mjs refs` | 列全仓"写状态 / 执行 PS"点，逐点核是否走唯一入口（只有 `src/commands/registry.ts` 的 `execute` 能执行；只有 `src/core/**` 能碰宿主）；非入口直写 = 违约。 |
| SSOT 第二份 | 抓字面量（命令 id、事件 stringID、存储键、色值）全库 grep，≥2 处定义 = 第二份。 | 取每个常量 / 配置键名全仓 grep，出现 ≥2 处定义或同语义不同名 → 第二份。 |
| 口径错位（高价值） | grep 某判断的所有比较点（大小写 / 是否剥后缀 / 边界取值）。 | 同一个判断在 N 处出现，逐点对比取值 / 归一化方式是否一致。 |
| 假护栏 / 假守卫（难检 · 高价值） | grep 守卫骨架：`if (` · `assert` · `validate` · `guard` · `ensure` · `check`；再看本仓机器守卫是否真挂链：`npm run check` 的十步链。 | **逐条读判据**：是否恒真（常量 / 固定开关 / `if(true`）、空集合判据、依赖从不变化的外界态；再问"这条守卫真挡得住吗"。 |
| 复发 / 回潮（难检 · 高价值） | `node scripts/debt.mjs list --all` 取历史债主题词。 | **跨轮比对**：每个新债先 `node scripts/debt.mjs search "<主题词>"` 看是否已有同类；同类再现 = 上次没治根（缺闸），记回潮并指向母体。 |

> 🔴 **重点项 · 绕过唯一入口**：架构级母体债。凡查到一处绕过，必顺藤摸瓜列全仓"写状态 / 执行 PS"点逐一核对——它养出的下游症状（口径错位 / SSOT 第二份 / 静默吞）往往比它本身更显眼，但**根在这**。审计中遇到即优先深挖并**挂母体**（本流程只读，不修码）；只把表面症状对应的那些债记下来、却不追到母体根因，等于没审到根——表面症状的债要记，母体债更要挂。

##### 3.2.1 难检两项：越难越要挖

这两类 grep 数字最低，却最该被 AI 主动捞——它们是"母体没治干净"的直接证据。

**假护栏 / 假守卫**：grep 只抓得到 `if (true` 这种蠢货。真正的假护栏是**语义级**的——守卫判据在现实路径上永远为真、或依赖一个"理论上会变、实际从不改"的开关。AI 必须：**①** 枚举全仓守卫骨架；**②** 对每一条追溯判据能否为假；**③** 凡"挡不住"却让人以为安全的，记一债。

**复发 / 回潮**：这根本不是代码 grep 能发现的，它要求**横向对照 `debt.mjs` 历史**。AI 必须：开审先 `node scripts/debt.mjs list --all` 拿到旧债主题词；每发现一个债先 `search` 一遍；若同类已存在 = 复发，说明上次只修了表面、缺了根上的闸，必须挂回母体并重开根因。

#### 3.3 六层叩问（结合 3.2 扫出的候选进行判定）

1. 同一真相是否被抄成 ≥2 份？（最高频母体）
2. 有没有绕过唯一入口？（页面直连 PS / 第二条执行入口）
3. 错误被静默吞了吗？
4. 有没有死代码 / 死参数 / 假护栏 / 假收窄？
5. 注释与实现一致吗？
6. **实现对了，效果到了吗？（"判据 vs 实况"对账）**

> 判定区分表：若是为一致性而改、处于正确位置的复杂逻辑、缝隙上的唯一实现，则不是债。

##### 第 6 问 · 为什么必须有

前 5 问全部检的是**代码内部的自洽性**（有没有两份、绕没绕过、吞没吞、死没死、注释对不对）。
**它们读不出「代码全对、用户却什么都没看到」这一类债。**

> **本仓形态举例**：`src/commands/font.ts:44` 丢掉缓存读的 `error` 分支 —— 代码层自洽（返回类型没错、调用方不炸），但 `CORRUPT` / `IO_ERROR` 与「首次运行没有缓存」混成一件事，缓存坏了永远静默重扫（TD-01-4）。**第 6 问就是为这类形态准备的。**

**动作**：当被审对象声称"某事已收口 / 已统一 / 已完成"时，**不许只读代码判定**，必须补一次
**判据 ↔ 实况对账**：写出该判据在真实数据上应当命中的集合，与实况求差；差集非空即为债。
常见形态：静态清单（白名单 / 枚举 / 映射表）的**隐含假设过期** —— 它写于某个历史时刻，
而生产侧的行为已经变了，清单却没跟着扩。

> **便宜的做法**：直接查真实数据 / 真实目录 —— 本仓的真源有三处：
> ① **原版一手源码** `线上 PS 应用源码（非本仓文档）`（jsx 派发表）；
> ② **页面规格** `（本仓不维护原版页面规格；结构对照以线上 PS 应用为准）`（结构树 + 全量 class + CSS 实测值）；
> ③ **真实数据文件**（用户目录下的字体 / 样式库 / 常用页数据，如 `sj_commonFunction.json` 的单一真相约定见 `ADR`）。
> 把该判据在真实数据上**应当命中的集合**与实况求差 —— **读代码永远读不出"数据在磁盘上但界面上一个都看不见"。**
> ⚠️ 本节只读（查文件 / 查目录，不改码）—— 与 §零.1 禁令不冲突。

#### 3.4 标定归属与证据闸

#### 4.1 明细入轮次文件（「探债」段）

**格式（线索全 · 解法从简）**：


# TS + React 异常 & 容错代码禁止项

原则：禁止静默吞异常、隐藏失败状态；失败与正常数据必须在类型上区分；所有异常必须可观测（日志 / 告警）。

1. Promise 相关
❌ 禁止空 catch：`.catch(()=>{})` / `.catch(e=>{})`，捕获错误必须写日志或上报。
❌ 禁止裸 `fetch` 不校验 `!res.ok`，必须手动 throw HTTP 错误。
❌ 禁止直接调用 async 函数不捕获异常（事件回调 / `watch` / `setTimeout` 里），产生 `unhandledRejection`。
❌ 禁止 `Promise.allSettled` 不判断 status 直接读取 value。
❌ 禁止在 `.finally` 回调内抛出未捕获异常。

2. 同步容错工具 `tryParse` / `tryRun` / `safeStringify` / `safeDecode`
❌ 禁止捕获异常后直接 `return null` / 默认值 / 空字符串，不记录错误。
❌ 禁止返回 `T|null` 单一类型；必须返回带 success 标识的联合类型 `{success, data?, error?}`。
❌ 禁止仅使用 `as T` 做类型转换，缺少守卫函数运行时校验。
❌ 禁止调用 `tryParse/tryRun` 后不判断 success，直接读取 data。

3. 组件与副作用（React）
❌ `useEffect` / 事件回调里的异步请求必须使用 `AbortController`，禁止竞态请求覆盖状态。
❌ 禁止组件卸载后写状态（`useEffect` 清理里要 `abort` / 清 timer）。
❌ `useEffect` 清理函数内异常必须 try/catch，禁止裸抛。
❌ 禁止在 computed 内做危险计算而不捕获异常直接向上抛出。

4. 类型断言与空值兜底
❌ 禁止双重类型断言 `as unknown as T`（`!` 已由 lint 拦；`as` 只允许在外部 API 桥接处，业务数据上用 `as` 靠评审挑）。
❌ 禁止使用 `??` / `||` 强行填充默认值掩盖缺失字段，无法区分空值和数据缺失。
❌ 禁止放宽返回类型来「消掉分支」：`Result<T>` → `Result<T | null>`，每个调用方都要猜 `null` 是什么。
❌ 禁止把必填参数 / 必填字段改成可选来「先跑通」：少传能编译，运行时才炸。
❌ 禁止让 `unknown` 往外扩散：收窄是生产者的职责，消费者自己判形状 = 第二份判据。

判据（四条同源）：**放宽之后，调用方要多知道什么？** 多知道一条 ⇒ 复杂度只是被推给了调用方。

5. 定时器、事件回调
❌ `setTimeout` / `setInterval` 内 async 回调必须 try/catch。
❌ 事件回调禁止空 catch 吞掉异常。

6. 接口与错误边界
❌ HTTP 200 时，禁止跳过业务错误码判断直接使用返回数据。
❌ `src/components/ErrorBoundary.tsx` 不能设置 `fallback=null`；捕获组件错误必须上报，禁止静默隐藏。

审计规则：任意一条命中 → BUG，写明原因；全部满足 → PASSED
