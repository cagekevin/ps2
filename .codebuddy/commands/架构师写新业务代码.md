# 架构师新建业务代码 4 步法（从零构建 SOP · PS 面板本仓版）

> **版本**：本文即本仓"新建"工序的**唯一落点**（原地取代旧版；旧版原文见 git 历史，不再维护）。
> **共用部分**：与 `架构师改码7步法.md` 共用的判据 / 命令 / 模板，**真源分工见 §0.2**。

**核心心法**：改码是「治病排雷」，新建是「优生防御」。新建没有历史病灶可对照，
必须靠**前置模型设计 + 机器门禁**杜绝把新代码写成明天的技术债。
**全局铁律**：**先想清最优解 → 再定真相 → 再设防腐 → 死磕失败 → 最后画 UI。** 敢从 UI 组件往下写，一律打回。

> ⚠️ **本仓新建的第一道闸不在本文件里**：改**新页面 UI** 前必须先过 **页面契约**（`docs/CONVENTIONS.md`，批准口令只有 `USER APPROVED PAGE: /route`）；新增**控件**必须过 **控件准入**（`docs/CONVENTIONS.md`，批准口令"同意新增 \<控件名>"）。**没有口令 = 没批准**（"好 / 继续 / 可以"都不算）。

| **L1 类型层** | **编译期报错** | 必填字段 · 判别联合 · 字面量联合 + 穷尽分支 | 低 | **优先** |

| **L3 闸** | 机器检查 | 本仓只有：`lint`（层边界 / 转型禁令 / 页面白名单）· `lint:css` · `typecheck` · `check:templates`（模板契约）· `check:nav`（导航白名单）。样式 / 模板 / 公共件分发均由 `check:templates` / `check:nav` 收口 | 高 | **默认不建**（已有闸够用时，不许再加） |

- ⚠️ **`npm run check` 六道关一次到位**：类型 / 层边界 / CSS / 模板契约 / 导航 / 单测全跑；交付前必须全绿（开发期可只跑相关单测）。

### 0.6 本文自身的验证与维护（**治本：不再存快照**）

> 「靠自觉回头更新」= 无机器防线；而"存快照"本身就是在制造腐坏面。

**治法：不存快照。** 本文的落点一律写成 **`grep` 查法**（查符号名，不查行号）：

| 不写（会腐） | 改写成（不腐） |
| --- | --- |

## 1 · 交付金标准：四零一毁

### 1.1 状态 0 副本（状态绝对收敛）—— **结构偏好（强）**

- **红线**：同一个真相（SSOT）在物理内存只能有一份；组件**不许把业务数据复制进本地状态**。
- **边界**：
  - **业务数据** = 会在别处被读 / 被落盘 / 被别人改的（字体列表、选中 id、样式库条目、落盘结果）⇒ **必须住 `src/store/`**（只读投影，`ADR`）；
  - **纯 UI 状态** = 只在组件内用、不落盘、无他人关心（受控输入草稿、折叠展开、hover、局部筛选）⇒ **允许组件本地状态（`useState` / `useRef`）**。
  - 判据问句：**「这个状态删掉，别处会失忆吗？」** 会 ⇒ 是业务数据，不许放组件。
- **🔍 违反时怎么发现**：
  - 组件里出现对 store 值的本地拷贝 + 双向同步（`useEffect` 双向同步 / 手写回写）⇒ 副本嫌疑；
  - 组件里 `props` 复制进 `ref` 再各自改 ⇒ 已分裂；
  - `grep -rn "create(" src/store` 看投影是否只读（不应有写动作进 store；本仓用 zustand 的 `create`）。

### 1.2 失败 0 猜测（类型逼迫处理）—— **🔴 红线**

- **红线**：契约自带强迫性，不让调用方猜。禁止 `T | null` 冒充成功、禁止隐式 `throw` 让上层猜。
  失败分支必须带**可展示文案**（否则消费者只能自己编话术 —— 那是"编造真相"）。
- **契约形状 / 字段口径 / throw 边界 / 🔍 违反时怎么发现** ⇒ **真源 = `src/types/result.ts`（`Result<T>`：成功 `{status:'ok',value}` / 失败 `{status:'error',code,reason,detail}`；构造只走 `ok` / `fail` / `failWithDetail`）+ `ADR`（读 / 写契约）**；本仓**已有**该主题的 ADR ⇒ **不要另立条**。
- **边界侧**：PS / 文件 / 第三方 API 的 throw 必须在**边界**（`src/core/**`）转成判别联合，不许把裸 throw 放给命令层或页面。

### 1.3 UI 0 业务（无脑视图）—— **结构偏好**

- **红线**：UI 只做「状态投影仪 + 指令发射器」；业务条件由 `src/domain/` 算完，命令层返回结果。
- **本仓真实例子**：
  - ❌ **反例（本仓实债 TD-09-3）**：读系统字体失败时 `sys-font.ts` 返回 `[]`
    ⇒ **把"读盘失败"渲染成"没有系统字体"**（失败被伪装成空）。
  - ✅ **正例**：失败由生产者产出（`Result<T>` 判别联合，见 `src/types/result.ts`）→ store 投影 → 页面分别渲染**失败态**（`src/components/ErrorBoundary.tsx` / 提示）与**空态**（`EmptyState.tsx`）。**失败与空是两个字段、两个组件**，UI **不做 `length === 0` 推断**。
- **🔍 违反时怎么发现**：
  - 组件里出现对**数据层字段的语义推断**（`length === 0` 当"没有"、`!x` 当"失败"）⇒ 越权；
  - 组件里出现跨实体判断（重试语义 / 状态机 / 可见性频率）⇒ 越权（`ADR`）。

### 1.4 页面可废弃（可切除性）—— **结构偏好，且只适用于页面/业务模块**

- **红线**：新页面可随时安全切除：删目录 + 改路由 1~2 行，其余页面零错跑通。
- **⚠️ 适用范围**：这条**只约束"页面 / 业务模块"**，**不适用于横切地基**（`src/core/**` · `src/commands/**` · `src/domain/**` · `src/components/**` 的公共件）。地基本就该被依赖，拿"能不能删"量它们 ⇒ 得出错误结论（会去拆地基）。
- **🔍 违反时怎么发现（可执行）**：删目录 + 改路由 ⇒ 跑 `npm run typecheck` 必须 **0 错**；
  再跑 `npm run lint`，并用 `grep -rn "<页名>" src/ tests/ docs/ scripts/` 复核没留孤儿引用。

## 2 · 施工 4 步法

### Step 0 · 先写最优解 + 普查拦截（唯一开工前置）

> 🔒 **第一动作不是"查"，是"先写出最优解"**（真源：`架构师改码7步法.md` Step 0 + A14）。

**0.1 一屏以内写出「正确落地时长什么样」** —— 若目标是**新页面**，这里必须包含：ASCII 结构图 / 组件清单（复用 `src/components/` 哪些）/ 页面 CSS（**优先"无"**）/ 数据流 / 新控件单列 —— 这就是**页面契约报备**的正文（`docs/CONVENTIONS.md`）。

**0.2 新建三问**（存量改造不会有）：
1. **真的需要"新"吗**？（新建模块是最贵的选项，能加几行就别建）
2. **边界在哪**？（哪些**确定**属于它、哪些**确定**不属于；模糊 ⇒ 会长成万能模块）
3. **可切除点在哪**？（需要它不与谁耦合）

**0.3 普查（三查）**：查原语（§5-B 速查表）→ 查相似链路 → **🔥 横向盘查**（同需求在别入口怎么满足的）。
→ **真源 = `架构师改码7步法.md` Step 0**（本文不再复制）。

**0.4 放行判据（红线）** → **真源 = `架构师改码7步法.md` Step 0 开工指令**。
**产出**：表①最优解（一屏）· 表②入口对照表 —— **未出不进 Step 1**。

### Step 1 · 定真相与边界

1. **SSOT**：锁定核心数据的唯一物理位置。
2. **所有权**：生产者/消费者划分；**消费者严禁执行所有方的动作**，只能发指令（`ADR`）。
3. **禁幽灵预留（YAGNI）** —— **本文定义段，其余处只引用本节**。
   - 只为当前真实需求写接口；禁为"以后可能"预留空接口 / 无效参数。
   - 判据：**指不出"现在谁在什么场景用它" ⇒ 删**。
   - 🔍 **怎么发现**：`grep -rn "<新符号>" src` ⇒ **除定义处外 0 命中** 即为幽灵预留；
     `grep -n "interface Abstract\|TODO\|以后" <新模块>` 抓"为未来预留"的痕迹。
4. **钉死模型**：强类型写死，消灭 `any` 与无意义的 `Record<string, unknown>`。
   - **类型权威下沉到"最低变化速率层"**（`src/domain/`，零 IO 零 UI 框架）；命令层 / store / 组件**引用它**。
   - 判据：**具名类型没人 import ⇒ 权威虚设**。
   - 🔍 **怎么发现**：`grep -rn "import .*<MyType>" src` 是否 **0 命中**；
     `grep -rn "Record<string, " src` 是否各处仍在手抄（手抄 = 权威没下沉）。
5. **🔥 建了原语 ≠ 完成 —— 必须同时规定「谁必须调它」**（本仓最痛教训）
   每个新增原语写两行：**① 谁必须调它（路径清单，必须穷尽）② 验收方式**。
   - **只列一条 = 假接线**（漏了一条路径，单测照样绿）；
   - 验收 = **生产消费 > 0**（`grep` 除定义处外真有命中；**只有测试命中 = 幽灵预留**）；
   - 能用类型就别用力（字面量联合 + 穷尽 `switch` ⇒ 忘接线**编译期报错**）。

### Step 2 · 定契约与防腐层

1. **ACL 防腐层**：PS / 文件 / 第三方数据**必须在边界洗脱**（`src/core/**`），转成 Step 1 的纯净类型后才准进 `src/domain/` / `src/commands/`。
   - 🔍 **怎么发现**：`grep -n "as unknown as" <新模块>` / `grep -n "as any" <新模块>`（绕过类型洗脱）；
     `src/core/**` 之外出现 `Record<string, unknown>` 形参 ⇒ 脏类型已进内层。
2. **失败契约（判别联合）**：见 §1.2（`src/types/result.ts` + `ADR`）。
   - 🔍 **怎么发现**：`grep -nE "\): (Promise<)?[A-Za-z]+ \| null" <新模块>`（`T | null`）· 逐个看失败分支是否带 error 分支或错误文案。
3. **切断默认值兜底**：查不到 ⇒ 抛错或显式缺失；**严禁私自塞 `""` / `[]` / `{}` 让逻辑跑通**。
   - 🔍 **怎么发现**：`grep -nE "\?\? *([\"']{2}|\{\}|0)" <新模块>`（静默补默认值）· `grep -n "?? \[\]" <新模块>`。
4. **异常也要洗脱**：PS / 文件 / 第三方 API 的 **throw 在 `src/core/**` 转成判别联合**
   （`{ ok:false, reason, message }`，**message 保留原文**），不许把裸 throw 放给命令层或页面。
   - 🔍 **怎么发现**：`grep -n "throw " <新模块>` ⇒ 逐个确认是「不该发生」的编程错误；
     凡是"预期会失败"的分支都必须改成判别联合返回。

### Step 3 · 核心组装与 UI 投影

1. **纯化运算**：「怎么算」抽成无外部依赖的纯函数（放 `src/domain/`，可单测）。
   - 🔍 **怎么发现**：`src/domain/**` 里出现 `window` / `document` / `setTimeout` / `Date.now()` / `Math.random()` / `localStorage` ⇒ 已被污染。
2. **命令层（唯一执行入口）**：收敛数据与规则，对外**窄接口**；外部"无脑传参"，不在外部拼业务逻辑再调。
   - **真源 = `src/commands/registry.ts` 的 `execute`**（`ADR`）；命令 id 与 payload 必须在 `src/commands/payloads.ts` 登记。
   - 🔍 **怎么发现**：`grep -n "^export" src/commands/<域>.ts` 看导出面是否过宽（理想只剩「命令定义 + payload 类型」）；
     `grep -rn "<新命令>" src` 看调用方有没有"先拼一段业务逻辑再调"。
3. **UI 极致降级**：UI 只做投影 + 派发（见 §1.3）；复用 `src/components/` 的现成件（`G*` 基础件），**不自造近似控件**。
   - 🔍 **怎么发现**：`node scripts/mv-sync-refs.mjs refs <名>`；再 `grep -rn "class=\"" src/features/` 找同族类名是否散落（一份真源）。无机器守卫。
4. **生命周期 / 并发 / 取消**（新建最容易忽视的一类）：
   - **订阅必须可退订**：`src/core/cep/ps-events.ts` 的订阅要在 `useEffect` 的清理函数里释放（React 严格模式会双挂载，不退订 = 双份监听）。

     `grep -n "await " <新模块>` ⇒ 每个长任务是否都有超时或取消路径。

### Step 4 · 机器验收与落闸

1. **测试闭环**：核心纯函数 + 命令边界必须覆盖；**只测黑盒输入/输出**；**失败分支必须断言**。
   **🔒 禁自证式断言**：判据 —— **把被测实现改坏，断言仍绿 ⇒ 它是装饰，删**。
   **本仓测试纪律**（`docs/CONVENTIONS.md`）：先列 3-6 条测试点；只断言可观察结果（返回值 / emit / 语义类 / 依赖调用），不测布局与坐标；P0（白屏 / 丢数据 / 静默失败）必须有。
   **验收入口 = 先红后绿**（真源：`架构师改码7步法.md` Step 7.1）。
   - 🔍 **怎么发现**：对每条断言跑一次探针（改坏实现 ⇒ 必须红）—— 工具 = **`node scripts/probe.mjs`**（临时注入 → 跑命令 → 精确断言 → 自动还原；`--suggest-out` 先从真实输出里取候选断言串，别凭印象猜）。
2. **落闸**：**默认不建**；先过「建闸前置评审」（真源：`架构师心法.md` §零.4）。能用**结构 / 类型 / 唯一入口 / 对账测试**守住的，**不许用闸**。
   - 🔍 **怎么发现**：该闸是否**真挂在 `npm run check` 链上**（清单真源 = `package.json` 的 `scripts`）；**不在链上 = 从没跑过**。
   - ⚠️ **禁 e2e / 浏览器自动化 / 截图回归**（本仓不做）：视觉与真机行为只能在 PS 里人工看，查不到就标 `UNVERIFIED`。
3. **接线验收**：对应 Step 1 第 5 条 —— 逐个新原语 `grep` 确认生产消费 > 0；每条写入口逐条核对真的接了。
   - 🔍 **怎么发现**：`grep -rn "<原语>" src` 去掉定义处与 `tests/` 后是否仍有命中（**只有测试命中 = 没接**）。
4. **全局登记**：链路有全局影响 → `docs/CONVENTIONS.md`；新命令 id / payload → `src/commands/payloads.ts`；新事件语义名 → `src/core/cep/ps-events.ts`；新环境契约字段 → `src/core/ps/env.ts`（**字段名不能改**）；新错误码语义 → `src/types/result.ts`（错误码集中定义）；新文案 → 页面私有文案或 `src/types/result.ts` 的 `reason`；
   确立/推翻约定或判据 → `node scripts/adr.mjs add`（**判据归 ADR，说明归区域日志**）；欠的债 → `node scripts/debt.mjs add`。
5. **裁决闭环**：施工图里标了「待/TODO/TBD」的，交付前**必须给结论**（或明确"不做 / 待实测 UNVERIFIED"）。
