# 架构师改码 7 步法（通用存量改造 SOP · PS 面板本仓版）

> **定位**：本文件是**改动本仓**（修 Bug / 还债 / 重构 / **新设计一份方案** / 响应"这里不对劲"）时的**强制操作步骤**。
> **读法**：`Step 0` 是**开工前置**，不计入 7 步。`Step 0 + 7 步` 才是完整流程（先查仓库里已有什么，再动手）。
> **两个入口，按"用户说的是什么"选**：
>
> - 用户说的是**一个症状**（"X 不好用 / 我测了还是不行"）⇒ 从 **`🩺 用户报症状时怎么开工`** 进。

>
> 两个入口最后都汇到 `Step 0` 普查 → `Step 3` 定位 → `Step 4` 定契 → `Step 6` 施工 → `Step 7` 落账。
> **适用面**：本文件以**改存量**为主；**从零新建走 `架构师写新业务代码.md`**（新建 4 步法）。但 **`Step 0` 普查 / `Step 3` 定位 / `Step 4` 定契 / `Step 5` 问用户 / `Step 7` 落账 对新建同样适用** —— 只有 **`Step 2` 存量归因 / `Step 6` 最小改动是存量专属**，硬套到新建会得出错误结论。
> ⚠️ **写方案（plan）也算"改动本仓"** —— 同样受 `Step 0` 约束，别以为"这是新设计所以不用查"。
> **效力边界**：仓库根 `AGENTS.md` 物理红线 > `架构师心法.md` > 本步骤。

## 🎯 架构师心法与全局铁律

**你是这个项目的架构师，结构、正确性、职责由你直接定。不确定时去取证，不许靠猜，也不许请示。**

### 🔒 五条不可让渡的架构师底线（凌驾于本文件其余所有战术动作）

**① 正确性最优先 —— 最重要**
**"能跑通"与"正确"冲突时，永远选正确**，不准"先跑通再说"。
验收看：**整体复杂度是否下降 + 失败是否诚实可见 + 兜底是否净减**，不看"这行代码跑没跑通"。

**② 职责边界 —— 不能让生产者去决定消费者**
谁拥有真相，契约就定义在谁那；消费者严禁执行所有方的动作，生产者也不替消费者定行为（详见 Step 3 / Step 6）。
本仓对应：`ADR · 消费者只能转发，不能猜生产者` · `ADR · 缺了先补生产者`。
越权就是结构错误，不是风格问题 → **停**。

**③ 复杂度 —— 放到合适的位置**
**把复杂度收敛到正确的物理位置，而不是搬家**：能删 > 能收敛 > 能下沉；用兜底 / 包装层藏进黑盒 ≠ 消灭。
⚠️ **但「能删」有前提**：**删掉它，用户能做的事不许变少** —— 命令 / 入口 / 功能 / 能力 / 对外契约属"变少了"，**不许删**，走 Step 5 问用户。**且清偿有时机**：死代码是替换动作的过渡产物 ⇒ 功能写完再清。详见 Step 6 顶部红线。
_依据：复杂度不会消失，只会被藏起来。_

**④ 业务数据判断 —— 架构师自己判**
**判据只有一条：用户用了之后，到底变没变？**

- 用户**没变** → 架构师**直接定**（结构 / 命名 / 位置 / 抽复用 / 删死代码 / 补守卫），**不许请示**。
- 用户**能做的事变了** → 才走 Step 5 摆 A/B/C 交用户。
- 反滥用：把该自己判的结构问题退化成"这个要问用户" = **偷懒**。

**⑤ 拆兜底 —— 绝不掩盖错误**

- **验收口径：「兜底数量净减」**（不是"症状消失了"）。
- **六种形态**（见 Step 4）：静默 catch / 失败归一 `[]`·`null` / 占位对象 + 事后补 / 默认值兜底 / UI 层提前宣告成功 / 只在某入口补的补偿步骤。
- 本仓判据：**`ADR · 读可降级但必须标记，写不可降级`**（读返回 `Result` 的 error 分支，写必须抛）。
- 每发现一处，**逐个问"它在掩盖哪条地基缺陷？"** → 答得出就**改地基、删兜底**。

### 其余全局铁律

1. **决策前置 —— 只在两个"有观察点"的时机过三关 + 留痕**（拍板前 / 本轮落账时）：
   **动作**：过三关（资格筛 → 门槛·全达 → 择优；任一门槛不过 ⇒ **停**）；**拍板时**每个 A/B/C 选项各带一份留痕；**落账时**补进区域日志 `§九 决策留痕`（骨架见 `daily/架构日志/_template.md` 该节）。
   **内容 / 格式 / 违反判据的真源**：仓库根 `AGENTS.md`（两道闸）+ `docs/adr/README.md`（ADR 写入规则）—— **本文件不复述**（抄 = SSOT 第二份，见 `ADR守护者.md` 末条）。
   _为什么不管"AI 内部每个决定"：无可观察点、不可判 ⇒ 假判据。_
2. **不为存量兼容留下第二份形态**：
   **判据一句话：「留这个是为了谁？」—— 若答案是"老数据 / 老版本"，直接收口。**
   不为旧形态保留 迁移器 / 双写 / 旧格式分支 / 弃用别名 / 兜底分支；只按正确形态落地。
   ⚠️ 例外（**红线级，不可动**）：用户目录里的**既有数据文件格式**（`ADR` 写前备份 + `ADR` 四种形态收口）、库文件格式 `.kux/.kuc/.kug/.kuf/.kus`（`src/repo/（库文件格式收口在 repo 层，详见 docs/CONVENTIONS.md）`）、`src/core/ps/env.ts` 的 `PS_ENV` 字段名 —— 改这些 = 老用户数据失联 / PS 契约破。
3. **任何"描述 / 名称"都是线索，必须重新取证**：
   债登记、注释、账本输出全可能错。**凡能查的一律不许靠推理**。符号名 / 文件名 / 能力名同样是描述 —— 写进代码或文档前，**必须先 grep 确认它存在、且真的导出**。
4. **不要修症状，要把能力重写正确**：
   任务是把结构重写对，症状消失只是副产品。**严禁四种滑法**：改一版试一次、猜环境、在错误位置深度优化、靠探针反复猜谜。
5. **工具债不延后（红线）**：
   开发途中命中 `scripts/**`、流程文档（`.codebuddy/commands/**`）或 `package.json` 的 `scripts` 缺陷，**立刻停工当场修好** —— 工具的错误产出会**污染后续所有决策**（细则见 `A10 执行细则`）。
6. **既有约定 ＜ 正确性 · 既有约定 ＜ 合理性**：
   **「仓里一直这么写」不是理由。** 既有约定只是**待验证的线索** —— **它未必是对的，可能正是要消灭的对象**。
   **判据（引用任何既有约定之前，先问）：「它凭什么成立？」**

- 答得出（有物理红线 / 类型层 / 唯一入口 / 对账测试支撑）→ 可沿用；
- 答不出（只是"历来如此"）→ **它就是要被消灭的对象**，按正确形态重写。
  ⚠️ **反滥用**：不许拿「既有约定」当挡箭牌；也不许拿「正确性」当借口做**无证据**的重写。
  📌 **落点**：被推翻 / 被确立的约定记入 **`docs/adr/`**（索引 `docs/adr/README.md`；写入口 `node scripts/adr.mjs add --user-approved`，**答卷贴给用户看、由用户拍板**）；**读债、普查之前先过一遍 ADR 索引**。

7. **用户提问优先 —— 先回答，再取证**：
   **用户问的每一句都是判据，也可能是更省的路线。** 他问「为什么 / 是不是 / 核实一下」时，
   **第一动作 = 回答那句话**（结论 + 一条证据），**不是先把周边查一遍**。
   **自检**：**我的下一步，能直接产出他要的那句话吗？** 答不出 ⇒ 我在做他没要的事 ⇒ **停手，先回答**。
   ⚠️ **不是"少取证"，是"取证的方向来自用户"**：问句 ⇒ **只回答**；指令 ⇒ 才动手，且**只做他点名的那一件**（发现别的只留一行"另开轮次"）。

### 一归 · 判据归一（SSOT 绝对收口）

**标准**：同一能力的判断逻辑必须从 **N 份收口为 1 份**。

**验收**：

- 契约必须定义在**真正拥有真相的那一层**（本仓：命令 id 与 payload 在 `src/commands/payloads.ts`；事件语义名在 `src/core/cep/ps-events.ts`；数据真相在 `src/repo/<域>-repo.ts`）。
- **严禁**留下「两名指一物」或「两处维护同一真相」的结构。
- **所有重复的实现必须被抽为唯一实现，其余全部改为委托。**
- **宣称"唯一入口"的，必须让绕过在结构上不可能**（做不到 ⇒ 顶部注释写清**下一个人必须怎么用**）—— 见 Step 4.4；只靠注释约定不算收口。

**不合格信号**：同一能力的判据在 ≥2 处各写一份；契约定义在消费方而非真相方 → **退回重写**。
（执行面 → Step 3「判真假接缝」/ Step 6「清剿尾巴」）

> **判据唯一 ≠ 收口**：定义只剩 1 份，但**到判据的路还有 N 条**，仍不算收口。
> 这一条最容易误判 —— 详见 **`🔁 形状收口手术` 刀 5**（入口数 = 层数、路径守卫方向互斥、`decode` 必填、`| null` 从契约里删掉）。

### 减一 · 兜底净减（拒绝捂盖子）

**标准**：系统里的兜底代码**不仅不能增加，且必须实现数量净减**。

**验收**：

- **严禁**为了让代码跑通而新增**静默 catch、默认值兜底或假装成功**。
- **每发现一处报错，必须去改地基、删旧兜底**，而不是加个新兜底把症状埋得更深。

**不合格信号**：新增了静默 catch / 默认值 / 假装成功；兜底总数未降 → **退回重写**。
（形态清单与处置 → Step 4「🔒 拆兜底」）

### 减二 · 复杂度实减（拒绝复杂度搬家）

**标准**：整体复杂度必须**真实下降**，链路必须**更短、更直**（**环节数下降**）。

**验收**：

- **把复杂度藏进包装层不叫消灭。**
- 改完必须能拿出**可比的度量数据**：**改动半径变小、fan-in 减少、跨层跳跃变少、重复份数下降**。
- **答不上「复杂度降在哪」，就不许改。**

**不合格信号**：环节数没降 / 拿不出改前改后度量 / 只把复杂度搬进新黑盒 → **退回重写**。
（度量口径 → Step 7.3「度量（强制）」）

### 一诚实 · 失败诚实可见（根部炸开）

**标准**：所有的失败**不能伪装成成功**，必须诚实可见。

**验收**：

- **错误必须在根因发生地抛出（根部炸开）。**
- 用**判别联合（`Result<T>`）**替代容易引发假成功的 `null` / `[]` / `boolean`（`ADR` · `ADR`）。
- 失败的**可见性必须给对读者**（**开发者看 logger，用户看 UI 状态**）。

**不合格信号**：仍是假成功 / 静默吞没 / 错误被 Catch 埋在三公里外的 UI 层 → **退回重写**。

### 零炸 · 防回归防副作用（只炸我该炸的）

**标准**：改动**只影响目标能力** —— 改前能用的改后仍能用（**防回归**）；改前会失败的改后**仍失败**（**不许顺手改好** = 防副作用）；**不许留半态**。

**验收**：

- **改前基线必须可复现**：动手前先固化"改前的行为清单"（正常路径 + 已知失败路径），**没有基线 = 没有防回归**。
- **不得顺手改好无关的失败**：目标之外的症状，即使"看起来也坏了"，**记下来另开一轮**（本仓：登记进 `daily/架构日志/债务.md`），不许顺路捎上。
- **不得扩大行为面**：只做被要求的那件事；调用方看不见的新行为 = 副作用。
- **不留半态**：改一半（旧字段还在读 / 旧分支还在跑 / 旧注释还在描述新实现）→ 不算改完，回到 Step 6 清剿尾巴。
- **已冻结页面只许修 bug / 数据错误 / 安全问题**（`/fontSet` `/fontManage` `/action` `/freePanel` `/set`）—— 顺手"统一视觉" = 越权。

**不合格信号**：

- 说不清「哪些行为被改了、哪些没被改」；
- 顺手修了目标之外的东西 / 扩大了可调用面；
- 改了一半（双名 / 双态 / 旧分支残留）；
- 只跑了"我改的那条路"，没验证过"原本能走的路还走得通" → **退回重写**。

### 一凭证 · 证据可复现（口说无凭）

**标准**：**前五闸的每条结论都必须带一条可复现的凭证** —— 别人拿同一条命令、同一份输入，能跑出同一个结果。**结论只有形容词 = 没有凭证。**

> **它与「一归」是同一件事的两个面**：**一归**管「**判据**收口」；**一凭证**管「**结论**收口」。
> **它不是第六个并列项，是前五闸的成立前提** —— 前五闸全是"宣称式"判据，成本为 0。

**验收（凭证三问，缺一即不合格）**：

1. **哪条命令**：这份结论由哪条命令 / 哪次只读实测产出？（说不出命令 → 是记忆，不是证据）
2. **跑没跑**：**必须真的跑过**，且结论块**粘进轮次文件**。本仓的取证手段：`grep` 输出、`npm test` 的结论行、`npm run check` 的通过行、`npm run typecheck` 的错误数 —— **不用结果 = 未验收**。
3. **红没红**：「先红」那一步**必须真红过**。**没红 = 没测到东西**，**不许跳过**。

**五闸各自的凭证要求（逐闸对齐）**：

| 闸         | 凭证形态（必须是这个，不许是形容词）                                        |
| ---------- | --------------------------------------------------------------------------- |
| 一归       | 改前 `grep -rn "<名>" src/` 命中的 **N 处 → 改后 1 处**（贴命令 + 输出）    |
| 减一       | 兜底**计数对照**（改前 X 处 → 改后 Y 处，Y < X）                            |
| 减二       | **可比的度量数据**（改动半径 / fan-in / 跨层跳跃 / 重复份数，改前改后并列） |
| 一诚实     | **先红后绿的对照**（注入假成功 → 红；修复后 → 绿）                          |
| 零炸       | **反向对照**（改前能走的路径仍绿 + 改前会失败的仍红）                       |
| **一凭证** | **就是上面五条的凭证本身** —— 无凭证即五闸全废                              |

**不合格信号**：

- 结论是「收口了 / 更短了 / 测过了 / 应该没问题」—— **全是形容词，无命令**；
- 断言**没红**却宣称"验证过"（= 自证式测试）；
- **写了自证式断言**（同义反复 / 断实现细节 / 断自己 mock 的值 / 无生产消费 / 断源码文本 / 只断"没抛错"）
  —— **自证式断言给的是假凭证**（它恒绿，不构成任何证据）→ 见 Step 7.2；
- 拿环境当跳过理由（"jsdom 测不了"）**却没换成手工实测并写明** → **退回重写**。
- ⚠️ **本仓的真机边界**：PS 是否回某事件、jsx 返回值取值这类**只能真机确认**，本仓**禁 e2e / 浏览器自动化 / 截图回归**，也**不许要求用户去 PS 里点**。

> **一句话**：**六条同时成立才叫「改完」；有一条答不出**可复现的**证据，就是补丁，退回重写。**

## 🔁 形状收口手术 —— 一整套动作（N 份形状 → 1 份形状）

> **什么时候用**：同一件事（读一个文件 / 判一份数据 / 写一次盘）在仓里有 **N 种结果形状**、**N 个入口**、**N 种判别语法**，消费侧每加一处就要重新猜一次"失败了该怎么办"。
> **它不是第 8 个 Step**：它是 **Step 3（定位）+ Step 4（定契）+ Step 6（施工）** 在"形状"这一维上的**专门打法**。七步法管"要不要改 / 改哪层"，本节管"**怎么把 N 收成 1**"。
> **判据仍然只有三条**（心法底线 ①②③）：判据唯一收口 / 职责不越界 / 复杂度收敛到正确物理位置。

### 手术总览：七刀，顺序不可换

| 刀    | 动作                         | 产物                                            | 不可换的理由                                     |
| ----- | ---------------------------- | ----------------------------------------------- | ------------------------------------------------ |
| **0** | **画形状地图**（不是调用图） | 形状清单 / 入口清单 / 判别语法清单              | 不画地图就动手 = 凭印象改，必然漏                |
| **1** | **按职责分四层**（不按文件） | 每个形状归到观测 / 判据 / 纯解析 / 业务结论之一 | 分类错 ⇒ 收错方向（把"结论"并进"观测"会丢信息）  |
| **2** | **砍可忽略字段**             | 裸形状 3 形态 → 0                               | 这是静默吞的**形状层形态**，不砍等于留着吞的口子 |
| **3** | **砍自由文本失败**           | 生产者不写用户文案                              | 文案散在生产层 = 绕过 `msg` 收口，且失败不可穷举 |
| **4** | **拆职责混装**               | 一个函数只干一件事                              | 混装必然造出"可忽略字段"（刀 2 的根因）          |
| **5** | **收路 + 方向互斥守卫**      | 入口数 = 层数                                   | 路不唯一 ⇒ 判据唯一也没用                        |
| **6** | **同步化与错误通道同批换**   | 同步段 + 判别联合                               | 只换同步不换通道 = 用静默吞换锁                  |

### 刀 1 · 按职责分四层（职责不明的根源就在这里）

同一个"读"字底下住着**四种完全不同的职责**。混在一起，就是"职责不明"：

| 层               | 职责                      | 它**知道**什么                   | 它**不知道**什么         | 本仓形状                     |
| ---------------- | ------------------------- | -------------------------------- | ------------------------ | ---------------------------- |
| **① 观测层**     | 把外部世界变成三态        | 在不在 / 读不读得到 / 字节是什么 | 内容对不对、业务能不能用 | `TextRead` · `Base64Read`    |
| **② 判据层**     | 把观测 + 解析折成**结论** | 能不能当 T 用、坏了的原因        | 用户该看到什么话         | `RepoRead<T>`                |
| **③ 纯解析层**   | 把不可信形状收成可信形状  | 哪个字段不对                     | 文件在不在、能不能写回   | `Decoded<T> \| DecodeFail`   |
| **④ 业务结论层** | 表达一个**业务判断**      | 该域特有的三态                   | 通用读的细节             | `LedgerRead` · `SysFontRead` |

**分层的判据（一句话）**：**问它「失败了说不出原因」会不会伤人** ——

- ① 说不出原因 = 只能报原始 errno（**可以**）
- ②③ 说不出原因 = 用户不知道下一步做什么（**不行**）
- ④ 说不出原因 = 业务判断丢了（**不行**）

**处置规则**：

- ① 只许**两个**（文本 / 字节），不许再裂
- ② 只许**一个入口 + 一个形状**（`readRepoFile` + `RepoRead`）
- ③ 只许**一个契约**（`Decoded | DecodeFail`），不许 `null`、不许 `throw`、不许 `{error}`
- ④ **允许存在**，但必须**有判别位**（`status: ok|none|broken`），且**不许带可忽略字段**

**判据**：**层数 = 形状数 = 入口数。** 三个数对不上 ⇒ 有层在兼职。

### 刀 2 · 裸形状：静默吞的形状层形态

**定义**：把一个"失败"编码进一个**可以被无视的字段**，而不是让失败在类型上**取不到值**。

| 形态                        | 长什么样                         | 为什么是吞                                                     | 处置                                       |
| --------------------------- | -------------------------------- | -------------------------------------------------------------- | ------------------------------------------ |
| **裸 `ok: boolean` + 空值** | `{ ok: boolean; stars: {} }`     | `{}` 同时表示"一个都没有"和"读不到"，调用方只看 `stars` 就是吞 | → `RepoRead<T>`                            |
| **裸 `degraded: string`**   | `{ value: T; degraded: string }` | 空串正常、非空是坏 —— 但 `.value` 永远可取                     | → 拆两半（见刀 4）                         |
| **裸 `note: string`**       | `{ groups: []; note: string }`   | 同上                                                           | → `RepoRead<T>` 或 `Decoded \| DecodeFail` |
| **自由文本 `fail: string`** | `{ fail: '台账顶层不是对象' }`   | 生产者写用户文案，绕过 `msg` 收口，且不可穷举                  | → 形状臂 + 语义臂（刀 3）                  |

**统一判据**：**`ok:false` 那一臂上，不许有 `.value` / `.groups` / `.stars`。** 有 ⇒ 它还能被无视 ⇒ 还是裸形状。

**验收**：`grep -rn "degraded: string\|note: string" src/` → 0（注释里的历史说明除外）。

### 刀 3 · 自由文本失败：生产者不写用户话

**错在哪**：`{ fail: '色板文件根不是数组' }` 这个字符串会一路变成 `RepoRead.reason` → 进 UI。
⇒ **纯解析层在决定"用户看到什么话"**，绕过 `msg.data.fn.*`，而且"有几种失败"不可穷举、不可测。

**正确形状：两臂**

```ts
type DecodeFail =
  // 形状臂：只报观测，说不出用户话
  | {
      fail: 'shape'
      field: string
      expected: 'object' | 'array' | 'string' | 'number'
      actual: string
    }
  // 语义臂：码可穷举，说不出字段
  | { fail: 'notJson' | 'emptyContent' | 'noItemsParsed' | 'badItem'; count?: number }
```

**为什么必须两臂**：`{ field, expected, actual }` 表达不了"内容为空"（形状完全合法）；`{ fail: 'emptyContent' }` 表达不了"哪个字段不对"。**失败本来就有两种**，硬塞进一臂必然有一类丢信息。

**渲染收口到一处**：`repo-read.ts` 的 `describeDecodeFail()` —— 全仓唯一把 `DecodeFail` 变成中文的地方。

**验收**：`grep -rn "fail: '" src/` 里**不许有一句中文**（只剩枚举码）。

### 刀 4 · 拆职责混装：一个函数干两件事 ⇒ 必然长出可忽略字段

**这是刀 2 的根因。** 实测形态：

```ts
// 错：归一化 + 判据 混在一个函数 ⇒ 只能靠可忽略字段事后提醒
readStyleWarehouseIndex(raw): { status:'ok', value: {} }

// 对：拆成两个，各说各的
normalizeStyleIndex(raw): StyleWarehouseIndex          // 纯转换，没有第二个字段可忽略
decodeStyleWarehouseIndex(raw): Decoded | DecodeFail    // 判据，结构不认识给 fail
```

**为什么拆了就不吞**：`normalizeStyleIndex` 会把"结构不认识"折成 `defaultStyleIndex()` —— 那在"索引为空"时对，在"结构不认识"时**会把坏文件当成新用户**。所以**结构判断必须在归一化之前**，不能塞进去靠一个字段事后提醒。

**判据**：**一个函数里同时出现「兜底 / 归一化」和「判断好坏」⇒ 拆。** 拆完那个"可忽略字段"就没有容身之处了。

**另一类混装：判据层兼职写文案** —— 同一条判据，生产者只管"是什么"，消费者只管"怎么说"（`ADR`）。刀 3 就是它的处置。

---

### 刀 5 · 收路：方向互斥的守卫

**判据唯一 ≠ 收口。** 判据唯一只管"定义了几份"，收口管"**到判据的路有几条**"。

| 手段                       | 本仓实例                                                                                                                                   |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| **入口数 = 层数**          | 读：`readRepoFile`（判据）/ `readOwnFileText`（取原文）/ `readExternalText`（外部）/ `readBase64File`（字节）—— 四个，各对应一种格式所有权 |
| **路径守卫方向互斥**       | `readOwnFileText` 只收 `userDir()` **内**；`readExternalText` 只收 **外** ⇒ "读哪个目录"结构上没有第三种选择                               |
| **原语消费者收窄到底座**   | `readTextSync` / `readTextAsync` 的消费者只剩 `disk-write` + `repo-read` 两个底座模块                                                      |
| **`decode` 必填**          | `readRepoFile(target, decode)` —— 不给 decode 就调不了 ⇒「JSON.parse 结果直接当 T」写不出来                                                |
| **`\| null` 从契约里删掉** | `Decoder<T> = (raw) => Decoded<T> \| DecodeFail` ⇒「失败但说不出原因」编译不过                                                             |

**做不到时的兜底（同 Step 4.4）**：宣称唯一入口却结构上堵不住（如原语必须给写侧用）⇒ **文件头写清"下一个人必须怎么用 / 不许碰什么 / 碰了会怎样"**，并**如实登记缺口**，不许宣称做到了。

---

### 刀 6 · 同步化必须与错误通道同批换

**这是「存」返工三次换来的判据。**

|            | 异步世界                                               | 同步世界                    |
| ---------- | ------------------------------------------------------ | --------------------------- |
| 失败怎么传 | Promise rejection                                      | **同步 throw**              |
| 怎么处理   | 必须 `await` / `.catch`（不处理 = unhandledRejection） | **任何 `try/catch` 都能接** |

⇒ 同步 `throw` **更容易被兜底吞掉**。所以"异步改同步"时如果不同批把 `throw` 换成**判别联合**，结果就是**用静默吞换掉锁** —— 一个缺陷换另一个。

**验收追加**：`grep -rn "try {" src/repo src/store` 里**不许有"兜读失败"的 catch**。有 ⇒ 错误还在走可吞通道。

---

### 施工纪律（今天顺利的直接原因，也是前三次返工的直接原因）

| #   | 纪律                                                                  | 前三次怎么错的                                                             |
| --- | --------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| 1   | **先分类再动手**：按"有没有异步依赖"逐处标注，不凭"应该是纯写段"      | 凭印象上手，改到一半发现两个导入函数必须留 `async`                         |
| 2   | **原子单元**：接口 + **全部**实现（含手写包装层）同批改完才 typecheck | 把"接口 + 3 个实现"拆两批 ⇒ 每批都假红，误判成"级联爆炸"                   |
| 3   | **从下往上**：底层实现 → 接口 → 上层 helper → 调用点                  | 先改接口再拆包裹 ⇒ `repo.update()` 还是 Promise 时拆包裹 = fire-and-forget |
| 4   | **不用脚本做语义改写**：只用精确锚点，一处一验                        | `indexOf('  return {')` 匹配到 4 空格缩进，把 200 行文件砍到 89 行         |
| 5   | **单元内不 typecheck，单元边界才验**                                  | 每改一行就 typecheck ⇒ 满屏预期内的红，判断不了"真错"还是"还没改到"        |

### 收口验收（形状账，逐条给数）

```
形状份数              N → 1        每层一个
判别语法种类          1 → 1        status（判别位只许 `status`）
可忽略字段            0 → 0        （maomao 无裸可忽略字段；失败走 `Result` error 分支）
自由文本失败          N → 0        grep "fail: '" 里不许有中文
入口数                每层 1 个     不是每个调用点一个
Decoder 的 null 通道  有 → 无      「失败但说不出原因」编译不过
```

**每一条都必须贴命令 + 改前改后数字**（一凭证闸）。答不出数 ⇒ 没做。

### 行为证据 —— 形状账答不了的那一半

**上面六个数字全是 `grep` 出来的静态量。** 它们能证明"形状收干净了"，**证明不了"改完还能跑"**。

这不是补充说明，是**这条判据的必备另一半**。只交形状账 = 交付一个收拾整齐但没通电的房子。

**每条改动必须能回答三问**：

| #   | 问                                                                                          | 答不出就是             |
| --- | ------------------------------------------------------------------------------------------- | ---------------------- |
| 1   | **改前什么样、改后什么样？** 具体到用户能看见的东西（哪个提示、哪个列表、哪一步会不会中断） | 只做了形状，没想行为   |
| 2   | **哪一处会红？** 一条能证伪的检查：单测 / 探针 / 临时断言                                   | 没有证据，只有自信     |
| 3   | **哪些路径没验？** 逐条列出                                                | 假装验过（最坏的一种） |

**三问里第 2 问最容易糊弄**。合法的"会红"只有三种：

- **单测**：改坏实现它必红（不是自证式，见 §7.2）
- **探针**：`node scripts/probe.mjs` 临时还原旧实现 → 精确变红 → 自动还原
- **临时断言**：改完立刻删掉的那种（`if (x !== y) throw new Error('…')`），但**必须粘进轮次文件**，否则等于没做

**没有会红的东西 ⇒ 只能**，不许写"应该没问题 / 逻辑上是等价的 / 类型保证了"。

**反面教材（本仓真实发生过）**：把"`npm run typecheck` 0 error + `eslint` 净 + 六个数"当成收口凭证，
交付了一批改了 22 处执行路径、删了整条队列的改动 —— **一次都没跑过**。
那不是收口，那是"编译通过"。

### 为什么"文档写了很多，却一直做不顺"

七步法把"**该不该改 / 该落在哪层 / 错了怎么办**"讲清了，但**没讲"改动怎么切单元、按什么顺序落"**。缺的是三样东西：

| 缺的                         | 后果                                                                | 本节的补法                                   |
| ---------------------------- | ------------------------------------------------------------------- | -------------------------------------------- |
| **分类不是表格，是脑内动作** | 凭"应该是纯写段"上手，改到一半发现两个导入函数必须留 `async` ⇒ 返工 | 刀 0 的三张表：**写下来才算分类**            |
| **没有"原子单元"概念**       | 把"接口 + 3 个实现"拆两批 ⇒ 每批都假红 ⇒ 误判成"级联爆炸" ⇒ 回退    | 施工纪律 2：**单元内不 typecheck，边界才验** |
| **没有"形状账"这个验收口径** | "收口了"只能是形容词，收没收到位无法判定                            | 收口验收：**六个数字，改前 → 改后**          |

一句话：**七步法管"改对"，本节管"改得完"。** 缺了后者，前者再完备也会在第三次返工时被放弃。

## Step 1 · 证伪 —— 这个需求真的存在吗？

> **判据**：用户说的"要 X"，真的是"缺 X"，还是"X 的入口/反馈/时机不对"？

1. **回源到 `file:line`**（不许凭名字 / 记忆 / 注释）。
2. **grep 调用方**（含边界外：`scripts/**` · `docs/**`）。
3. **查能力是否已存在**（"件都在、缺接线"是本仓高频形态：例如 `src/core/ps/<域>.ts` 有函数但页面没接）。
4. **禁"不做"式循环论证**：拿另一个"待裁 / 待验证"支撑"不做" = 循环论证。
   **《不做取证三问》**：① 回源 `file:line` · ② grep 调用方（含边界外）· ③ 查后端 / 端口 / 类型是否已存在。
   **查不出 ⇒ 不许下「不做」**，只能写「**事实待实测 /**」。
   _为什么_：判错「做」= 多写代码（可见、可回退）；判错「不做」= **能力永久缺席** ⇒ 举证责任**更重**。
5. **产出**：一行结论 —— 「**需求成立 / 不成立（附证据） / 事实待实测（附要测什么）**」。

## Step 2 · 归因 —— 是孤例，还是母体？（存量专属）

> **判据**：某个修复能同时消灭 ≥3 个症状 ⇒ 它是母体（多在契约层 / 数据层）。

- **病因母体**：改完**症状真消失**（如"同一真相抄多份" → 收口到一处，副本真没了）。
- **检测母体**（守卫缺位）：改完**只防新增，既有症状不消失** ⇒ 它的"症状数"是它放过的债数，**别相加当工作量**。
- **本仓高频母体**：
  - 绕过唯一入口（页面直连 `@/core/**`）→ 养出"两份滚动容器 / 两份小图标按钮 / 两条确认路径"（本仓实债：`TD-08-12` / `TD-08-13` / `TD-08-14` / `TD-08-15`）；
  - 消费侧猜字段（`ADR`）→ 养出"读失败被当成没有"（`TD-09-3`）；
  - 静默兜底（`ADR`）→ 养出"静默失败 / 丢数据"。
- **产出**：母体 登记一债全消，症状挂其名下；无母体不强行编造，独立登记 N 个债（`node scripts/debt.mjs add`）。

> **判据**：契约必须落在**真正拥有真相的那一层**。

## Step 4 · 定契 —— 正确性与"错误透传"怎么设计？

> **效力**：本仓红线原文在 `ADR`（读可降级但必须标记 / 写不可降级）、`ADR`（消费者只转发）、`ADR`（缺了先补生产者）、`ADR`（读原语只报观测）。本节只写**动作**，不另立文。

### 4.1 定数据契约

- **契约形状**：命令 id + payload（`src/commands/payloads.ts` 是 SSOT，`defineCommand` 强制 id 在表内）；结果统一为 `Result<T>`（`src/types/result.ts`）。
- **失败形状**：**判别联合（`Result<T>`）**，禁 `null` / `[]` 冒充成功（`ADR` · `ADR`）。
- **throw 边界**：命令层允许 throw，**统一在 `src/commands/registry.ts` 的 `execute` 里归一**；页面只拿结果，**不许自己 try/catch 吞掉**。
- **发现违反的方式**：`npm run typecheck`（漏登记即报错）+ `npm run lint`（断言缺失）+ `npm run lint`（越层）。

### 4.2 🔒 拆兜底（六种形态，逐个处置）

| 形态                       | 本仓长什么样                              | 处置                                              |
| -------------------------- | ----------------------------------------- | ------------------------------------------------- |
| **静默吞**                 | `catch {}` · `.catch(() => …)` · 空 catch | 删；改成抛 / 告警 / 用 `detail` 带观测               |
| **失败归一空值**           | 读失败返回 `[]` / `{}` / `null`           | 改成 `Result` 的 error 分支（带 `code`/`reason`/`detail`）或判别联合（`ADR`） |
| **占位对象 + 事后补**      | 先塞一个空对象，等回调补                  | 改成一次性拿到真值再入状态                        |
| **默认值兜底**             | `?? 默认值` 掩盖缺失字段                  | 缺失要**看得见**（字段可选 + 显式缺失标记）       |
| **UI 层提前宣告成功**      | 点了就显示"已保存"，落盘还没发生          | 改成"处理中 → 成功 / 失败"两态，失败必须给出口    |
| **只在一入口补的补偿步骤** | 某个页面多调一步"刷新列表"才看得到        | 把补偿收进唯一入口，删调用点的补丁                |

**六形态的共同判据**（`ADR`）：**读可降级但必须标记；写不可降级必须抛。**
**验收口径 = 兜底数量净减**（改前 X → 改后 Y，Y < X），不是"症状消失了"。

### 4.3 消费者不越权

- 消费者**只转发**：不拼文案、不重分类、不下因果结论、不替生产者决定可见性与频率（`ADR`）。
- **缺了先补生产者**：禁消费侧转型 / 默认值 / 猜字段（`ADR`）。
- **判别**：出现"消费者自己造 canonical 能力"（自己拼文案、自己定重试）⇒ 违约。

### 4.4 🔒 宣称「唯一入口」⇒ 先让它**结构上不可能**绕过

**判据**：任何一处你说"这是唯一入口"，**先试着让绕过在结构上不可能**（不导出内部实现 / 只给窄接口 / 类型层挡住 / import 边界拦 / 漏改即编译失败）。**能做到就一定要做到** —— 只靠注释约定 = 没做到。

**做不到时**（TS 表达不了、要给实现级用例留导出、跨进程边界等）：**做不到可以，但必须在该文件顶部写明白"下一个人必须怎么用"** —— ① 唯一的正确调用姿势是什么；② 哪些东西**不许**直接碰；③ 碰了会怎样（响的错 / 静默写坏数据）。"为什么做不到"最多带一句，**不是重点**；**没写清怎么用 = 没做**。顶部声明的四段见 `.codebuddy/commands/形状收口手术_执行方.md` 刀 9 落点。

**不合格信号**：入口只有一行注释自称"唯一入口"，结构上却仍可直 import / 直调 ⇒ 它只是「**唯一实现**」，不是「唯一入口」（本仓自我判定范例：`src/repo/data-repo.ts` 首部第 4 条）。

## Step 5 · 定权 —— 我自己改，还是问用户？

| 动作     | 架构师**可以自己决定**                                 | 架构师**无权决定**（必须交决策者）                                        |
| -------- | ------------------------------------------------------ | ------------------------------------------------------------------------- |
| **对象** | 删代码、删重复、删假抽象、删死参数、把 N 处收敛到 1 处 | 删需求、砍功能、拒绝接活、推迟交付、降低业务能力                          |
| **判据** | 删掉后**功能不变**，只是结构更少                       | 删掉后**功能 / 业务能力发生变化**                                         |
| **动作** | 直接做，做完在账本里记"还债"                           | 摆成带成本的 A/B/C 选项（**结论 + 代价 / 代价等价的真备选**），由用户拍板 |

> **问前必过三关 + 留痕**：摆 A/B/C 时**每个选项各带一份留痕**（说明差异在哪、代价是什么）。**缺留痕 ⇒ 不许问** —— 缺痕＝把该自己判的退化成问答题。
> ⚠️ **本仓另有两道硬闸**（不属于"问用户"，属于"没批准就不许写"）：改**新页面 UI** 前要 `USER APPROVED PAGE: /route`；新增**控件**前要"同意新增 \<控件名>"。这两道闸**没有口令 = 没批准**（"好 / 继续 / 可以"都不算）。
> ⚠️ **不许把验证责任推回用户**：**不许发"你测一下"**。

## Step 6 · 施工 —— 最小改动，不留尾巴

> **红线**：不许顺手重构无关代码 · 不许改业务流程 / 对外契约 / 持久化格式 · 不许借机"统一视觉"（已冻结页面只许修 bug / 数据错误 / 安全问题）· 不许把"还没写完"当"已完成"。

### 6.1 施工顺序（写码4步法的同款纪律）

1. **骨架 → 签名 → 空实现（带"接下来做什么"注释）→ 填充**。
2. **建文件 = 一次替换**（AGENTS.md 动作 2）：新增入口时**当次删掉它替代的那个** ⇒ 这次 diff 里必须有删除。
3. **先搜一次再建文件**（AGENTS.md 动作 1）：`grep -rln "<概念词>" src` 命中 > 1 ⇒ **先合并，不许新建**。
4. **命名带域**：`src/domain/<域>.ts` / `src/repo/<域>-repo.ts` / `src/store/<域>-view.ts`。
5. **公共文件首行三段**：`// 是什么｜替代了什么｜谁在用`。
6. **宣称唯一入口 = 同时让绕过结构上不可能**（不导出 / 窄接口 / 编译期报错）；真做不到 ⇒ **文件顶部注释写清"下一个人必须怎么用"**（正确姿势 / 不许碰什么 / 碰了会怎样），并留下可执行的兜底判据（`Step 4.4`）。

### 6.2 最小改动

- 只做被要求的那件事；**不顺手改好**无关的失败（那会让人说不清是修好了还是改坏了）。
- **不扩大行为面**：调用方看不见的新行为 = 副作用。
- 改动前**固化基线**：改前"正常路径 + 已知失败路径"的行为清单（Step 7 的零炸凭证靠它）。

### 6.3 清剿尾巴（不留半态）

- 删字段 → 同步删接口 / 解构 / 死分支；加新注释 → 删被取代的旧注释。
- **不留"以防万一"的旧实现**（旧实现 = 第二份真相）。
- **收尾对账（半径外孤儿）**：本次改动让**谁**失去了消费者 —— 那些在本次 diff **之外**、因我退役了上游而变零引用的符号 ⇒ **逐条处置**（真死删 / 接上 / 是能力留痕）。

### 6.4 删的前置动作（动作真源 = `删.md`）

> 📌 **动作真源 = `删.md`**（准入判据 + 四口径判死 + 半径外对账）；**本节不复述**。

1. **先分清时机**：清偿死代码是**收尾动作**，不是**准入门槛** —— **先把功能写完、跑通，再清偿**。
2. **先答「删了它，能解决什么问题？复杂度下降在哪一项？」** —— 答不出 ⇒ **不删**。
3. **是不是命令 / 入口 / 功能 / 能力 / 对外契约 / 持久化格式？** 是 ⇒ 停，走 Step 5 问用户。
4. **四口径判死**（缺一不算查清）：① 模块引用（`node scripts/mv-sync-refs.mjs refs <file>` + `npm run typecheck`）② 字符串裸引用（refs 的第二段 + `grep`）③ 桶再导出（`grep -rn "<file>" src/**/index.ts`）④ 运行时字符串（命令 id 在 `src/commands/payloads.ts`、事件语义名在 `src/core/cep/ps-events.ts`、注入契约在 `src/core/ps/env.ts`）。**单口径命中 0 不算证据**。
5. **逐条定性**：真死 ⇒ 删；被取代 / 断链 ⇒ **接上**；是能力 / 契约 ⇒ **停，问用户**。
6. **后置动作 · 半径外对账**：落账必须附四口径输出 + **逐条处置**（删 / 接上 / 留痕 + 理由）。**拿不出对账输出 = 未验收**。

## Step 7 · 验证与落账 —— 探针、测试、门禁与账本（最重的一步）

### 7.1 先红后绿 + 反向探针（本仓取证口径）

> 本仓的探针执行器 = **`node scripts/probe.mjs`**（2026-10-24 自 maomao 仓搬入）：临时注入 → 跑命令 → 精确断言 → **自动还原**。
> 它把"先红后绿"从手工改源码 + 手工还原变成机器判定（journal 兜底 / 还原 sha 自校验 / 并发编辑守卫 / 基线必绿前置）。
> 凭证形态 = **探针结论块**（含 命令 / 退出码 / 输出命中 / 已还原 sha），**原样粘进轮次文件**。

1. **拿真实断言串**：`npx vitest run tests/<路径>.test.ts`（不要猜断言）；探针侧用 `node scripts/probe.mjs --run "<命令>" --suggest-out` **从真实输出里取候选串**。
2. **先红**：修之前**注入缺陷 / 写出会红的断言**，跑 ⇒ **必须真的红**。没红 = 没测到东西。
3. **后绿**：修复后同命令 ⇒ 绿。
4. **反向探针（零炸）**：再证明"**我没改坏别的**" —— 改前能走的路径仍绿 + 改前会失败的仍红。
5. **粘贴结论块**：把命令与结论行**原样粘进轮次文件**（不要人工再抄成第二份表）。

```bash
# 行为探针（临时还原旧实现 → 期待单测精确变红 → 自动还原）
node scripts/probe.mjs --label "TD-xx 行为探针" \
  --file src/commands/style.ts --find "<新实现>" --replace "<旧实现>" \
  --run "npx vitest run tests/commands/style.test.ts" \
  --expect-exit 1 --expect-out "<从 --suggest-out 取得的候选串>"

# 闸探针（负例探针：注入一处越层 → 期待闸精确报该处）
node scripts/probe.mjs --label "页面越界 负例" \
  --file src/features/fontSet/index.tsx \
  --find "<越层 import 片段>" --replace "<注入后的片段>" \
  --run "npm run lint" --expect-exit 1 --expect-out "pages"
```

> ⚠️ **探针会临时改文件** —— 只允许通过它做（journal 兜底 + 还原 sha 自校验 + 并发编辑守卫 + 基线必绿前置），**用完即还原，不许 `--keep`**。
> ⚠️ **基线不绿 ⇒ 探针拒跑**（exit 2）：未注入时那条命令本来就失败的话，注入后的"红"与你的修复无关。

```bash
# 典型一条龙
npx vitest related src/commands/style.ts --run  # 射程自动反查（按模块图；实测命中 28/133 个测试文件）
npx vitest run tests/commands/style.test.ts     # 或直接点跑改动涉及的那几块
npm run typecheck                                # 类型漂移
npm run check                                    # 十二步静态闸
npm test                                         # 全量（只在 L3 或用户要求时）
```

> ⚠️ **全量只在 L3 重改动或用户明确要求时跑**；拿全量当**定位**工具 = 白等（见 `测试门禁5步法.md`）。
> ⚠️ **`npm run check` 已是 typecheck → lint → lint:css → check:templates → check:nav → test 六道关（含类型与测试）**；针对性单测按 `测试门禁5步法.md` 补跑。

### 7.2 🔒 禁自证式断言

**判据**：断言必须**能依赖被测代码之外的事实** ⇒ **把实现改坏它必红**。改坏实现仍绿 ⇒ **它不是测试，是装饰**。

**六种自证式形态**：

1. 断**实现细节**（断私有函数名 / 断内部数组顺序）；
2. 断**自己 mock 的值**（mock 什么就断言什么）；
3. **无生产消费**（测的是一个不存在的能力）；
4. 断**源码文本 / 文件存在**（`expect(readFileSync(f)).toContain('xxx')` 且 xxx 是自己刚写的）；
5. 只断"**没抛错**"；
6. 同义反复（断言的是自己刚赋的值）。

**本仓测试纪律**（`docs/CONVENTIONS.md`）：

- **先列测试点（3-6 条）再写代码**；写不出测试点 = 没想清楚。
- **只断言可观察结果**：返回值 / emit / 语义类 / 依赖调用；**不测布局与坐标**（真机验证）。
- **P0（白屏 / 丢数据 / 静默失败）必须有**；P2 细节可以没有；不追覆盖率。
- 手段：`vitest`，全在 Node 里跑（**不启浏览器、不点 PS、不 fetch、不启 dev server**；AGENTS 禁止 `@testing-library` / `jsdom`，逻辑走 `src/domain` 单测）。
- **禁 e2e / 浏览器自动化 / 截图回归**。
- ⚠️ **边界（易误读）**：**跨文件规范扫描型测试**（扫全仓文件、查"是否遵守某条不变量"）**不属自证式** —— 它断的不是"被测实现自身的文本"，且**注入违规会红**。其合法性按"负例探针证它会红"判定，**不许据本条把它当自证式删掉**。

### 7.3 度量（强制）

改完必须给出**可比的度量**（改前 vs 改后并列）：

| 口径               | 怎么量                                                             |
| ------------------ | ------------------------------------------------------------------ |
| **改动半径**       | 改这一处要同时碰几个文件 / 几层？                                  |
| **fan-in**         | 真相源被多少个上游直接 import？（`grep -rn "<名>" src/` 的命中数） |
| **跨层跳跃**       | 一次数据流穿过几层 / 几个分支？                                    |
| **重复份数 N → 1** | 改前 `grep` 命中 N 处 → 改后 1 处                                  |
| **兜底计数**       | 改前 X → 改后 Y，**Y < X**                                         |

### 7.4 不留假账

- 落账前**回读一遍**：每个结论后面有没有**命令 + 输出**？没有 ⇒ 补或撤。
- **"已做"不许预支**：写"已删 3 处"之前先 `git log --diff-filter=D -- <路径>` 核一遍。
- **状态不许写"已完成"**：查不到的真机行为进该页清单。

### 7.5 落账（唯一落点，不许多写）

| 动作         | 落点                                                                        | 怎么写                                                                                                                                     |
| ------------ | --------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| **必写**     | 区域日志 `daily/架构日志/<NN>-<区域>-<YYYY-MM-DD>.md`（或对话内的交付说明） | 探债表 + 覆盖度表 + 状态行                                                                                                                 |
| **按需**     | `docs/CONVENTIONS.md`                                                     | 仅链路漂移时改现状图（禁追加叙事段）                                                                                                       |
| **写账**     | `daily/架构日志/债务.md`                                                    | `node scripts/debt.mjs add` / `resolve --cmd "…" --claim "…"`（**闸：真跑命令、claim 必须命中**；也允许直接改表，`debt.mjs check` 兜格式） |
| **判据**     | `docs/adr/`                                                                 | `node scripts/adr.mjs add --title "…" --conclusion "…" --user-approved`（**答卷贴给用户看、由用户拍板**）                                  |
| **日志**     | `docs/CHANGELOG.md`                                                                | 手动追加一篇（文件名带日期，平铺；决策 / 踩坑 / 机制变更才写）                                                                          |

## 📎 附 · TS + React 异常 & 容错代码禁止项

原则：禁止静默吞异常、隐藏失败状态；失败与正常数据必须在类型上区分；所有异常必须可观测（日志 / 告警）。

1. Promise 相关
   ❌ 禁止空 catch：`.catch(()=>{})` / `.catch(e=>{})`，捕获错误必须写日志或上报。
   ❌ 禁止裸 `fetch` 不校验 `!res.ok`，必须手动 throw HTTP 错误。
   ❌ 禁止直接调用 async 函数不捕获异常（事件回调 / `useEffect` 依赖 / `setTimeout` 里），产生 `unhandledRejection`。
   ❌ 禁止 `Promise.allSettled` 不判断 status 直接读取 value。
   ❌ 禁止在 `.finally` 回调内抛出未捕获异常。

2. 同步容错工具 `tryParse` / `tryRun` / `safeStringify` / `safeDecode`
   ❌ 禁止捕获异常后直接 `return null` / 默认值 / 空字符串，不记录错误。
   ❌ 禁止返回 `T|null` 单一类型；必须返回带 success 标识的联合类型 `{success, data?, error?}`。
   ❌ 禁止仅使用 `as T` 做类型转换，缺少守卫函数运行时校验。
   ❌ 禁止调用 `tryParse/tryRun` 后不判断 success，直接读取 data。

3. 组件与副作用（React）
   ❌ `useEffect` / 事件回调里的异步请求必须使用 `AbortController`，禁止竞态请求覆盖状态。
   ❌ 禁止组件卸载后写状态（`useEffect` 清理里要 `abort` / 清 timer）。
   ❌ `useEffect` 清理函数内异常必须 try/catch，禁止裸抛。
   ❌ 禁止在 useMemo 内做危险计算而不捕获异常直接向上抛出。

4. 类型断言与空值兜底
   ❌ 禁止双重类型断言 `as unknown as T`。
   ❌ 禁止滥用非空断言 `!`。
   ❌ 禁止使用 `??` / `||` 强行填充默认值掩盖缺失字段，无法区分空值和数据缺失。

5. 定时器、事件回调
   ❌ `setTimeout` / `setInterval` 内 async 回调必须 try/catch。
   ❌ 事件回调禁止空 catch 吞掉异常。

6. 接口与错误边界
   ❌ HTTP 200 时，禁止跳过业务错误码判断直接使用返回数据。
   ❌ `src/components/ErrorBoundary.tsx` 不能设置 `fallback=null`；捕获组件错误必须上报，禁止静默隐藏。

审计规则：任意一条命中 → BUG，写明原因；全部满足 → PASSED
