# 分配任务工作流

> ⚡ 奥卡姆剃刀：如无必要，勿增实体。每句删了能不能完成任务？能，就删。

## 一、角色定义

| 角色 | 做什么 |
|---|---|
| **主控（委派者）** | 清旧任务书 → 接收需求 → **判定任务类型** → 写任务书（三段式）→ 登记任务号 → 归档 |
| **执行 AI（受命者）** | 按任务书执行，不会回来提问，必须独立完成 |
| **用户** | 给出原始需求 |

**核心纪律**：执行 AI 不会提问。任务书必须自包含，不留模糊空间。

---

## 二、本仓任务体系（写任务书前必须知道落点）

| 东西 | 是什么 | 落点 | 写入口 |
| --- | --- | --- | --- |
| **任务** | 计划要做的活，有起点有终点，做完即消失 | 任务号 `T-xx` | `daily/架构日志/00-任务-总索引.md`（**手改本文件，无脚本**，新增往对应表尾加一行，ID 递增） |
| **债务** | 已经发生的行为缺陷 / 结构偏差，不还会持续造成损害 | 债号 `TD-<区>-<序>` | `daily/架构日志/债务.md`（一行一债、只存摘要）—— **唯一写入口 `node scripts/debt.mjs`，禁手写** |
| **区域日志** | 一个区/一个主题的完整记录 | `daily/架构日志/<NN>-<区>-<主题>-<日期>.md` | 手写；**是债的锚点**（`debt.mjs add --anchor <该文件名>`） |
| **页面状态** | 每页做到哪 | `docs/CHANGELOG.md` | 手写（带 `stats` 注入块） |
| **单页验收** | 原版 vs 我方逐项 | `docs/plan/`（按本仓实际份数） | 手写 |
| **决策判据** | 为什么这么设计 | `docs/adr/ADR-NNNN-*.md`（**一条一文件**） | `node scripts/adr.mjs add --title "…" --conclusion "…" --user-approved`（需 `--user-approved`，且答卷要贴给用户看） |
| **踩坑与决策流水** | 最近踩过什么坑 | `docs/CHANGELOG.md` | （本仓暂无 log 工具；架构日志手记 daily/架构日志/，索引人工维护） |

> ⚠️ **任务 vs 债的判据一句**：「现在不做，它会自己变坏吗？」会 → 债；不会 → 任务。
> ⚠️ **状态只写一处**：同一个事实不许出现两遍。待办只写 `daily/架构日志/债务.md`，页面档位只写 `docs/CHANGELOG.md`，逐项验收只写 `docs/plan/`。

**任务书落点**：`daily/任务书/T-xx-<任务短名>.md`（目录当前不存在，第一次写任务书时创建；**一个任务一份文件，文件名必带任务号**，不同执行者不能写同一文件）。
**任务书格式**：三段式，模板见 `docs/plan/`。

## 三、第一步：先判定任务类型（决定要不要行号）

> ⚠️ **动手写任务书前必须先判定类型**。不同类型对「精确行号」的需求完全不同，给错就是返工。
>
> **一句话区别：开放式任务「让 AI 自己发现问题」，限定任务「让 AI 按清单执行」。**

| 类型 | 本质 | 给不给行号 | 给什么 | 本仓举例 |
|---|---|---|---|---|
| **A. 探索/查漏补缺** | 执行 AI 自己去找"哪里该有却没有/该走却没走" | **不给** | 文本要求 + 目标 + 大概文件（**强调不限定只这些，可自行扩展**）+ 判断标准 | "查所有绕过 `useCommand` 直调 `@/core` 的地方" |
| **B. 精确查细节** | 定位某个具体函数/逻辑/值是什么 | **给** | 文件 + 行号 + 关键词 | "`src/commands/registry.ts` 里 `execute` 的归一逻辑是干嘛的" |
| **C. 文档/分析** | 重写/写某主题文档，读代码归纳 | **给探索起点**（文件+行号锚点） | 目标 + 探索起点 + 覆盖清单 | "重写云同步契约文档" |
| **D. 代码改写** | 重命名/改注释/改具体逻辑 | **必须给** | 三件套（映射表+行号+代码模板） | "把 `style.ts` 里混淆变量改成语义名" |

**判定问题**：
1. 目标是"让 AI 自己发现问题"？→ **A**（探索）
2. 目标是"定位一个已知的东西"？→ **B/C**（精确）
3. 目标是"改某处已有代码"？→ **D**（必须行号）

**铁律：探索类（A）任务永远不给行号。给了行号就变成填空题，AI 不会去找漏缺，只会填格子——这违背探索目的。**

## 四、工作流

### 0. 定落点
先读现状再动手：`daily/架构日志/00-任务-总索引.md`（任务号取号 + 依赖列）与 `daily/架构日志/债务.md`（同区既有债）。**动手前先查有没有"母体债"会污染这件事**（见 `写代码4步法.md` 的母体债前置禁令）。

### 1. 理解需求
确认目标主题、是否禁止参考现有文档、是重写还是新增、**任务类型（A/B/C/D）**。产出：需求摘要 + 类型判定。

> 需求不明确时标记 [信息缺口] 追问，不用假设填空。

### 2. 探索代码基底
- **A 探索类**：不做详细定位。只需列出「大概文件 + 关键词」作为提示，**明确写"不限定只这些文件，可自行扩展"**。
- **B/C/D**：grep 关键词 → 读核心文件 → 定位关键行区。产出：探索起点清单（路径+行号+grep 词+语义）。
  - 本仓常用取证：`grep -rn "<名>" src/ tests/ docs/ scripts/`；`（本仓不维护原版页面规格；结构对照以线上 PS 应用为准）`（结构树 + CSS 实测值）；`线上 PS 应用源码（非本仓文档；jsx 签名以真机验证为准）`（一手源码，jsx 派发表行号随版本漂移）；`node scripts/adr.mjs search <关键词>`（既有判据）；`node scripts/debt.mjs search <关键词>`（既有债）。

### 3. 设计生命周期覆盖
- **A 探索类**：只列「该查的链路/方向」，不枚举具体点（具体点是 AI 自己去找的）。
- **B/C/D**：按本仓生命周期拆解，枚举"出现的所有地方"。产出：覆盖清单（带路径+行号）。
  - 本仓生命周期链路：`src/features` → `src/commands` → `src/core`（ps / cep / transport）→ 落盘或 PS 文档；另一头是 `src/store` 只读投影 → 视图刷新。

### 4. 起草任务书（三段式）
按 `docs/plan/` 组装：

```
# T-xx 任务短名

## 甲区【可执行】
1. 目标：…（一句话说清"做完什么东西、怎么算达标"，判据能核对）
2. 判据：…（逐条可验：命令输出 / 行号 / 测试名 / 退出码）
3. 不许碰：…（不允许改的路径与行为；没写等于允许，所以必须写）
4. 交什么：…（文件清单 + 提交标识）

## 乙区【参考·未验证，默认不采纳，你逐条标"采纳 / 驳回 + 依据"】
1. …（主控的猜测 / 倾向；每条一行回执，只写 `采纳` 或 `驳回 + 依据`，不许写"可以考虑"）

## 丙区【问题】
1. …（主控自己不确定的地方、要执行者反考的地方；不约束格式，也不要求回执）
```

- **甲区**是可执行契约：目标 / 判据 / 不许碰 / 交什么，四项齐全。
- **乙区**是"主控的猜测"，执行者必须**逐条回执**，不许默默照做。**这是本仓任务书的重点**：主控的判断默认未被采纳，要执行者拿证据顶回来。
- **丙区**是主控自己拿不准的地方。
- **格式**：三段式**没有闸**了（2026-10-25 删 `spec:check`：手写文档不作为门禁）。对着 `docs/plan/` 自己核：甲区写目标+判据、乙区逐条回执、丙区到文末且三区之外不许有正文。

**结构随类型而变**：
- **A 探索类**：甲区判据写"判断标准"（AI 按此自己找），乙区放"大概文件（不限定）"，不给行号清单。
- **B/C/D**：甲区判据写探索起点（带行号）+ 覆盖清单（带行号），乙区给三件套。

#### 4.1 代码改写类任务（D）：必须包含三件套

| 必须给 | 格式 | 不给的后果 |
|--------|------|-----------|
| **变量映射表** | 原名→新名 对照表 | agent 猜错 → 返工 |
| **精确行号** | `src/commands/style.ts:120` | agent 盲搜整个 `src/` → 写脚本 |
| **代码块模板** | `\| 节点类型 \| 组件名 \|` + 空 ` ```ts ```` | agent 丢错位置 → merge 失败 |

> 原则：**D 类 agent 花的每一秒在"探索"而不是"执行"，都是任务书设计失败。** 三件套给齐 = 填空题，缺一样 = 探索题 → 脚本。
> **A 类恰恰相反：让 AI 自己去探索、去发现，才是目的。绝不给行号清单。**

### 5. 归档
- 取任务号：`daily/架构日志/00-任务-总索引.md` 扫已有 `T-xx`，取最高序号 +1，往对应表尾加一行（ID / 状态 / 依赖 / 事项 / 说明），**手改本文件，不写脚本**。
- 任务书落 `daily/任务书/T-xx-<任务短名>.md`。
- 若本次产出"现在不能动、但确是债"的东西 ⇒ 同一轮用 `node scripts/debt.mjs add --area NN --summary "…"` 登记债，锚点指向对应区域日志。

### 6. 交付话术
输出一行，用户直接看文件路径发给对应 AI 即可：

`任务书：daily/任务书/T-xx-任务短名.md → 发给执行者`

## 五、绝对禁令清单

1. **文件名铁律**：每次委派必须指定唯一产出路径 `daily/任务书/T-xx-<任务短名>.md`，不同执行者不能写同一文件。
2. **禁止参考**：如要求"不参考现有文档"，硬约束必须写明。
3. **探索起点真实**：B/C/D 类的行号必须来自本次会话的实际 grep，不能复用历史（行号会变）；**A 类禁止编造行号**。
4. **验收标准强制**：每份任务书必须有可自测的验收标准。
5. **序号递增**：任务号扫 `00-任务-总索引.md` 已有 +1，禁止硬编码 `T-001`。
6. **不可交互**：任务书禁止出现"如有问题请联系"等假设执行 AI 能提问的表述。
7. **独立文件夹**：每个执行者的产出放 `daily/任务书/`，不混进 `docs/plan/` 或 `docs/CHANGELOG.md`。
8. **类型先行**：动手前先判定 A/B/C/D，类型决定是否给行号。
9. **不推责任**：任务书不许写"请你开 PS 点一下 / 你测一下 / 帮我确认"。真机行为查不到的写 `UNVERIFIED`。
10. **不造债不造任务**：文档里写下的"未落 / 不落 / 与源有意差异"这类定性，必须同一轮 `node scripts/debt.mjs add` 登记；**标注而不登记 = 把债藏进注释**（下一个执行者只读 `债务.md`，看不见散落的标注）。

## 六、示例

### 示例 1：探索类（A）— 正确写法
> 用户：安排 AI 查"该走命令层却直摸 `@/core`"的漏缺。

- 产出：`daily/任务书/T-xx-探索-绕过命令层直调PS出口.md`
- 任务书核心（**无行号**）：
  - 背景：`src/commands/` 是唯一写入口，页面只该调 `useCommand`；`npm run lint` 现在对页面是**默认拒绝** `@/core/**`（只放行 `fs` / `env` / `open-url` / `types` 四个只读来源）。
  - 判断标准：任何页面出现 `@/core/**` 的非白名单 import、任何裸 `evalScript` / `__adobe_cep__` 调用、任何绕过 `registry.execute` 的写操作，都算缺口。
  - 大概文件（**强调不限定**）：`src/features/` 与 `src/components/` 下所有直接引用 PS 能力的文件；**你可根据实际需要自行扩展范围**。
  - 怎么做：通读 → grep 关键调用 → 逐一判断该走哪条路 → 找"该有却没有"的漏缺。

### 示例 2：代码改写类（D）— 正确写法
> 用户：安排 AI 把某个混淆变量改成语义化名。

- 产出：`daily/任务书/T-xx-重命名.md`
- 任务书核心（**必须行号**）：映射表（`a→updateNodeData`）+ 精确行号（`src/commands/style.ts:120`）+ 代码块模板。

### 示例 3：精确查细节 / 文档（B/C）
> 用户：安排 AI 重写云同步契约文档。

- 产出：`daily/任务书/T-xx-云同步契约-v2.md`
- 探索起点（带行号锚点）：grep `syncChangeFileToServe / pushFile / change-sync`；读 src/core/（云同步相关模块，本仓若无独立 cloud 模块则以 src/core/ 实际落点为准）。
- 覆盖清单：入队 → 防抖 → 拉基线 → 三方合并 → 冲突 → pending 台账 → 状态可见。

## 八、多 Agent 并行规则

核心思想：**agent 不知道别人存在，就无从抄袭和互扰。**

### 8.1 自包含任务书
- 任务书内嵌所有需要的参考材料（A 类=判断标准+大概文件；D 类=映射表+行号+模板）。
- agent 只知道自己的产出文件路径，不知道还有几个 agent、他们做什么。
- 不写"本次共分配 N 个 agent"、"你的编号是 X"。

### 8.2 只写一个文件
```
1. 分配：每个 agent 一份自包含任务书
2. 输出：agent 填自己文件的表格/代码块，只在这一个文件里写
3. 合并：你运行合并脚本统一写入（备份→逐条验证→全量 check→失败回退）
```

> 📁 任务书首行写死：`你只能写这个文件，碰任何其他文件视为失败。`

## 九、如何写任务生成脚本

不要在聊天里手写几十个任务文件。写一个 `scripts/gen-xxx.mjs`，跑一次生成全部。

### 9.1 模板
```js
// 是什么：批量生成 N 份任务书｜替代了什么：手写几十个 md｜谁在用：主控一次性派活
// 用法：node scripts/gen-xxx.mjs && rm scripts/gen-xxx.mjs
import { mkdirSync, writeFileSync } from 'node:fs'

const TASK_DIR = 'daily/任务书'

const items = [...]          // 要分配的任务项列表
const AGENTS = 5             // agent 数量
const batchSize = Math.ceil(items.length / AGENTS)

for (let b = 0; b < AGENTS; b++) {
  const batch = items.slice(b * batchSize, (b + 1) * batchSize)
  if (batch.length === 0) continue  // 最后一个为空就跳过
  const num = String(b + 1).padStart(2, '0')

  let md = `# XX${num} — 任务描述（${batch.length} 个）\n\n`
  md += `> ⚠️ 请勿查看其他 agent 的结果文件。\n\n`
  md += `## 方法\n...\n\n`
  md += `## 输出格式\n...\n\n`
  md += `| # | 项目 | 结果 |\n`
  md += `|---|------|------|\n`
  for (let i = 0; i < batch.length; i++) {
    md += `| ${i + 1} | \`${items[i]}\` |  |\n`
  }

  writeFileSync(`${TASK_DIR}/XX${num}.md`, md)
}
```

### 9.2 关键点
- **数据源从代码提取**，不手写：`grep` / `readFileSync` / AST 解析
- **每个 agent 独立文件**，不共用
- **输出格式明确**：填表格、代码块、或键值对
- **同步写合并脚本**：生成任务文件的同时，写好对应的 `scripts/merge-xxx.mjs`
- **用 `.mjs` 扩展名**：本仓 `package.json` 是 `"type": "module"`，`.mjs` 是既有脚本的写法（`scripts/*.mjs` 共 23 个），别混 `.cjs`
- **脚本首行三段注释**：`// 是什么｜替代了什么｜谁在用`（`src/{core,domain,repo,store,hooks,types}` 下的文件是硬要求，`scripts/` 下的新脚本照此办理，便于下一个人 5 秒内知道它是干什么的）
- **跑完删脚本**：`node scripts/gen-xxx.mjs && rm scripts/gen-xxx.mjs`

### 9.3 已有参考
- `tools/new-feature.mjs（npm run new:feature）` — 新建页面骨架
- （本仓无此脚本；页面清单用 tools/check-nav.mjs 或 grep src/features/）— 按页面聚合原版组件文档
- `scripts/page-spec.mjs`（本仓无此脚本；页面结构/契约核对走 tools/check-templates.mjs 与 tools/check-nav.mjs）— 生成页面规格

## 十、踩坑经验（每个坑都返工过）

### 坑 1：把探索类任务写成了"填空题"（最核心的坑）
**错误**：给探索任务配了精确行号清单，让 AI 逐条核对。
**结果**：AI 只填格子，不去找漏缺；本该发现的"该有却没有"被忽略。
**正确**：**先判定类型**。探索类只给判断标准 + 不限定范围的大概文件，让 AI 自己去搜、去找漏缺。只有代码改写类（D）才给死行号。

### 坑 2：没检查就重做
**错误**：看到任务文件里没代码块就标记"未完成"，全部要求重写。
**结果**：有几个 agent 的代码块其实能过构建，白白浪费。
**正确**：**先跑门禁看实际结果**。本仓口径 = `npm run check`（六道关：typecheck→lint→lint:css→check:templates→check:nav→test）+ `npm test`（vitest）。能过的保留，只补失败的。跑命令比人工判断准。

### 坑 3：执行者会写脚本（D 类）
**错误**：以为多加禁令就能阻止。铁律第一条写了"不写脚本"，照样违。
**根因**：agent 写脚本是因为手写成本 > 脚本成本。任务书不给映射表+行号 → agent 得先定位函数、猜变量含义 → "不如写个脚本一次性搞定"。
**正确**：让手写比脚本更省力。给齐三样东西：映射表（不用猜）、行号（不用搜）、代码块模板（不用建格式）。手写 5 分钟 vs 写解析脚本 30 分钟。

### 坑 4：简单括号匹配提取大函数体会失败
**错误**：用正则 + 括号计数从原版源码里提取函数体。
**结果**：含模板字面量 `${}` 的大函数括号计数错乱，提取出错误片段。
**正确**：
- 官方 jsx 函数名单先回 `线上 PS 应用源码（非本仓文档；jsx 签名以真机验证为准）` 核对：**派发表行号随版本漂移**，以真机核对为准；对不上就是假的
- 要组件树用 `node （本仓无此脚本；组件树/结构核对走 tools/check-nav.mjs 与 grep src/features/）`（从原版 AST 提），要结构 + CSS 用 `（本仓无此脚本；页面结构/契约核对走 tools/check-templates.mjs 与 tools/check-nav.mjs）`
- 大函数不提取全量，改用行号定位 + 映射表就够了

### 坑 5：铁律藏在不显眼的地方
**错误**：铁律写在 md 文件中部，agent 跳着读忽略掉了。
**结果**：多次违规。
**正确**：铁律放在任务书最顶部，用 `## ⚠️ 铁律（违反重做）` 醒目标题，三条以内，每条一句话。格式层面**没有机器守卫兜底了**（2026-10-25 删 `task-spec.mjs`）：三段式靠人对着模板核。

### 坑 6：把"未落 / 有意差异"写在文档里却没登记债
**错误**：任务书里写"这里没做 / 这里和官方不一样"，当作说明就完事。
**结果**：下一个执行者只读 `daily/架构日志/债务.md`，看不见这句定性 ⇒ 债被藏进注释。
**正确**：同一轮 `node scripts/debt.mjs add --area NN --summary "…"`；确有出处的"刻意不做"写在**区域日志**里并注明"为什么不是债"。
