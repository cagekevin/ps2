## 一、一句话结论

**契约已完成，写入口未做。** 不是「没设计」，也不是「没开始想」，是**没有一行代码会去写 `sj_appFreePanel.json`**。

## 三、缺的四件（这就是全部）

| # | 缺什么 | 落点 | 说明 |
|---|---|---|---|
| 1 | 写盘 | `src/repo/free-panel-repo.ts`（新建） | 读写 `<legacy>/sj_appFreePanel.json`；形状走 `domain/free-panel.ts`，坏数据按 `MSG.corrupt` + `detail` 报 |
| 2 | 命令 | `src/commands/free-panel.ts`（新建）`addToFreePanel(item)` | 唯一写入口；页面与三处手势都调它 |
| 3 | 手势 | `components/IconPanel/index.tsx` 的 `onContextMenu` | **当前只展开面板**（与官方一致）。要加的是 **Ctrl 分支**：`if (event.ctrlKey || event.metaKey) → addToFreePanel(...)`，否则维持展开。**唯一入口，页面不许自己接 `contextmenu`** |
| 4 | 页面 | `features/free-panel/**`（新建） | 自由面板整页未立项；不做也能接第 1–3 件（先只写文件） |

## 四、手势的准确口径（这条被问过很多次，写死）

官方（`docs/原版/app.v4.js`）：

| 手势 | 行为 | 证据 |
|---|---|---|
| 左键 | 执行 / `isMore` 项展开子面板 | 瓦片模板 `click → clickFunction(e,a)`（`:1211825` 一带） |
| **普通右键** | **展开子面板**（有子项的项） | 图标容器 `contextmenu → t.open(a)`（`:1212956`）；`open()` 内 `if (!ctrl && isMore)` 才展开（`:1290952`） |
| **Ctrl+右键**（Mac 是 Cmd） | **把该项发到自由面板** | `fpFunction` 首句 `if (!Object(ft.f)()) return`（`:1271646`）＋ `ft.f` = `window.event.ctrlKey \|\| metaKey`（`:2267897`）；`$freePanelBox.show(名称, jsx函数, 参数)` 共 28 处 |

我方现状：**普通右键展开 = 与官方一致（已实现）**；**Ctrl+右键 未接**（三处目前分别是：常用页无处理、动作页 toast「自由面板未上线」、字体面板角标 toast「未上线」）。

## 五、接续顺序（不要打乱）

```
1. repo/free-panel-repo.ts        读写文件（形状已定）
2. commands.addToFreePanel(item)  唯一写入口（写后重读自己的 store）
3. IconPanel.onContextMenu 判 ctrl 唯一手势入口；动作页/字体面板的 toast 同时删掉
4. features/free-panel            整页（最后再做，不阻塞 1–3）
```

## 六、三条「别再问」的话

1. **不是没契约** —— 四个 interface 与映射表都在 `domain/`，`02` §3.6 有文档。
2. **不是右键** —— 普通右键展开（我们已实现），**Ctrl+右键**才是加入自由面板。
3. **不是急需** —— 用户明确说不紧急；债号 `TD-09-7`，区域 09，利率中。

## 七、判定「做完了」的凭据

- `grep -rn "sj_appFreePanel" src/repo` 命中 1 处（且是 repo）；
- `grep -rn "addToFreePanel" src` 命中 commands 定义 + `IconPanel` 调用 2 处；
- 真机：**Ctrl+右键** 一个常用页格子 → `sj_appFreePanel.json` 出现该项；普通右键 → 只展开面板、文件不变。
