## 4. 验证方法（**这套工具链是本轮最值钱的东西，别丢**）

### 4.1 三个必须知道的坑

1. **headless Chrome 的 `--window-size` 不等于 viewport**：实测 `window-size=360` 时 `innerWidth` 是 **500**（最小视口）。直接截图会拿到"左边 360px 的裁剪"，误判成页面溢出。**必须用 CDP 的 `Emulation.setDeviceMetricsOverride`，或者用 iframe 包一层**。
2. **判据要按视觉行聚合**：一行 3 个格子，第 1 个的 `right` 不是行末尾。逐个判会误报 56 处。
3. **靠右的内容只判右边距**：底栏按钮组靠右，左边本来就该空，判"两边相等"是误报。

### 4.2 脚本（都在 `/tmp`，重启会丢，按需重建）

| 脚本 | 用途 |
|---|---|
| `cdp-shot.mjs <page> <selector> <out.png>` | 打开页面 → 点击/右键 → 截图。selector 支持 `text=xxx` 按文字定位、`right:` 前缀派发 contextmenu |
| `measure.mjs <page> <rootSel>` | 量一个容器所有子元素的 top/bottom/间距 |
| `edges.mjs <page> <sel1,sel2>` | 量多行左右边界，判对称 |
| `responsive.mjs` | 6 宽度 × 5 页扫左右对称 |
| `overflow.mjs` | 6 宽度 × 5 页扫横向溢出 |
| `color.mjs <page> <sel>` | 右键后读 `.mm-menu` 的 computed style |
| `drawer2.mjs` | 打开常用页抽屉并读外壳 computed style |

用法：`node <脚本>`，需先起带调试端口的 Chrome：

```bash
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" \
  --headless=new --disable-gpu --no-sandbox --remote-debugging-port=9222 \
  --user-data-dir=/tmp/chrome-cdp about:blank &
```

### 4.3 最重要的教训

**看图不可靠，必须读计算样式。** 本轮有两次靠肉眼判错：

- 以为样式页菜单四项全红 → 实测只有「删除」是 `rgb(224,82,82)`，其余 `rgb(176,176,176)`

## 5. 关键决策记录

| 决策 | 依据 |
|---|---|
| 抽屉表面由 `.mm-icon-panel__box` 给，而非各内容类 | 原约定「壳不画背景、内容自己带」导致 3 个类各写一份、参数发散，且有一个抽屉展开后是空白 |
| 抽屉不改结构、只统一参数 | 字体面板 6 个抽屉被 `disabled` 挡住无法截图验证，结构改动风险不可控 |
| 靠 hover 叠白、不换底色档位 | 换档会让 hover 在某些组件上变亮、某些变暗（`card-hover` 原先就比静态暗） |
| 字体面板块间距 6 保持不动 | 每两块之间夹 1px 分隔线，净视觉间隔 6+1+6≈13，与其它页 12 是一档；且一屏 8 块，拉到 12 会溢出 |
| `InputDialog` 的 `--mm-font-panel-dialog-*` 改名 | 公共组件不应引用某个 feature 前缀的 token |
