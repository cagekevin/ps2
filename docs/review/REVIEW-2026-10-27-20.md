## 3. 风险清单

### P0（会导致抄错，必须真机确认才能关闭）

1. **`zt_changeTextBranchMerge` 可能不是函数**：`src/core/ps/init.ts:77` 把它登记进
   `VENDOR_FUNCS`，`src/core/ps/text.ts:226` 真的按函数名调用。参考实现
   （`ps/src/cep/jsx/font.ts:186-191`）记录它只是原版派发表的 key（`case 94` 转发到
   `zt_textBranchMerge`）。若真机探测报缺失，**整页判「官方能力未就绪」**。
   处理预案写在 `PS-CHANNEL-NOTES.md` §11.3 第 7 条，本报告不擅自改（会违反计划里
   「30 个函数全部登记」的硬规则）。**待真机。**

### P1（当次修或排下一步，不允许无限期挂起）

2. **8 个孤儿模块**（§7.2 #5）：`domain/free-panel-legacy.ts`、`store/text.ts`、
   `store/font-set.ts`、`hooks/useDebouncedCallback.ts`、`features/font-panel/` 下
   5 个组件 + 常量表，当前无人 import。原因是 M2 页面未接入，**M2 完成即消失**；
   若 M2 中止，必须删掉而不是留在仓库里。
3. **`store/font-set.ts` 没有失败通道**：接口按计划 §3.7 冻结，读失败只记日志。
   用户可见的失败发生在写的时候（命令返回 `CORRUPT`/`IO_ERROR`）。已登记为已知取舍。

### P2（可延后，必须登记）

4. `features/home/HomePage.tsx:18` 直接 import `core/ps/diag`：`/debug` 页的本职，
   不是本段引入，维持现状。
5. `encodeText` 有两套算法：`core/cep/text-codec.ts`（服务 `ys_*` 参数）与
   `domain/translate.ts`（服务混淆文本）。**不是重复实现**，两处头部都写了「不是同一套」。
6. `core/ps/text.ts:48` 写操作对「解析不出 `err`」按成功处理，与 §11.2 严格判据不同；
   真机确认返回形状后必须收紧（已写进 `PS-CHANNEL-NOTES` §11.3 第 3 条）。
7. `commands/font-set.ts:411` 快捷字体「加当前图层」读系统字体缓存而不是 `loadFontList()`：
   `commands` 依赖表不允许 commands → commands。缓存缺失时给可行动错误。
