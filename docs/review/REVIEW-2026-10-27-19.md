# 第十九次审查 · 字体管理代码质量（2026-10-27）

> 范围：`features/font-manage`、`commands/font.ts`、`repo/font-repo.ts`、`store/font.ts`、
> `domain/font-*.ts`、`core/ps/font.ts`、`hooks/usePagedList.ts`、`hooks/useInfiniteScroll.ts`。
> 方法：逐文件读 + 死代码/死样式扫描 + 导出面扫描 + React 规则 + 分层边界核对。
> 结论：**没有新的 P0；可维护性总体好；本轮修 5 处，剩 10 条结构性建议**。

## 一、本轮修掉

| # | 问题 | 修法 |
|---|---|---|
| 1 | `FontWeight` 下拉的 padding 点击冒泡到列表项 → 误触「应用字体」 | 弹层容器加 `onClick stopPropagation` |
| 2 | `--mm-glyph-font` 直接拼 `"${ps}"`，未转义；与 `useFontManage` 的 `cssQuote` 重复 | 抽 `features/font-manage/css.ts`（`cssQuote` / `fontFamilyValue`），两处共用 |
| 3 | 字重字形 `key={ps}`，PostScript 重名会撞 key | 改成 `${ps}-${index}` |
| 4 | `usePagedList.PAGE_SIZE` 导出但无外部消费者 | 收回为模块内常量 |
| 5 | `font-repo` 的 `replaceFontTags` / `replaceFontStars` / `restoreFontStars` 只被同文件用却导出 | 收回，缩小公共面 |

## 二、分层质量结论

| 层 | 结论 |
|---|---|
| `domain` | 纯函数、零 IO；`filterFonts` 预先建 Set；`parseTagArchive` 先校验后写；30 个用例 |
| `repo` | 唯一读改写入口；三种「文件不存在」语义分成三个入口；「缺失=空」只有一处；12 个用例 |
| `commands` | 不碰 DOM、不弹 toast、失败码原样透传；导入先评分后标签、失败回滚；无单测（依赖 CEP 对话框） |
| `store` | 只读投影，不 import commands；选择器订阅 |
| `hooks` | 分页/触底各一份；触底用 callback ref + 事件 ref，节点替换能重挂 |
| 页面 | `memo` + `content-visibility` + `useDeferredValue`；组件基本 ≤100 行 |
| CSS | 全部 token；扫描 101 个类，未引用 12 个都是动态拼接（`item--${mode}` 等），**无死样式** |

## 三、未修的结构性问题

| 级别 | 问题 | 证据 | 建议 |
|---|---|---|---|
| P1 | 单文件过大：`useFontManage.ts` 425 行、`FontManagePage.css` 957 行 | `wc -l` | 拆 3 个 hook（数据/筛选、标签动作、应用与评分）与 3 个 CSS（layout / list / popover）；纯移动，不改行为 |
| P1 | `apply` 依赖 `weightIndex`，每次应用后回调换新 → 所有 memo 行重渲染 | `useFontManage.ts` `apply` 的 deps | 用 ref 读当前字重，让 `apply` 稳定；或把字重索引随事件传 |
| P2 | 折叠高度两处：`TagFilter` 常量 94 与 CSS `--mm-tag-collapse-h: 94px` | `TagFilter.tsx:10`、`FontManagePage.css` | 从 CSS 变量读一次，或把常量提到共享模块并内联设置 |
| P2 | 三套输入框：`SearchRow` 用 `Input`，`PreviewText` / `TagInput` 用原生 input | 三个组件 | `PreviewText` 改用 `Input` + class；`TagInput` 保留（需要自定义清空/IME） |
| P2 | 字体 token 两套命名：`--mm-font-10/11/12/15` 与 `--mm-font-xs/sm/md` | `tokens.css` | 合并为语义 token，数值 token 删除 |
| P2 | 两个强调蓝：`--mm-color-accent`(#0f7df2) 与 `--mm-color-accent-solid`(#3565ff) | `tokens.css` | 要么统一，要么在 tokens 注释里写清各自场景 |
| P2 | 无障碍：`PreviewSetting` / `SearchRow` 缺 `aria-haspopup`，弹层缺 `role`；`TagCreator` 关闭后焦点不回到触发器 | 组件 | 补 aria；关闭时恢复焦点（记录打开前的 activeElement） |
| P2 | `TagMenu` 每个标签做两次 `active.includes`，O(n²) | `TagMenu.tsx:33-34` | 先建 `Set` |
| P2 | `TagCreator` 连点「确定」可重复提交 | 无 submitting 状态 | 加提交中禁用 |
| P2 | 列表 `key={font.family}`，同家族多条目会撞 key | `FontManagePage.tsx:103` | key 加 `postScriptNames[0]`（或归一化时合并） |
| P2 | `normalizeFontItem` 保留没有 PostScript 名的项：列表可见、点必失败 | `font-normalize.ts` | 归一化时判坏并计入 `dropped`，或列表上标灰 |

## 四、结论

- **没有发现新的数据安全或分层违规**：写入口唯一、读失败不写、未知键保留、导入可回滚。
- 主要质量债是**文件体积**（hook 425 / CSS 957）和**少量重复常量/输入框**；都不影响正确性，适合单独一轮纯搬家。
- 测试：`domain` 30 个 + `repo` 12 个用例覆盖关键纯逻辑与写路径；`commands` 依赖 CEP，暂不可单测。

## 六、P1 / P2 落地（同日补齐）

| 项 | 处理 |
|---|---|
| P1 文件体积 | `useFontManage` 425 → **285**；标签动作拆到 `useTagActions.ts`（206）；CSS 957 → **433 + 282 + 244**（页面 / 列表 / 浮层） |
| P1 `apply` 稳定 | 字重索引改由 ref 读取，`apply` 只依赖 `notify`；应用一次不再让所有行换回调 |
| P2 折叠高度 | `TagFilter` 量取 `--mm-tag-collapse-h`，TS 不再写死 94 |
| P2 三套输入框 | `PreviewText` 改用公共 `Input`，复合选择器保证覆盖顺序；只剩 `TagInput` 因需自定义清空/IME |
| P2 字号 token | 删 `--mm-font-10/11/12/15`，改为 `2xs / xs / sm / xl`，全仓替换 |
| P2 两个强调蓝 | `--mm-color-accent-solid` 加注释：字体页原版蓝，与全局 `accent` 不混用 |
| P2 无障碍 | 三个触发器补 `aria-haspopup`；筛选/预览卡/标签弹层补 `role="dialog"`；标签右键补 `role="menu"`；`TagCreator` 关闭后把焦点还给打开者 |
| P2 TagMenu O(n²) | 先建 `Set` 再分组 |
| P2 重复提交 | `TagCreator` 增加 `submitting`，提交中禁用按钮并显示「处理中…」 |
| P2 列表 key | `family + postScript[0]`，同家族多条目不再撞 key |
| P2 无字面项 | 不静默丢数据：列表标灰 + `title` 说明「缺少字面信息」 |

**没做的**：`normalizeFontItem` 仍保留无 PostScript 名的项。理由：真机数据未验证，归一化阶段直接判坏可能把整批字体丢光；改为「显示但标灰，点击给出明确错误」。
