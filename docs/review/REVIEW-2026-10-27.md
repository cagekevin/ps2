## 四、AI 抄错风险清单

### P0-1：两套读写 JSON 的实现

| 位置 | 写法 |
|---|---|
| `core/storage/index.ts:74` | `readJson(name, fallback, root)` — 双根、去 BOM、带日志 |
| `core/cep/bridge.ts:138` | `readJsonFile(name, fallback)` — **硬编码 `/FengZiSeBan`**、无 BOM 处理、无日志 |

`bridge` 里的 `readDataFile` / `writeDataFile` / `readJsonFile` 是早期遗留，与 storage 完全重叠，而且指向旧目录。

**后果**：AI 看到 bridge 有现成的 `readJsonFile`，会直接用它，写进 `FengZiSeBan` 而不是 `Maomao`，数据分裂。

**动作**：删除 `bridge.ts` 里这三个函数，只保留路径与 evalScript。

### P0-2：`'EvalScript error.'` 字面量散落 5 处

```
core/cep/bridge.ts:55,74
core/ps/init.ts:15
core/ps/layer.ts:20,30
core/ps/shape.ts:21
core/ps/document.ts:24
```

**后果**：CEP 某天返回别的错误串，要改 5 个文件，必然漏。

**动作**：在 `core/cep` 导出常量 `JSX_ERROR` 与 `unwrap(raw)`，ps 层统一调用。

### P1-1：导航配置与路由双份维护

`nav-config.ts` 的 `implemented: true` 与 `router.tsx` 的 `<Route>` 是两份独立数据。

**后果**：AI 加页面只改一处 → 导航有项但路由 404，或路由存在但导航看不见。

**动作**：在 `check-templates` 或新增脚本里校验「implemented 的项必须在 router 有对应 Route」。

### P1-2：HomePage 孤儿 + store/app 死代码

`features/home/HomePage.tsx` 已不在路由里（router 只注册 `/style`），但仍是「范本」；`store/app.ts` 只被它使用，等于死代码。

**后果**：AI 会以为这是可用页面，或者复制它的 store 用法。

**动作**：要么把 HomePage 接到某个路由（如 `/debug`），要么删除并把 store 范本改到 style 切片上。

### P1-3：6 个横切零使用

`storage`、`paths`、`http`、`auth`、`ui`、`store` 都没有真实调用方。

**后果**：AI 照抄时，第一个真实使用会暴露问题（比如 storage 的 `makedir` 参数）。

**动作**：写第一段样式页时，正好让 `storage` + `paths` + `store` 落地；`http` + `auth` 等接口阶段。

### P2-1：`isRecord` 守卫重复

`domain/style-library.ts` 内部私有实现了 `isRecord`，其他模块若需要会再写一份。

**动作**：抽到 `src/types/guards.ts`，全项目共用。

### P2-2：`nav-config` 的 `implemented` 是人工维护

新增页面时容易忘记改。属于 P1-1 的一部分。
