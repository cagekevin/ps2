## 5. 修复记录

1. **bug 本体**：`capabilities.ts` 的 `getActionList.parse` 由 `passthrough` 改 `sentinelJson`（raw 文本 → 值），数组 / `{info:[]}` 的归一仍留在 `domain/action-library.mapPsActions`。
2. `action.ts` 文件头两条过时描述改掉（「返回不解码」→「返回已解成值」；`UNVERIFIED` → 真机结论），并写明「不要退回 `passthrough`」的原因。
3. `GOVERNANCE` §4.1「PS 动作」行改成 `parse: sentinelJson` + 「不许用 `passthrough`」；「raw 协议解析」行白名单补 `sentinelJson`。
4. `raw.ts` 的 `sentinelJson` 注释从「`mm_style_getForegroundColor` 这一档」改成按判据描述（宿主直接返回载荷、无 err 信封的读能力），不再绑单一消费者。
5. `PS-CHANNEL-NOTES` §11.5 补一句「到前端是 JSON 文本（`bridge.ts:154`）」，避免下一次按「返回数组」直读。
6. `action.test.ts` +1 条：`CAP.getActionList.parse('[{"name":…,"children":[…]}]')` 必须得到数组。
7. 债 `TD-01-30` 登记（`psdList` 同类缺陷）。
