## 一、总体结论

**结构是干净的，没有第二套做法。**

- 找模型：只有 `core/cut/engine.resolveModel` 一处，候选顺序与 `core/dlss/engine.resolveRuntime` 同一条 `CONVENTIONS` §5.2 规则（形状差别只有「单个文件」与「目录 + 找 exe」，plan 21 §2 已写明属允许）。
- 临时目录：只有 `core/temp.prepareTemp(domain)` 一个出口，`CUT_TEMP_DIR` 是它的入参；jsx 侧吃传进去的绝对路径，不拼 `Folder.temp`。
- 结果贴回文档：**只有一处 `mm_placePngIntoDoc`** —— DLSS 导回与抠图（`core/ps/cut.placePng`）都调它，jsx 侧没有第二份。它的 `frameOffsetX/Y` 量测服务抠图（结果图四周有透明留边），DLSS 满画布不透明时恒为 0。
- 本地 tile：只有 `domain/common-use.LOCAL_TILES` + `appendLocalTiles`，拼接点在 store 的两个入口复用同一函数；`toTiles` 未被改动（官方 14 项仍只来自文件）。
- 设置页只有一段「抠图模型」，与「DLSS 引擎」段同形（只读输入框 + 当前命中 + 选择按钮）。

体检当场发现 **1 个 P2（3 条零引用文案）**、**1 个文档漂移（目录树缺三处）**，均已修。

## 四、修复记录

1. **删 `MSG.cut.running` / `done`**：抠图没有「页面级 tip + 成功提示」的调用点（tile 直接执行），留着就是死文案。删后 `MSG.cut` 只剩 3 条，全部有消费者。
2. **接 `MSG.cut.noPython` / `missingDeps`**：新增 `src/commands/cut.ts` 的 `function explainRunFailure<T>(failure: Failure): Result<T>`，在 `cutCurrentLayer()` 的 `runCut` 失败分支调用。判据只有两条：
   - `failure.code === 'IO_ERROR' && failure.detail.startsWith('spawn:')` → `MSG.cut.noPython`（`runProcess` 只在 `spawn` 抛错时给这个前缀）；
   - `failure.detail.includes('ModuleNotFoundError')` → `MSG.cut.missingDeps`（Python 侧 stderr 原样进 detail）。
   其余原样返回 —— **不按 `code` 猜**：`IO_ERROR` 还可能是读图失败。
3. **`docs/CONVENTIONS.md` §3 目录树补三处**：`core/cut/`（模型探测两条候选 + spawn Python 脚本）、`core/temp/`（临时目录唯一出口）、`public/vendor/cut/`（Python 推理脚本，随 dist 走；模型 176MB 不进 `public/`，见 §5.2）。

三项均未新增导出、未改签名、未动 `jsx` 契约。
