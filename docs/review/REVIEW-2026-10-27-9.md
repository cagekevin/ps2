## 三、P1（已修）

### P1-1：`fs()!` 非空断言（ku-archive.ts:87）

`sidecarNamesOfWarehouse` 里 `fs()!.readFileSync(...)`——Node 模块不可用时直接 TypeError，
而同文件其他调用点都判了 null。已改为先判空返回 `fail('IO_ERROR', ...)`。

### P1-2：坏 JSON 被静默跳过（ku-archive.ts:87）

`readFileSync` 和 `JSON.parse` 合并在一个 try 里，库文件存在但内容损坏会 `continue`——
导出的包**少几张旁路图而用户以为导全了**。app 同位置注释明确禁止（「读不到和读不懂不许同待遇」）。

已拆开：文件不存在 = 跳过（没导出过，正常）；文件存在但解析失败 = `CORRUPT` 中止导出。

### P1-3（第 7 项）：BottomBar 直接调 `getBoundingClientRect`

底层 API 的调用点在 `features/` 层。修法不是把它挪个地方，而是让 `ContextMenu`
支持 `anchor?: HTMLElement` ——定位知识进了公共组件，`features` 里的调用清零。
复检：第 7 项零命中。
