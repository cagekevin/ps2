## 9. React 最佳实践对照（`react-best-practices` 57 条的适用子集）

范围：本轮写的 `features/common/**`、`app/common-use-watcher.tsx`、`components/{Segment,IconPanel}`。
57 条里有 20 条是 Next.js / RSC / 服务端专属（`server-*`、`async-suspense-boundaries`、`bundle-defer-third-party` 等），
本仓是 CEP 里的纯客户端 SPA，**不适用**；下面是适用项逐条结论。

### 9.1 本轮改的（3 处真问题）

| 规则 | 问题 | 处理 |
|---|---|---|
| `rerender-derived-state-no-effect` | `ExportPanel` 用 6 个 `useState` 复制 store 里的值（路径 / 命名 / 品质 / 宽 / 高 / 水印）→ 别处改了设置，本地草稿永远是旧的（上一轮记的 P2-2） | 改用 `hooks/useDraft`（渲染期比较、源值变了才回填），6 个 `useState` → 1 个草稿 + `setField` |
| `js-hoist-regexp` | `CustomTransformPanel` 的「非数字」正则在每次按键时新建；`ExportPanel` 与 `ps-events.droppedPathOf` 的反斜杠正则同理 | 三处提到模块级常量 |
| `rendering-hoist-jsx` | `CustomTransformPanel` 的「3 行 × 2」分组数组每次渲染重建 | 提到模块级 `FIELD_ROWS`（`Array.from` 一次生成） |

### 9.2 通过（附证据）

| 规则 | 证据 |
|---|---|
| `rerender-derived-state` | 页面/store 全订阅派生布尔：`booleanOptionOf(...)` 选择器 6 处；`s.options.` 直读 = 0 |
| `rerender-dependencies` | `common-use-watcher` 的 effect 依赖是 6 个原始布尔，没有对象/数组 |
| `rerender-functional-setstate` | `setDraft((current) => ({ ...current, [key]: value }))`；`setDraft` 来自 `useDraft` 内部函数式更新 |
| `rerender-lazy-state-init` | `useDraft` 内部 `useState(() => ({...}))`；`CustomTransformPanel` 初值是模块常量 `EMPTY` |
| `rerender-move-effect-to-event` | 页面只有 1 个 effect（首屏 `load()`）；提交/开关全在事件处理器里 |
| `async-parallel` | watcher 的 5 个 `subscribeHostEvent` 是 `void …then()` 并行发起，没有 `await` 串行；`ExportPanel` 的批量导出是「先拿列表再逐份导」，天然串行（每份一个 evalScript） |
| `rendering-conditional-render` | 搜 JSX 里的 `&&` 与 `length` / `count` 组合 = 0；条件渲染一律三元 + `: null` |
| `js-set-map-lookups` | `TILE_COMMANDS[tile.id]`、`LINK_OBJECT_LABELS[value]` 都是对象/Map 直取，无 `find` |
| `js-early-exit` | 所有校验函数先 return，命中最短路径 |
| `bundle-barrel-imports` | 新增 import 全部指向具体文件；唯一「看起来像 barrel」的是 `components/ui`，那是 `CONVENTIONS` §5.1 定的唯一 UI 出口，属**约定例外** |
| `bundle-dynamic-imports` | 7 个面板都在 `CommonPage` 内，页面本身由 `app/router` 懒加载；`Segment` / `AnchorGrid` 是小件，拆出来反而多一次往返 |

### 9.3 接受但不改（写明理由）

| 规则 | 现状 | 为什么接受 |
|---|---|---|
| `client-event-listeners` | 任一开关翻转会让 watcher 把**当前所有**语义退订再订阅（effect 依赖 6 个布尔） | 订阅是「加/删 listener + 按事件 ID 去重注册」，一次切换的成本在微秒级；拆成 6 个独立 effect 要复制 6 段几乎相同的代码，可读性损失大于收益。若真机发现事件注册有配额限制再改 |
| `rendering-content-visibility` | 网格 14 格、面板 7 块，无长列表 | 本页没有 100+ 项，不需要 |
| `rerender-memo` | 面板内的 `map` 渲染都没包 `memo` | 每块内容 ≤ 10 个节点，包 `memo` 的比对成本高于重渲染 |

**结论**：适用项 3 处真问题已修，10 条通过有证据，3 条写明接受的例外。没有为了「符合 57 条」去加 `memo`/`useCallback` 这类负优化（`CONVENTIONS` §18 同样要求「不要无脑包」）。
