## 二、修的问题

### 1. 形状能力有两套，旧的有 bug（P0）

| 实现 | 位置 | 状态 |
|---|---|---|
| 旧版 | `core/ps/shape.ts` + jsx 5 个 `mm_shape_*` | 日志证明对形状图层返回 `not-shape` |
| 移植版 | `core/ps/style.ts` + jsx `mm_style_*` | 已验证通过 |

证据（2026-10-27 03:15:36 日志）：

```
mm_layer_getKind  raw:"smartObject"
mm_shape_setFill  raw:"not-shape"      ← 形状图层也报 not-shape
```

旧的 `setShapeFill` 只被 `HomePage` 的测试按钮调用，其余 3 个函数零使用。

**已删**：`core/ps/shape.ts`、jsx 的 `mm_shape_apply` / `mm_shape_setFill` / `mm_shape_setStroke` / `mm_shape_setFillEnabled` / `mm_shape_setStrokeEnabled` / `mm_parseColor` / `mm_rgbOf`（共 97 行）、`HomePage` 的「填充示例色」按钮。

**连带修正**：`init.ts` 的能力探测列表原本探 `mm_shape_setFill`，函数删了会导致 vendor 永远标记为不可用。已换成 `mm_layer_getState` / `mm_style_applyColor`。

### 2. `core/ps` 文档树写错（P0）

文档写的：

```
├─ layer.ts     选择、类型、重命名、显隐、锁定
├─ shape.ts     填充/描边读改、开关
├─ text.ts      内容、字体、字号、颜色      ← 文件不存在
├─ smart.ts     替换、嵌入                  ← 文件不存在
└─ document.ts  信息、导出
```

实际有的：

```
├─ init.ts      jsx 加载 + 能力探测
├─ layer.ts     选择、类型、名称
├─ style.ts     颜色 / 渐变 / 图层样式应用
├─ font.ts      字体应用（先检查再应用）
├─ document.ts  文档信息
├─ env.ts       环境变量注入
└─ diag.ts      能力诊断
```

**5 个里错了 4 个**。AI 照文档找 `text.ts` 会找不到，然后自己新建一个——这正是结构漂移的起点。

### 3. 命名示例用了已删除的函数

`CONVENTIONS.md` §8 的命名约定举例 `setShapeFill` / `mm_shape_setFill`，这两个已不存在。已换成 `getLayerState` / `mm_style_applyColor`。
