# 色板工具本地版 · 上色逻辑理解

> 这份文档记录「点色块给图层上色」这件事的完整逻辑：官方怎么做的、本机 PS 上哪些 API 真的能用、
> 本地版现在怎么实现的、每一处为什么这么写、还差什么。
> 写它的目的：后面再改这块时，不要重新踩一遍已经踩过的坑。
> 事实与推断分开标注；推断的地方写明依据与验证方法。

---

## 一、目标与范围

| 项 | 说明 |
|---|---|
| 目标 | 点一个色块 → 给**所有选中图层**上色；一次撤销全部回退 |
| 范围 | 仅 PS 侧（`jsx/main.jsx`）；前端 `js/app.js` 只负责发一次 `evalScript` |
| 不做 | 登录态、主面板、官方目录依赖（本地版的立身之本） |
| 涉及图层类型 | 普通像素、形状、文字、智能对象、图层组（组 = 容器，只能用颜色叠加） |

## 二、官方版是怎么做的（事实，来自官方副本）

官方副本位置：
- `扩展备份/com.local.psz.seban-old/`（色板工具独立面板，含 2019 年前后的改动）
- `%APPDATA%\Adobe\CEP\extensions\com.local.psz.panel.v4\panel\js\app.v4.js`（主面板前端）
- `%APPDATA%\fz.FengZi3Hao\jsx\main.jsx`（色板面板明文 jsx，与备份同源）

### 2.1 点色块走两路

官方 `js/sf.js:286-320`（`YingYongYanSe`，左键）：

```js
} else {
  var mesObj = { type: 'setColor', data: arr[index].color };
  f_SendMessage(mesObj);          // 路①
  f_BenDiShangSe("fill", ...);    // 路②（本地面板版的补丁，官方原版这里是本面板 jsx）
}
```

| 路 | 链路 | 作用 |
|---|---|---|
| ① | `f_SendMessage`（sf.js:598-605）→ CEP 事件 `com.fengzi.event.seban` → 主面板 `app.v4.js:17773` 绑定 → `handleSeBanEvent`（app.v4.js:17894-17900）→ 读开关 `cyAutoFillColor`：开 → `ys_useStyleColor(item, isFill=true)`；关 → `ys_setForegroundColor(item)` | **多图层上色在这里**（主面板的「智能填充」，`ys_useStyleColor` 在加密的 vendor.jsx 里，读不到） |
| ② | 本面板 jsx `sb_cy_SheZhiQianJingSe`（官方 `jsx/main.jsx:6`） | **只有单选才上色**：官方 `main.jsx:32-33` —— `iTuCengGeShu = sb_DL_HuoQuDangQianTuCengShu(); if (iTuCengGeShu == 1) { ...上色... }`。多选时只设前景色 |

官方原注释（同处）：`2019.04.16更新 去掉自动填充应用普通图层，增加 颜色关联 可以对其他图层进行着色`。

**结论**：官方色板工具面板自己的 jsx 不做多图层上色；多图层能力在主面板的智能填充里。
本地版不依赖主面板，所以必须自己实现「逐层上色」—— 这不是抄官方色板面板的代码能解决的，
要抄的是官方**处理多图层选择**的那套动作（见 2.3）。

> **主面板那一半抄不了**：真正干活的 `ys_useStyleColor` 在**加密的 vendor jsxbin** 里
> （`com.local.psz.panel.v5/lib/all.decrypted.js` 头部是 `@JSXBIN@ES@2.0@…`，仓库 `jsx/vendor.jsx` 是同一份密文，
> 明文 grep `ys_` 前缀函数名命中 0）。能抄的只有事件契约 `{type:'setColor', data:color}`，
> 而我们没有主面板，抄了也发不出去。⇒ 多图层上色只能自己实现，且只能用官方的选层原语（见 3.4）。

### 2.2 官方上色的四条通道（`jsx/main.jsx:43-81`）

| 图层类型 | 官方做法 | 函数 |
|---|---|---|
| 普通图层 NORMAL | 锁透明度 → 填充前景色 → 解透明度 | `sb_DL_SuoDingTuCengTouMingDu` / `sb_DL_TianChongQianJingSe` / `sb_DL_JieSuoTuCengTouMingDu` |
| 形状 SOLIDFILL | 有填充改填充色，只有描边改描边色 | `DL_SheZhiXingZhuang`（`:173`） |
| 文字 TEXT | `textItem.color = c` | `main.jsx:79` |
| 智能对象 SMARTOBJECT | 图层样式颜色叠加 | `sb_DL_XuanXiangYanSeDieJia`（`:433`） |

另有两条官方细节，本地版原先没有：

- **同色规避**（官方 `main.jsx:25-29`）：目标色 == 当前前景色时，先把前景色设成 `f0ebe2`，再设目标色，
  否则「填充前景色」不触发。
- **颜色对象按文档模式构造**（官方 `main.jsx:11-22`）：CMYK 文档只填 `cmyk.*`，否则只填 `rgb.hexValue`。
  两种颜色一起塞进同一个 `SolidColor` 是错的（见 三.8）。

官方 `jsx/main.jsx:526-609`（形状「去填充/去线框」`sb_SheZhiXingZhuang` 就是靠它们做多图层）：

## 三、本机真机验证到的 PS 侧事实

验证环境：Photoshop 21.x，文档为 **CMYK 模式**（前景色回读 `hex|c|m|y|k` 的 cmyk 段与文档一致），

### 3.1 `doc.activeLayers` 在本机不存在

```js
try { act = doc.activeLayers.length; } catch (e) { }   // → act = -1
```

读 `.length` 抛错 ⇒ 属性本身不存在（不是「没有选中图层」）。
⇒ **取多选不能用 `doc.activeLayers`**。仓库 `maomao-design-tools` 的 `mm_layer_getSelection`
用的是 `app.activeDocument.activeLayers.length`（`jsx/main.jsx:70`），在别的机器上可用，
说明这是版本/实现差异，不是 PS 通用写法。

### 3.2 `targetLayers` 能准确给出选中数量与引用

```js
ref.putProperty(charIDToTypeID('Prpr'), stringIDToTypeID("targetLayers"));
ref.putEnumerated(charIDToTypeID('Dcmn'), charIDToTypeID('Ordn'), charIDToTypeID('Trgt'));
desc = executeAction(charIDToTypeID('getd'), args, DialogModes.NO);
list = desc.getList(stringIDToTypeID("targetLayers"));
```

实测 `list.count` 与用户选择一致（1 / 2 / 3 / 4 次都对）。
⇒ **官方取多选的这条路是可靠的**，与官方 `sb_DL_HuoQuDangQianTuCengID` 同款。

### 3.3 引用上只有 `getIndex('Lyr ')` 能用

| 尝试 | 结果 |
|---|---|
| `list.getReference(i).getObjectValue(stringIDToTypeID('layer'))` | 取不到图层对象（`picked=0`） |
| `list.getReference(i).getIdentifier(charIDToTypeID('Lyr '))` | 取不到（`ids=0`） |
| `list.getReference(i).getIndex(charIDToTypeID('Lyr '))` | **可用**，返回数字 |

⇒ 想拿到图层对象，只有「序号」这一条路（官方走的就是这条）。

### 3.4 官方处理多图层选择的三个原语（抄这三段，别自己发明）

官方 `jsx/main.jsx:526-609` 给出三个原语，本地版已原样抄入（函数名加 `sb_` 前缀）：

| 原语 | 作用 | 关键实现 |
|---|---|---|
| `sb_DL_HuoQuDangQianTuCengID()` | 取所有选中图层的序号 | `targetLayers` 引用 → `getIndex('Lyr ') + 1` → itemIndex 列表；单选时返回活动层的 itemIndex |
| `sb_DL_GenJuXuHaoQuXiaoTuCeng(id)` | 按序号取消选中某层 | `putIndex('Lyr ', id + bgOffset)` + `removeFromSelection`；`bgOffset` = 文档有背景层时 -1 |
| `sb_DL_GenJuXuHaoDuoXuanTuCeng(ids)` | 按序号加选图层 | `putIndex('Lyr ', id + bgOffset)` + `addToSelection` |

**官方的多图层思路**：不把图层对象取出来，而是**用「序号 + select 动作」控制当前只有一个图层被选中**，
它就是活动层，对活动层执行动作；处理完再把选中的图层加选回去。

官方形状动作 `sb_SheZhiXingZhuang`（`main.jsx:459-496`）就是靠这套做的：**倒着**把选中层一个个取消选择，
每取消一个，活动层就落到下一个；满足条件就执行并 break；最后统一加选回去。

> **不要再用「自己摊平所有图层 → 按序号查」的写法**（已删）：组内图层的 `itemIndex` 是相对所在组的，
> 根层级里查不到；自己摊平又有歧义（多层同名、多个组同序号）。官方原语是唯一验证过的做法。

### 3.5 `slct` 动作带 targetLayers 引用不生效

```js
d.putReference(charIDToTypeID('null'), list.getReference(i));   // 引用直接当目标
d.putEnumerated(..., 'addToSelection');
executeAction(charIDToTypeID('slct'), d, DialogModes.NO);
```

实测：4 次调用后活动层始终是同一个「自动按钮」（4 层都叫这个名字），选中数也没变。
⇒ **这条路不成立**，已从实现里删除。

### 3.6 所有改颜色的动作都作用于**活动层**

| 动作 | 目标 |
|---|---|
| `Fl  `（填充前景色） | 活动层 |
| 形状样式 `setd` → `contentLayer`/`Trgt` | 活动层 |
| 图层样式 `setd` → `Lefx` | 活动层（`Trgt` = 目标层） |
| `textItem.color` | 指定的图层对象 |

⇒ 上色的循环体必须保证「目标层 = 活动层」。

### 3.7 图层名不能做标识

实测 4 个选中层**名字完全相同**（都是「自动按钮」）。
⇒ 定位只能靠序号/引用，不能靠名字。

### 3.8 颜色对象要按文档模式构造

官方 `main.jsx:11-22` 与仓库 `mm_style_applyColor` 都是：

```js
if (app.activeDocument.mode === DocumentMode.CMYK) { c.cmyk.cyan = ...; } else { c.rgb.hexValue = hex; }
```

本地版原先的 `sbSolid` 两种都填（`c.rgb.hexValue` + `c.cmyk.*`）。在 CMYK 文档里这会让
「把颜色赋给图层」这一步抛错（文字 `textItem.color = c`、形状 `c.rgb.red` 读取都可能受影响）。
**待真机确认**：把 `sbSolid` 改成按模式构造后，文字层是否恢复正常。

### 3.9 图层样式里「颜色叠加」会盖住内容颜色

- 内容颜色的来源：普通图层=填充、形状=形状填充色、文字=`textItem.color`。
- 若图层带**颜色叠加**样式，可见颜色由样式决定 → 改内容颜色看不出变化（用户反馈的「有图层样式就不生效」）。
- **投影不盖内容颜色**：只有投影的文字层，改字色是看得见变化的。
  ⇒ 用户说的「有图层样式就不生效」要么是那层同时有叠加样式，要么是 3.8 的赋值失败被吞了。两者修法不同，要靠日志区分。
- 渐变叠加 / 图案叠加不能替换成纯色（会毁设计），只能记日志不动。

### 3.10 撤销

多图层上色若不包撤销组，每层各是一条历史记录 → 只能一层一层撤（用户反馈）。
⇒ 整批必须包一个 `suspendHistory`。

## 四、本地版当前实现

文件：`色板工具本地版/jsx/main.jsx`（唯一的 PS 侧实现）、`js/app.js`（前端）、`js/core.js`（通道与持久化）。

### 4.1 数据流

```
用户点色块
  → js/app.js applyColor(item, wire)
  → js/core.js ps.dispatch('ys_useStyleColor' | 'ys_setBorderColor', [项], 标签)
  → CSInterface.evalScript("ps_onJsx('{...}')")
  → 官方 vendor（jsx/vendor.jsx）一次处理所有选中图层
  → 返回值：-1 = 宿主拒绝（多为没选中图层），其余视为成功；面板按此提示
```

### 4.2 函数清单

**`jsx/main.jsx`（面板自己还要用的能力）**

| 函数 | 职责 | 依据 |
|---|---|---|
| `sbS` / `sbC` | stringID / charID 包装 | — |
| `sbEncode` | 颜色编码 `hex\|c\|m\|y\|k` | 官方 `sb_ZhuanHuanYanSeDuiXiang` |
| `sbGetForegroundColor` | 读前景色 | 面板「最近使用」 |
| `sbGetLayerColor` | 读当前图层颜色（文字/形状） | 面板图标 4 |
| `sbPickColor` | 拉系统取色器 | 面板 ctrl+左键 |
| `sbShapeInfo` / `sbShapeStyle` | 形状填充/线框的读取与写入 | 官方 `DL_SheZhiXingZhuang` |
| `sbSetShape` / `sbSwapStrokeFill` | 去填充去线框 / 填充线框互换 | 面板图标 6、7 |

**`js/core.js`（通道层）**

| 函数 | 职责 | 依据 |
|---|---|---|
| `PS_ENV` | 官方 vendor 要的 15 个环境变量（字段名不能改） | 仓库 `core/ps/env.ts` 同一份 |
| `ps.loadVendor` | 加载 `jsx/vendor.jsx` → 注入环境变量 → 探调度宿主 | 仓库 `core/ps/init.ts` |
| `ps.dispatch` | 调度通道 `ps_onJsx({f,arr,n})` | 直接调 `ys_*` 会报「缺少必需值」 |
| `ps.vendorReady` | 官方 vendor 是否可用 | 不可用时点色块会明确提示 |

**`js/app.js`**

| 函数 | 职责 |
|---|---|
| `applyColor` | 点色块 → 官方 `ys_useStyleColor`（线框走 `ys_setBorderColor`）；官方拒绝或 vendor 不可用 → 明确提示，**不再有第二套实现** |

### 4.3 上色语义

上色全部由官方 `ys_useStyleColor` 决定（见 5.1）。真机取证结论：**文字层改的是字色**（内容颜色通道）；官方**不给任何层加「颜色叠加」样式**；智能对象与图层组官方也不处理（与用户观察一致）。

### 4.4 撤销与多选

撤销与多选状态都由官方智能填充自己管（`jsxHistory` 通道），本地版不插手。

### 4.5 已知缺口

| 缺口 | 现状 |
|---|---|
| 智能对象批量不上色 | 官方行为；单独选中它再点一次即可 |
| 图层组不上色 | 官方行为 |
| 官方 vendor 加载失败 | 面板会明确提示（不留静默兜底） |

## 五、当前实现（两条路，主次分明）

### 5.1 主路：官方 vendor 的智能填充（多图层上色的真正实现）

```
用户点色块
  → js/app.js applyColor()
  → ps.dispatch('ys_useStyleColor', [{hex,c,m,y,k,isFill:true}], '智能填充颜色')
  → ps_onJsx('{"f":"ys_useStyleColor","arr":[…],"n":"智能填充颜色"}')     ← 官方调度入口
  → 官方 vendor（jsx/vendor.jsx，加密 jsxbin 原文件）一次处理所有选中图层
```

要点：

1. **`jsx/vendor.jsx` 就是官方 vendor 原文件**（与 `com.local.psz.panel.v5/lib/all.decrypted.js`、
   仓库 `jsx/vendor.jsx` 同一份，MD5 `c6ca05a0…`）。读不了没关系，PS 能执行，主面板就是这么用的。
2. **不能直接调 `ys_useStyleColor`** —— 官方 `ys_*` 走调度通道，直调报「缺少必需值」。
3. **加载顺序不能改**（照仓库 `core/ps/init.ts`）：`evalFile jsx/main.jsx` → `evalFile jsx/vendor.jsx`
   → `Sys_setSystemEnvInfo(PS_ENV)` → 探 `typeof ps_onJsx`。环境变量少一个就报「undefined 不是对象」。
4. **参数形状**：官方主面板把色板项里的**扁平颜色对象** `{hex,c,m,y,k}` 加上 `isFill:true` 传进去
   （`app.v4.js:17894-17900`），本地版照抄。`isFill` 在顶层。
5. 线框色对应 `ys_setBorderColor`（官方 `app.v4.js:17902-17903`）。
6. **官方拒绝（返回 `-1`）或 vendor 不可用 → 明确提示**，不留第二套实现（见 4.5）。

### 5.2 已删除的本地实现（留着当反面教材）

本地曾经自己实现过「逐层上色」，现在全部删除。原因与踩过的坑：

| 曾经的写法 | 结果 |
|---|---|
| `doc.activeLayers` + 遍历 | 本机属性不存在（3.1） |
| 摊平所有图层 + 按摊平序号查图层对象 | 根层级能用；组内图层序号对不上（itemIndex 是组内相对值），且同名多层会歧义（3.7） |
| `targetLayers` 引用 → `getObjectValue` / `getIdentifier` | 本机取不到图层对象与 id（3.3） |
| `slct` + targetLayers 引用 | 不生效，活动层不变（3.5） |
| 官方三段原语（`sb_DL_*`）+ 逐层上色 | 能跑，但组内定位未验证，且与官方实现语义不一致 → 保留两套实现是自找麻烦，删 |

### 5.3 真机验证结果（2026-10-28）

面板日志（`%TEMP%\seban-debug.log`）：

```
VENDOR-ENV => {"err":0,"data":true}
VENDOR-DISPATCH => function
DISPATCH ys_useStyleColor => 1        ← 官方智能填充成功返回
```

脚本自检（Photoshop COM → DoJavaScript，不经人手）：

## 七、给后续改这块的人

1. **不要用 `doc.activeLayers`** —— 本机 PS 没这个属性（3.1）。
2. **不要用 targetLayers 引用里的 `getObjectValue` / `getIdentifier`** —— 本机取不到（3.3）。
3. **不要用 `slct` + targetLayers 引用** —— 不生效（3.5）。
4. **不要用图层名做标识** —— 用户可以给多层起同一个名字（3.7）。
5. **颜色对象按文档模式构造** —— CMYK 文档不能 rgb+cmyk 一起塞（3.8，官方与 maomao 都这么写）。
6. **多图层上色优先用官方 vendor**（`jsx/vendor.jsx` + `ps_onJsx`），别自己重写一套：
   官方色板工具的多图层上色就是 `ys_useStyleColor` 做的，主面板只是转发事件；
   我们没有主面板，就自己转发同一个调度调用。
7. **官方 `ys_*` 不能直调** —— 必须经 `ps_onJsx({f,arr,n})`，直调报「缺少必需值」。
8. **vendor 加载顺序不能改** —— evalFile vendor → `Sys_setSystemEnvInfo` → 探 `typeof ps_onJsx`。
10. **每轮只动一处**，已经能用的场景不许退化；新写法先与旧写法并存验证，确认后再删旧的。
