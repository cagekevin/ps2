## 0. 一句话

识别成功之后、建层之前，对**当前选区**做一次内容识别填充。一个 jsx 函数，命令里两行。

```
5 识别 → 6 布局 → 7 抹掉原文（新）→ 8 建层
```

放在建层之前，是因为建层后活动层变成新文字层，填充会打在文字层上。

## 4. 边界

| 情形 | 行为 |
|---|---|
| 无像素选区（整图识别） | 跳过，返回 `ok`。**不整层填充**（不可逆毁图） |
| 活动层是文字 / 形状 / 智能对象 / 组 | 跳过，返回 `ok`。不自动栅格化用户图层 |
| 文字在多个图层上（PSD 文字层） | **不在需求范围内**（用户 2026-11-03 确认）：本步骤只给「文字烧在位图上」的图用，文字是独立图层时删层即可，不需要填充。填充仍只作用于活动层，这是范围不是缺陷 |
| 活动层是透明底的像素层 | 填充只能采样本层，透明区没有内容可采 → 结果可能是一块糊或什么都不变（未验） |
| 宿主拒绝（图层锁定 / 不认 `contentAware`） | `PS_ERROR`；命令层 `log.warn`，**不阻断建层**（文字是主交付） |
| 撤销 | **两步**：填充一步、建层一步。plan 17「一次全撤」自此只对建层成立 |
| 失败是否提示用户 | 不弹 toast：抹没抹掉画布上一眼能看见，弹一句只是噪音 |
| 选区羽化 | 填充边缘跟着羽化渐变，可能留一圈半透明（未验） |

## 5. 验收（真机 3 条）

1. 拉选区框住两行字 → OCR：文字层建出来，原图那块被周围像素补掉。
2. `Ctrl+Z` 两次：先撤文字层、再撤填充。
3. 不拉选区 / 选中文字层时点 OCR：文字照建，图**没有**被整层填掉。

## 6. 未验

1. **`contentAware` 这个枚举值本机 PS 认不认** —— 全仓没有任何证据（它只出现在 Fill 对话框的「使用」下拉里）。认不出时表现为「返回 ok 但图没变」或直接抛错，真机第 1 条专门看这个。
2. **填充的采样来源是「当前图层」还是「所有图层」** —— 决定多层文档能不能用（§4 第 3 行）。`Fl  ` 没有采样范围参数，只有内容识别填充工作区里有「采样所有图层」。
3. **填充质量**：选区靠近画布边缘 / 占满大半张图时，内容识别填充没有足够素材，结果会糊。脚本侧**没有任何参数可调**（强度 / 采样区域 / 颜色适应都在工作区里）。
4. `mm_ocr_selectionRect` 在「选区太小」分支里写死了日志前缀 `mm_ocr_exportImage:`，复用到抹除流程时日志会指向错的函数（一句话可修，落地时顺手改成中性文案）。
