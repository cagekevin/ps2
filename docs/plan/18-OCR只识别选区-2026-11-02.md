# 18 · OCR 只识别选区

日期：2026-11-02
状态：**形状已落地，功能未实现**
- 已落地（2026-11-02）：`OcrExport` / `core/ps/ocr-raw.ocrExportRaw` / `exportImage` 已按 §5 改完，`offset` 恒 `{0,0}`，`raw.exportPathRaw` 已删（`TD-01-31` 结账）。
- 未实现：选区裁切（`dup.crop`）、`offset` 非零、`toOcrGroups` 加偏移。
前置：`docs/plan/17-OCR成图层-2026-11-01.md` 的 M1–M4 已落地（整画布识别可用，见 `docs/CHANGELOG.md`）。本文只加「有选区时只识别选区」，**不改 17 的任何已落地结论**。

---

## 0. 四条裁定

1. **有选区只识别选区，无选区整图**。不新增按钮、不新增弹窗、不新增 tab —— 入口仍是「改字」页的 `[OCR]`（plan 17 §7）。
2. **裁切在 jsx 的副本上做**（`dup.crop`），不引入图像库、不在 Node 侧裁图。
3. **坐标偏移由 jsx 产出、只在 `domain/ocr.toLayer` 加一次**，命令层不做换算。
4. **返回值形状改了就把旧形状删净**：`mm_ocr_exportImage` 不再返回裸路径，`raw.exportPathRaw` 已删（矢量化早就是对象形状，OCR 是它最后一个消费者）。

## 1. 现状（代码事实）

| 环节 | 现状 |
|---|---|
| 导出 | `jsx/main.jsx` 的 `mm_ocr_exportImage` 复制**整份文档** → `saveAs` JPG → 返回 `{ path, offset }`（`offset` 恒 0） |
| 解析 | `capabilities.ts` 的 `ocrExport` 用 `ocr-raw.ocrExportRaw`（认对象，形状不对报 `PS_BAD_PAYLOAD`） |
| 薄函数 | `core/ps/ocr.ts` 的 `exportImage(quality)` 返回 `Result<OcrExport>` |
| 布局 | `domain/ocr.ts` 的 `toOcrGroups(blocks)` 直接按识别坐标出 `left/top`，坐标即文档绝对坐标（**偏移还没接**） |
| 命令 | `commands/ocr.ts` 第 4 步读图、第 6 步 `toOcrGroups`、第 7 步建层 |

⇒ 形状已是对象（`offset` 恒 0），但**没有任何选区概念**：百度返回的坐标天然等于文档坐标。

## 3. 三条硬事实

1. **无选区时 `doc.selection.bounds` 抛异常**，不是返回整画布（`feedmac` 的 `try/catch` 与 Adobe 社区一致）。
   ⇒ 判断只有一处：`try { b = doc.selection.bounds } catch (e) { b = null }`。
2. **`crop` 吃 `UnitRect`**，`[left, top, right, bottom]`，与 `selection.bounds` 同形，可直接传；裁完画布左上归零，**偏移 = 裁切矩形的左上角**。
3. **单位跟随 `app.preferences.rulerUnits`**：`bounds` 与 `crop` 都按当前单位解释。
   ⇒ 与 `mm_text_doCreateAbsolute`（`jsx/main.jsx:490`）同一套写法：存 → 设 `Units.PIXELS` → `finally` 还原。

## 4. 改动清单（7 处）

| 层 | 文件 | 改什么 |
|---|---|---|
| jsx | `jsx/main.jsx` 的 `mm_ocr_exportImage` | 切 px → try 读 `selection.bounds` → clamp → 副本 `crop` → 返回 `{ path, offset }` |
| 类型 | `src/types/ocr.ts` | 加 `OcrExport`（`path` + `offset`） |

| PS 解析器 | `src/core/ps/ocr-raw.ts`（**已落地**） | `ocrExportRaw` 只服务 `CAP.ocrExport`。**必须单独文件**：放 `ocr.ts` 会形成 `capabilities → ocr → capabilities` 运行时环（与 `text-batch-raw.ts` 同一个理由） |
| PS 薄函数 | `src/core/ps/ocr.ts` | 只改返回类型 `Result<OcrExport>`（不 import 解析器） |

| 命令 | `src/commands/ocr.ts` | 第 2–4 步拿 `{ path, offset }`，第 6 步把 `offset` 传给 `toOcrGroups` |

### 4.1 归属裁定：读选区**不**单独建能力

| 候选位置 | 裁定 |
|---|---|
| `core/ps/layer.ts` | **不放**。那里的 `selection` 指「选中的图层」——`mm_layer_getSelection` 返回选中图层数（`layer.ts:82`），像素选区是画布上的蚂蚁线。同名两义，放一起下一个人必然搞错 |
| 新建 `core/ps/selection.ts` + `mm_sel_getBounds` | **现在不建**。只有一个消费者；且读 bounds / crop / saveAs 必须在**同一个副本、同一次 `evalScript`** 内完成，拆开就是两次调用 + 中间态（两次之间用户可改选区）+ 多一个能力表行 / `CORE_FUNCS` / 探测项 |
| `mm_ocr_exportImage` 内部 | **放这里**。TS 侧只看到 `OcrExport.offset`，看不到「选区」这个概念 |

抽公共层的条件（写死，满足才动）：**第二个功能也要读像素选区**（如「矢量化只转选区」「裁剪到选区」）。
那时建 `core/ps/selection.ts` + jsx 的 `mm_sel_getBounds`，命名必须与图层选择一眼可分（`mm_sel_*` vs `mm_layer_getSelection`），两者在能力表里相邻也不许混。

判据一句话：**它是「导出」的一部分，不是「读选区」这个动作。** 谁把它拆成两步，谁就得负责处理两次调用之间选区被改的情况。

## 5. 契约

```ts
// src/types/ocr.ts
export interface OcrExport {
  path: string;
  /** 裁切矩形左上角（px，文档坐标）；无选区时为 0 */
  offset: { left: number; top: number };
}
```

```js
// jsx/main.jsx
/** 导出当前画布（有选区则只导出选区）为 JPG → { path, offset } | 'no-doc' | 'error:…' */
function mm_ocr_exportImage(quality)
```

```ts
// src/core/ps/ocr-raw.ts
export function ocrExportRaw(raw: string): Result<OcrExport>;   // 只服务 CAP.ocrExport
```

```ts
// src/core/ps/ocr.ts
export function exportImage(quality: 8 | 6 | 4): Promise<Result<OcrExport>>;
```

```ts
// src/domain/ocr.ts
export function toOcrGroups(
  blocks: readonly OcrBlock[],
  offset: { left: number; top: number }
): { groups: OcrGroupSpec[] };
```

`offset` **必填不给默认值**：只有 OCR 一个调用方，给默认值等于允许漏传而不报错（`CONVENTIONS` §4.3「必填 → 可选」是放宽）。

### 5.1 解析：wire 上是文本，不是对象

jsx `return` 对象 → `callJsx` 自动 `JSON.stringify` → 解析器收到的是 **JSON 文本**（`JSX-通道与自写指南` §4）。`ocrExportRaw` 三步，顺序不能换：

```
1 unwrapRaw(raw)                         'no-doc' → PS_NO_DOC（约定值表在 raw.ts）
2 空串 → PS_BAD_PAYLOAD                  宿主没给结果，不当成 JSON 错误
3 parseJson(raw, 'OCR 导出结果', 'PS_ERROR')   唯一 JSON 入口在 types/json.ts
4 字段校验：path 是非空 string、offset.left / offset.top 是有限数字
   任一条不满足 → PS_BAD_PAYLOAD + 原文前 120 字进 detail
```

- 第 3 步的 `code` 传 `PS_ERROR`：宿主返回值解析不了，不是用户文件坏了。
- 字段校验写在本文件，**不写在薄函数里**（`JSX-通道与自写指南` §8「同一件事不许两个判据」）。
- `offset` 允许是 0，**但不允许缺字段**：缺了说明 jsx 还是旧版本，报失败比默认成 0 安全（默认 0 会把选区识别的层错位到左上角）。

### 5.2 命令层数据流（`path` 与 `offset` 同生命周期）

体积循环里 `exportImage` 可能调 1–3 次，`path` 每轮被覆盖 —— `offset` 必须跟着同进同出：

```ts
let imagePath = '';
let offset = { left: 0, top: 0 };     // 与 imagePath 一起声明、一起覆盖

for (const quality of OCR_QUALITIES) {
  const exported = await exportImage(quality);
  if (exported.status === 'error') { dropTemp(imagePath); return exported; }
  imagePath = exported.value.path;
  offset = exported.value.offset;     // ← 本轮裁出来的偏移
  /* 体积判定不变 */
}
// 之后 toOcrGroups(blocks, offset) 用的是「成功那一轮」的偏移
```

拿第一次的 `offset` 配第三次的图，就是层全部错位 —— 这类 bug 只有真机能看出来，所以写死在文档里。

## 6. 边界（写死在 jsx 一处）

1. **clamp 到画布**：`l = max(0, b[0])`、`t = max(0, b[1])`、`r = min(w, b[2])`、`bot = min(h, b[3])`。
   选区可以超出画布，`crop` 传画布外的矩形会直接抛错（PS 报「结果文档过大」一类）。
2. **零尺寸按无选区处理**：`r - l < 1 || bot - t < 1` 时整图导出、`offset` 归 0，并 `mm_log` 记一行。
   PS 里画不出零宽选区，这个分支是给异常输入兜底；报成用户可见失败反而误导。
3. **非矩形 / 羽化选区**：`crop` 只取外接矩形；JPG 无 alpha，选区外的透明区变白底（对识别影响见 §8）。
4. **`bounds` 元素取数**：做 clamp 前统一 `.as('px')` 取数字，不拿 `UnitValue` 直接比大小。

## 7. 验收

1. 拉一个框住两行字的矩形选区 → 只建这两行的层，位置与画布上肉眼一致（对比整图识别同一区域的 `left/top`）。
2. 无选区 → 与现在逐像素一致（`offset` 为 0，建层坐标不变）。
3. 选区远小于画布时，`fileSizeAt` 明显下降，不再触发 8→6→4 降质量循环。
4. `Ctrl+Z` 一次全撤（撤销组仍在 jsx 内，未动）。
5. 手工把 jsx 返回值改回裸路径（模拟旧 jsx）→ 报 `PS_BAD_PAYLOAD`，**不许**按 `offset` 0 静默建层。
6. `npm run check` 全绿；`init.test` 对账绿（`ocrExport` 的 `fn` 没变）。

## 8. 未验（不许当已验证）

1. **`bounds` 元素是 `UnitValue` 还是数字**：不同 PS 版本不一致，`.as('px')` 在纯数字上会抛。
   真机跑 `alert(app.activeDocument.selection.bounds.toSource())` 确认后再定取数写法。
2. **羽化 / 非矩形选区的白底**：crop 外接矩形后选区外是白底，百度对白底黑字的识别影响未测。
3. **`dup.crop` 在含智能对象 / 文字层的副本上**：crop 是文档级操作，理论上无差别；PS 26.7 之外的版本未测。
4. **选区恰好等于整画布**：会白跑一次 crop，预期无害（裁完尺寸不变），未实测。

## 10. 不做的

- **不做「整图识别后按选区过滤 blocks」**：不省流量、不省钱，只解决「别在选区外建层」；诉求不是这个。
- **不做选区预览 / 二次确认弹窗**：PS 里选区本身就是预览，多一步确认只是多一次点击。
- **不做「记住上次选区」**：选区归 PS 管，脚本不该有第二份状态。
