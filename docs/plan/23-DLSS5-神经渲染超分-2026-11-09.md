## 0. 六条裁定

1. **spawn 子进程全仓唯一一处**：新增 `core/cep/process.ts` 作为 `nodeRequire('child_process')` 的唯一出口（`runProcess(exe, args, { cwd, timeoutMs })` → `Result<{ code, lines }>`，超时 kill、行缓冲收集、两路输出合并）。`core/dlss/engine.ts` 只拼参数、判输出。plan 21（一键抠图）落地时 Python 的 spawn 也走这里，不许出现第二个 spawn 写法（`ADR-0001`）。
2. **jsx 只加两个函数**：`mm_dlss_exportLayer`（导出整个画幅的可见合成）与 `mm_dlss_finishResult`（结果导回）。原插件第三个函数 `dlss5_docInfo` 是为独立面板 UI 服务的，maomao v1 不需要，不迁（奥卡姆剃刀；64MP 守卫收进 `exportLayer`）。
3. **返回值用普通对象，不做 ES3 JSON 机**：原插件的 `dlss5_ok/dlss5_jstr`（ASCII 键值对 + 手写序列化）是为了绕旧宿主的坑；maomao 的 `callJsx` 外壳自动 `JSON.stringify` 返回对象，`mm_ocr_exportImage` 返回 `{path, offset}` 已在真机验证过中文路径往返。照 maomao 约定写。
4. **引擎 runtime 不搬进 maomao**：220MB 超仓库承受（同 plan 21 模型不进 git 的理由）。运行时按 §3.4 的 3 条候选探测，用户实际安装位置 `…\CEP\extensions\runtime` 被第 3 条 `<ext>/../runtime` 命中 —— 它与 `com.maomao.design` **同级**，不在原插件目录里，所以**删原插件不影响**。手动路径存 prefs 的 `'dlss.runtime'`（`PrefKey` 联合成员，**没有** `maomao.` 前缀，也不是 localStorage——`core/prefs` 是 `prefs.json`）。机器专属路径（`D:\DSHarness\…`）不进 config。
5. **撤销本轮按「不包」落地**：`finishResult` 改文档（跨文档 duplicate + translate），按 `JSX 指南 §7.5` 应包 `suspendHistory`；但它内部要 `app.open` 结果文件，suspendHistory 里开文档、跨文档复制未验（探针 P2，本轮跑不了）。原插件 `host.jsx:318` 本来就不包，所以**未跑探针即按不包执行**（撤销粒度 = PS 默认，两步 Ctrl+Z），代码注释写明「P2 未验」；要改成一条历史是另开一轮的事。

### 3.1 `src/types/dlss.ts` —— 数据形状

```ts
export type DlssSrPreset = 'default' | 'E' | 'F' | 'J' | 'K' | 'L' | 'M';

/** 不含输出尺寸的「外观」参数：内置预设用它（输出尺寸是每张图自己定的，原插件注释同） */
export interface DlssLook {
  i: number;   // intensity 强度 0–2
  d: number;   // detail 细节
  c: number;   // color 色彩
  ls: number;  // local structure 局部结构
  lt: number;  // local tone 局部影调
  sk: number;  // skin 皮肤（-1 关）
  st: 0 | 1 | 2;        // 风格：0 标准 / 1 自然 / 2 电影
  sr: DlssSrPreset;     // DLSS SR 预设
  am: 0 | 1;            // 自动蒙版
  ui: 0 | 1;            // UI 修正
}

/**
 * 一组神经渲染参数：输出尺寸**二选一，不能都不给**。
 * 写成判别联合是为了让「都不给」编译不过 —— 否则 `resultName` 会算出 `0x`。
 */
export type DlssParams = DlssLook &
  ({ sc: number; w?: never } | { w: number; sc?: never });

/**
 * 导出阶段结果（`mm_dlss_exportLayer` 的载荷）。
 * **不带 path**：路径是调用方传进去的，jsx 再返回一遍就是同一件事两个来源。
 */
export interface DlssExport {
  left: number; top: number;  // 层在文档里的区域左上角
  width: number; height: number;
  layerName: string;
}

/** 导回阶段结果（`mm_dlss_finishResult` 的载荷；size≠区域时 mode='document'） */
export interface DlssPlaced {
  mode: 'layer' | 'document';
  name: string;
  left?: number; top?: number;
  width: number; height: number;
}
```

**不另立 `DlssRunOptions`**：引擎入参就是 `DlssParams` + `{ inPath, outDir }` 两个文件字段。同一份参数两个类型 = 以后加一个参数要改两处，且两处会漂。

### 3.2 `src/domain/dlss-token.ts`（+ `dlss-token.test.ts`）—— 参数 token（纯逻辑）

`params.js` 的移植，**无 DOM / 无 CEP / 无 PS**（原文件头同款理由：token 写进图层名，解析 bug 是永久性的，必须能脱离面板单测）：

本轮**只有两个导出，只做编码**。读回（`dlssTokenOf` + 读回类型）、`dlssSameParams`（预设高亮）都归阶段 2/3 —— 现在写就是零消费者的代码。

原插件的 `TOKEN_VER` / `PRESET_KEYS` **不迁**：前者只在 `makeToken` 里用一次（内联 `[NR5 `），后者只服务 `sameParams`（本轮不做）。

**测试钉死字面量，不做「编码→解码」往返**：往返测试有个陷阱 —— 编解码两边一起写错时测试照样绿（自己跟自己一致），而 token 是要写进用户 PSD 的，错了是永久的。所以用例写成「输入一组参数 → 断言精确字符串」（照 `params.js` 的输出逐字对），再补 `fmtNum` 的边界（`1.50→1.5`、`-0→0`、非有限值→`0`）、`baseName` 去旧后缀、`sc` 与 `w` 二选一。

阶段 3 做读回时再补解码（届时按 `CONVENTIONS` §1.1：没有 token 是正常状态、不是失败，先例是 `domain/vectorize.svgCanvasSize` 返 `null`，所以叫 `dlssTokenOf` 而不是 `parse*`）。

键序、`fmtNum`（去尾零、`-0`→`0`）、最长键优先匹配、`safeName` 允许字符集（letters/digits/space/`· [ ] , . - _`）全部照抄 `params.js`，不改语义——改一个字符，旧 PSD 图层名里的 token 就读不回来。

### 3.3 `src/core/cep/process.ts` —— spawn 唯一出口（新范本）

```ts
/** 跑一个外部进程：行缓冲收集输出（两路合并），超时 kill；失败原因原样进 detail */
export function runProcess(exe: string, args: string[], options: {
  cwd?: string; timeoutMs: number;
}): Promise<Result<{ code: number | null; lines: string[] }>>;
```

- `nodeRequire('child_process')` 取模块；**失败原样透传** `nodeRequire` 的 `Result`（它已产出 `detail: node:child_process:<异常>`，`node.ts:40`）——再包一层会变成 `node:child_process:node:child_process:…`。
- 参数走**数组** spawn（不经 shell）——中文/空格路径不需要引号（原插件同款，plan 21 §6 同判）；`windowsHide: true`。
- `timeoutMs` **必填**：通用原语不带域常量（`DLSS_TIMEOUT_MS` 由 engine 传）。超时 kill 进程，`Result` 落 `TIMEOUT`，`detail: timeout:<ms>` + 已收到的 `lines` 尾部。**本模块不记日志**：同一失败只记一次（`ADR-0003`），尾部随 `Result` 上抛，由 engine 决定要不要落日志。
- **stdout / stderr 合并成一个 `lines`**：引擎本来就把两路当一份日志（原插件 `emit` 同处理），分两路等于每个调用方都要再拼一次。
- **不设 `timedOut` 字段**：超时就是 `Result` 的 `TIMEOUT`，成功臂再表达一次是同一件事两个来源。
- `code` 可能是 `null`（被 kill / 信号结束）：类型写实，别断言成 `number`。
- **有会红的检查**（`ADR-0002` 判据 5）：`process.test.ts` 用 `node -e` spawn 自己，测正常退出码、非 0、超时 kill、两路合并成 `lines`。
- 文件头带【范本】标记：全仓 spawn 只许这一处（裁定 1）。

### 3.4 `src/core/dlss/engine.ts` —— 引擎域逻辑

`DlssEngineInfo = { gpu, driver, version }` 从 `--probe-nr` 的 `gpu:` / `driver:` / `dlssnr:` 三行抓，缺行给 `—`（core 不产中文）。probe 失败码由本模块一次定死：`PS_UNREADY`（没有 `Neural Rendering RAN`），消费者不许换码（`ADR-0003`）。

`verifyEngine` 不换码，只在 `PS_UNREADY` 时把码级通用句换成本域中文（`core` 不许写中文）；`code` / `detail` 原样。页面据此走整页不可用态。

- 输出定位（`engine.js:220` `findOutput` 移植）：引擎写 `<输入名>_nr.png`，先按名找，退化按 `_nr.png$` 目录扫描。
- **临时目录归本模块**：`%TEMP%\maomao-dlss\<stamp>\`（**不用**原插件的 `dlss5ps`，避免两边互踩），输入 PNG 与输出同在 `<stamp>/`，删目录即删干净 —— 不单独删文件，也就不会漏。`commands` 不许直接 `fs`（分层），而 `core/storage` 只有删文件的 `removeFileAt`。
- `--nr-*` 名字映射只在本文件一处（`p.i → --nr-intensity` …），`DlssParams` 是唯一参数形状。**输出尺寸二选一只在这里判**：用 `sc !== undefined` 收窄判别联合（有 `sc` 走 `--nr-scale`，否则 `--nr-width`），不用 `?? 1` 兜底。`dlssResultName` 用同一个判别式算名字里的尺寸 —— 两处同判据、`0x` 不可能出现（`ADR-0004`）。**`--nr-preset` 固定传 `0`**（模型档位只有内置那一套；别把它跟 `st`（风格）混了）。
- **spawn 必须带 `cwd: runtimeDir`**（原插件 `engine.js:115/170` 都带）：引擎按 cwd 加载同目录的 `nvngx*.dll`，不设的话换个 cwd 就可能在加载阶段失败。probe 与 run 两处都要。

### 3.5 `jsx/main.jsx` —— 两个函数（契约，`mm_safe` 包、约定值前置）

> 下面引用的 `host.jsx:213` / `:292` / `:318` 只作历史出处；原插件删除后以本节描述为准。

**超分作用于整个画幅，不作用于单个图层**（2026-11-09 用户裁定）：选中哪个图层、图层空不空都与结果无关，所以不读 `activeLayer` / `layer.bounds`，也没有「恰好 1 个图层」前置与「空层」约定值。

```js
/**
 * 整个画幅的可见合成导出为 PNG →
 *   { left:0, top:0, width, height, layerName } | 'no-doc' | 'layer-too-big' | 'error:… @line n'
 * width/height 是画布尺寸；layerName 是文档名（整幅没有「单一图层」，结果名以文档名为底）。
 * 合并可见照本仓现成范本 `mm_ocr_exportImage` 的 `doc.duplicate(name, true)`
 * （第二参数 mergeLayersOnly：只留合成图，隐藏层不参与），原文档与它的图层、选区一律不动。
 * 再 duplicate 进 8-bit RGB 同尺寸临时文档：引擎只吃 8-bit PNG，跨文档复制自动转位深/模式。
 * w*h > maxPixels → 'layer-too-big'（引擎按整帧分配显存）；上限由前端传，config 是叶子模块 jsx 读不到。
 */
function mm_dlss_exportLayer(pngPath, maxPixels)

/**
 * 结果导回：结果尺寸 == 导出区域 → duplicate 进原文档并平移对齐（mode:'layer'）；
 * 尺寸变了（放大档）→ 结果文档留在桌面不关（mode:'document'）。
 *   { mode, name, left?, top?, width, height } | 'no-doc' | 'result-missing' | 'error:… @line n'
 * 'result-missing' 回**约定值**而不是 throw：throw 会被 mm_safe 折成 `error:result-missing @line n`，

 * **本轮不包 suspendHistory**（P2 未验；原插件 host.jsx:318 也不包），注释写明「P2 未验，两步 Ctrl+Z」。

```

不迁 `dlss5_docInfo`（裁定 2）；也**不新增 `inPixels` helper** —— 照 `mm_vec_exportLayer` 的写法：进函数先存 `app.preferences.rulerUnits`、设 `Units.PIXELS`、`finally` 还原，画幅宽高用 `doc.width.as("px")` / `doc.height.as("px")` 取数。

**不切单位就会出 NaN**：标尺是百分比时 `as('px')` 给 NaN，`documents.add(NaN)` 直接失败。所以这段不是「可选优化」。

### 3.6 `src/core/ps/dlss-raw.ts` —— 私有解析器（照 `ocr-raw.ts` 范本）

**单独文件**：能力表 import 它，写进 `./dlss.ts` 就是 `capabilities ↔ dlss` 运行时环（同 `text-batch-raw` / `vectorize-raw` / `ocr-raw` 的既定理由）。

```ts
export function dlssExportRaw(raw: string): Result<DlssExport>;   // unwrapRaw 约定值 → parseJsxRaw → 逐字段 accept
export function dlssPlacedRaw(raw: string): Result<DlssPlaced>;   // mode:'layer' 必带 left/top；'document' 不带
```

**新增约定值同批加 `raw.ts` 的 `RAW_FAILURES` 表**（`JSX 指南 §7.3` 硬规则，漏了会落 `PS_BAD_PAYLOAD`）。共 **2 条**：

| jsx 裸串 | 折成 | 理由 |
|---|---|---|
| `'layer-too-big'` | `PS_REJECTED` | 画幅超 64MP 的硬上限拒绝（与选中图层无关） |
| `'result-missing'` | `PS_ERROR` | 引擎没产出是故障（红），不是前提不满足 |

`detail` 只有 `raw:<裸串>`：`RAW_FAILURES` 是 `Record<string, ErrorCode>`，`unwrapRaw` 的 detail 写死成 `raw:<原文>`（`raw.ts:42`）。

**没有「空层」判据**：曾把 `'empty-layer'` 折成 `PS_WRONG_LAYER`，reason 是码级通用句「当前图层不是形状图层」—— 选中空层就弹这句，既荒谬又与整幅超分无关，已删（连同 `requireOneLayer` 前置）。`MSG.codeReason.PS_REJECTED` 也从「PS 拒绝执行，请确认已选中图层」改成中性的「PS 拒绝执行」。

## 5. 边界与失败

| 情形 | 处理 | 码 |

## 8. 未验 / 风险

1. **P1b 未验（面板上下文）**：引擎侧 P1a 已过，但「面板 CEF 里 `require('child_process')` 能不能拿到、spawn 有没有权限」还没在面板里跑过 —— 由**阶段 2 首跑**覆盖（`runDlss` 第一步就是 spawn）。`require` 本身有真机证据（矢量化从扩展目录 require vtracer），manifest 也已有 `--enable-nodejs`。P2 已按「不包」定死（裁定 5）。
2. `evalScript` 与 spawn 的交错：导出（evalScript）→ 引擎（Node）→ 导回（evalScript）三段中，PS 队列在引擎段是空闲的，用户此时在 PS 里改文档会导致 finishResult 的区域对不上——v1 接受（loading 遮罩挡面板侧，PS 侧无解，原插件同病）。
3. token 与原插件互通性：两端键序一致即可互读；以 B1 的字面量用例对齐一次。
4. 64MP 上限是原插件守卫值，未在 maomao 侧实测引擎的真实上限。

## 10. 不做的

- 不迁原插件 UI（原生 HTML/滑杆/IO 导入导出框）；maomao 页面按 `STYLE.md` 公共件重写。
- 不做批量多图层、不做进度百分比、不做引擎日志面板（v1 用 loading 最后一行）。
- 不把引擎 runtime / DLL 放进 maomao 仓库或 `dist/`。
- 不做引擎路径自动写注册表 / 装 NGX；probe 失败只报原因。
- **不做非 NVIDIA 显卡的降级放大**（PS 自带「保留细节 2.0」或第二个超分引擎）：同一能力两套实现（`ADR-0001`）。没有 RTX 就是「本功能不可用」——页面报原因、执行按钮禁用，其余功能不受影响。
- 不做 adapter/GPU 选择（固定 `--adapter` 不传，驱动自选，原插件默认同值）。
- 不依赖原插件目录：删掉 `com.dlss5.nr.ps` 后功能照常（依赖只有同级 `extensions\runtime`）。删除动作由用户执行，不在本 plan 的改动范围内。
- 不把原插件源码抄进仓库（第三方代码）：契约摘要留在本 plan（§3.2 token 形状与键序、§3.4 命令行参数、§3.5 返回形状），代码注释的出处引用写 plan 章节号，不写原插件行号 —— 插件删了那些行号就无处可查。
- 本轮不做云同步预设（plan 22 的 `script.custom` 先行，dlss 预设是否上云另议）。
