## 0. 四条裁定

1. **按钮只做一件事**：从本地配色表随机取一对，写成 PS 的**应用前景色与背景色**。不改图层、不改文字颜色、不写库文件。
2. **设色自写 jsx**（`mm_style_setAppColors`），**不调** vendor 的 `ys_setForegroundColor`：它只设前景色，且 `App_setForegrounddColor`（`jsx/vendor.jsx:6103`）在 PS ≥ 21 上会「建临时图层 → 设色 → 删图层」，多出历史步；vendor 里也没有设背景色的函数。
3. **用 `setd` 描述符**设 `Clr / FrgC`、`Clr / BckC`（应用级属性），不用 `app.foregroundColor =` 那条会牵连当前文字/形状层的赋值路径。载荷只传 **RGB 三元组**（PS 侧只按 RGB 设色）；不传 `AppColor` 的 hex + CMYK，那是 vendor 上色要的形状。
4. **不判前置**：设置应用色不依赖文档与图层；成功静默（字体面板其它动作也静默），失败走 `runCommand` 的 toast。

图标要求（给选图标的人）：单色 path（不要渐变 / 多色 / 位图）、`viewBox` 写成 `0 0 1024 1024` 或原始 24×24（我会换算）、14px 下点数与轮廓能认出来。

**图标必须是实心（fill）型**：现有 sprite 189 个 symbol 里 `stroke` 出现 0 次，`<Icon>` 根节点写死 `fill="currentColor"`。描边型图标（Lucide / Tabler 默认）如果把 `fill="none" stroke="currentColor"` 留在根元素上，`build-icons` 只取 symbol 内层内容 → 这两个属性丢失 → 渲染成一坨实心块。要么选实心图标（iconfont 的「面性」/ Phosphor 的 `fill` 权重），要么把 `fill="none" stroke="currentColor" stroke-width` 下放到每个 path 上。

## 3. 契约

```js
// jsx/main.jsx
/**
 * 设置应用前景色与背景色（不碰图层）。
 * param: '{"foreground":{"r":0-255,"g":…,"b":…},"background":{…}}'
 * 返回 'ok' | 'error:…'
 */
function mm_style_setAppColors(param)
```

```ts
// src/types/color.ts（RgbColor 从 domain/text-info 上移；core / domain / commands 共用一份）
export interface RgbColor {
  r: number;
  g: number;
  b: number;
}

export interface ColorPair {
  foreground: RgbColor;
  background: RgbColor;
}
```

```ts
// src/core/ps/capabilities.ts
/** 设置应用前景/背景色：应用级属性，不依赖文档与图层，所以不带 require */
appColors: {
  fn: 'mm_style_setAppColors', gate: 'core', channel: 'direct', timeout: WRITE_TIMEOUT,
  parse: strictVoid(MSG.coreOps.appColors)
}
```

`parse` 只能是 `strictVoid`，**不能是 `lenientVoid`**：后者认 `''` / `'0'` / `'1'`，**不认 `'ok'`**（`raw.ts:248`），jsx 返回 `'ok'` 会被判成「返回数据无法识别」。`strictVoid` 显式认 `'ok'` / `'OK'`，且把「宿主没回话」判失败——设置颜色这种「没生效本身看不出来」的写正好要这一档。

```ts
// src/core/ps/style.ts
export function setAppColors(pair: ColorPair): Promise<Result<void>>;

// src/commands/style.ts
export function applyRandomColors(): Promise<Result<void>>;

// src/features/font-panel/useFontPanel.ts
onRandomColor: () => void;

// src/features/font-panel/components/FontColor.tsx
onRandomColor: () => void;   // 必填 prop，不给默认值
```

- 新增 1 条文案：`MSG.coreOps.appColors`（如「设置前景/背景色失败」）。`fail` 里不许再写中文（`CONVENTIONS` §12）。
- 参数只走一条形状：**一对 `ColorPair`**，不拆成两个参数、不给可选字段（`JSON.stringify` 会删掉 `undefined` 键，残缺对象到 jsx 侧不报错也不生效）。

## 4. 数据流

```
FontColor（按钮 onClick）
  → useFontPanel.onRandomColor
  → commands/style.applyRandomColors        （domain/color-system.randomColorPair）
  → core/ps/style.setAppColors              （能力表 appColors）
  → core/ps/capability.callCapability       （门 → 函数存在性 → 直调 → 解析）
  → core/cep/bridge.callJsx → evalScript
  → jsx/main.jsx mm_style_setAppColors      （两次 setd：FrgC / BckC）
```

失败原样上抛：`PS_UNREADY`（jsx 没加载 / 函数缺失）、`PS_ERROR`（jsx 抛错或返回认不出）、`TIMEOUT`（60s）。页面不按码改文案。

## 5. 边界

| 情形 | 处理 |
|---|---|
| 没有打开的文档 | **不判**：应用色不依赖文档。真机确认 `setd` 在无文档时不抛；若抛，`mm_safe` 转 `error:` → `PS_ERROR`，此时再补 `'no-doc'` 约定值 |
| 参数解析失败 | jsx 侧抛 → `error:` → `PS_ERROR`（数据是前端产的，解析失败即代码 bug，不降级） |
| 连点 | `evalScript` 串行队列，天然排队，不需要额外节流 |
| 与「智能填色」联动 | 改前景色会触发 `common-use-watcher` 的 `fillColorChanged`（开关打开时），与用户在 PS 里手动改前景色同一行为。**本轮不处理**，只记事实 |

## 6. 验收（真机 5 条，缺一不算完成）

1. 选中**文字图层**点按钮：前景/背景色块变了，**文字颜色不变**，图层面板没有多出/少掉图层。
2. 选中**形状图层**点按钮：同上。
3. **没有文档**时点按钮：不弹错（或按 §5 补 `no-doc` 后给出「没有打开的文档」）。
4. 连点 5 次：每次颜色都变，面板不卡、无报错。
5. 重开面板后按钮仍可用（jsx 重新加载后能力探测通过）。

自动化侧：`npm run check` 全绿；`domain/color-system.test` 8 条；`capability.test` 会校验「能力表 ↔ `CORE_FUNCS`」与「`mm_*` 必须 `gate: 'core'`」。

## 8. 未决 / 风险

1. **`setd` 会不会改当前图层颜色**：这条决定实现形态。真机验（§6 第 1、2 条）；若真改了，退回「临时图层」方案并包 `suspendHistory` 抵消历史步——但那时要先说明为什么又抄 vendor 的写法。
2. **前景/背景的角色**：现在数据里固定「深色 → 前景、浅色 → 背景」。若真机试下来觉得反了，改 `color-system` 一处映射，不动数据。
3. **同色重复**：`randomColorPair` 可能连续给同一对（300 分之 1）。先不处理；要处理就由 `useFontPanel` 拿上一次的值比一次，不进 domain。
