## 0. 六条裁定

1. **先量后改**：本轮先实测再设计。实测否决了原「四层缓存」方案（`statFile` + mtime 判定 +
   写失效 + 同一引用契约 + `inFlight` 去重），**一行都不加**。
2. **读库不是瓶颈**：四个库 parse + 归一化合计 < 1ms（§1 实测），不缓存、不加版本判定。
3. **切页 1–2 秒的根因是 `getUserDataPath` 每次 IO 都走 CEP 同步 IPC**（渐变页一次 `load()` 问 5 次）。
   先修它；`loading` 态**暂时保留** —— 真的慢时它是唯一反馈，修完 IPC 后若 `load` < 50ms 再决定删。
4. **真正的卡顿在渲染层**：悬停整页重渲染、508 项无 `memo`、模板页无分页。
5. **不做半态**（`ADR-0001`），边界见 §5。
6. 每条改动必须能指出对应的最佳实践规则，指不出来的不做。

## 1. 实测数据（本机真实库文件，30 次取平均）

| 库 | 大小 | 组 / 项 | `JSON.parse` | parse + 归一化 |
|---|---|---|---|---|
| color | 37 KB | 108 组 / 508 项 | 0.12 ms | **0.17 ms** |
| color2 | 3 KB | 4 组 / 46 项 | 0.01 ms | 0.01 ms |
| gradient | 45 KB | 3 组 / 71 项 | 0.10 ms | 0.13 ms |
| gradient2 | 178 KB | 8 组 / 282 项 | 0.39 ms | 0.49 ms |

**结论：解析与归一化不是瓶颈（合计 <1ms）。但这份基准在 Node 里跑，没覆盖 CEP 的
`getSystemPath` 同步 IPC —— 用户体感 1–2 秒来自「每次读文件都问一次宿主路径」，不是解析。**

因此原「切页缓存」方案（`core/storage.statFile`、`json-file` 版本缓存、写失效、
`style-repo` 归一化缓存、`store` 去重、四条硬契约）**整体删除** —— 解析侧没有问题。

真正的修法是 `core/cep/bridge.getUserDataPath` 加进程内缓存（3 行）：
渐变页一次 `load()` 从 5 次 IPC 降到 1 次（首次），模板页与 DLSS 页的多次路径探测同样归零。

## 3. 不做清单

| 候选 | 为什么不 |
|---|---|
| **读路径缓存（`statFile` / mtime / 写失效 / `inFlight`）** | **实测读库 <1ms，解决的是不存在的问题**；四条硬契约纯属自找复杂度 |
| 通用缓存框架 `core/cache` | 同上 |
| 虚拟滚动 | 508 项 + 折叠 + 分页够用；会打乱长按拖拽的落点判定 |
| 去掉 `router` 的 `key={pathname}` | 页面常驻会让所有页面 DOM 与监听同时存在，内存成倍 |
| 「数据未变不 `set`」的深比较 | 比较成本可能高于收益；只做浅层引用比较，且优先级低 |
| `content-visibility` | 列表已折叠，收益不抵滚动位置与落点判定的风险 |
| `mutateRawGroups` 增量写 | 由单个 JSON 文件格式决定，改它要动用户文件布局 |

## 4. 验收

1. **切页无闪烁**：`/style` → `/gradient` → `/style` 来回 5 次，不再出现「读取中…」。
2. **悬停不整页渲染**：DevTools Performance 录样式页悬停 3 秒，不应出现整页 re-render。
3. **图片取色**：350px 宽照片从「秒级」降到 300ms 内。
4. **日志**：超过 2MB 自动轮转，诊断页打开不阻塞。
5. `npm run check` 六道关全绿。

性能类改动一律要求「验证错误写法确实变慢」：验证不了的，只能算「改了」，不算「做完」。

## 5. 半态边界（`ADR-0001`）

### 必须整批

| # | 改动 | 只做一半会怎样 | 同批边界 |
|---|---|---|---|
| 1 | 删 `loading` 态 | 只删页面那行、store 字段还在 → 下个 AI 以为该态仍有用，会再挂回去 | store 字段 + 两处 `set` + 页面订阅 + JSX，一次删净（`grep loading` 归零） |
| 2 | `ItemView` 加 `memo` | 只加 `memo`、props 仍是内联箭头 → memo 100% 失效，**伪修** | `memo` + 回调稳定化 + `useLatest` 同批，并以 DevTools 验证悬停不整页渲染 |
| 3 | `ps-events` 异常回滚 | 只改 `subscribeHostEvent`、漏 `startHostEventWait` | 两处同批 |
| 4 | `logger` 轮转 | 只加轮转、不改 `readLogText` → 大文件仍卡 | 轮转 + 只读尾部同批 |
| 5 | 订阅收窄 | 渐变页改、样式页没改 → 两种订阅写法 | 全仓一次改完，或都不改（收益小，可不做） |

### 天然不会半态（可单独做、随时收工）

- `TD-06-2` 拖拽 hook 卸载清理
- `TD-01-45` `ensureCallback` 空实现不置 true
- `TD-10-2` watcher 补 `.catch`
- `TD-11-12` `tokens.css:141` 过时注释
- `TD-01-43` / `TD-01-44` process 摘监听、logger 重复 require

### 附则

`TD-01-37`（探测失败不重试）单独改会变成「每次调用都重试」的死循环 ——
必须与「5s 节流」同批。
