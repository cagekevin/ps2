## 0. 六条裁定

1. **只做一条链**：两个颜色 → 选过渡方式 → 算出中间色标 → 写成 PS 能认的渐变 → 应用到图层 / 存进样式。
   图片取色、图片试色、分享链接、预设库、色环三联图、明度曲线、导出 PNG 全部不做（§7）。
2. **不写 jsx，不加能力表行**。应用渐变与读回渐变都已有能力（`ys_useGradient` / `ys_getGradientInfo`），
   本轮 `jsx/` 一行不动。
3. **不设第二个渐变载荷构造器**。把 `domain/image-color.createGradientItem` 的入参由「一对」放宽为「N 个色标」，
   其它调用点不动（`ADR-0005`：一个能力一个入口）。
4. **不设第二条入库通道**。存进样式复用 `repo/style-repo.addKuItem`，命令层只包一层薄函数。
5. **不开放角度 / 形状 / 反转**。普通图层走 `Style_setGradient`，它把 `Angl` / `GrdT` / `Rvrs` / `Algn`
   写死成 `0` / `Lnr ` / `false` / `true`（`jsx/vendor.jsx:6079-6083`），界面给控件就是「提示成功但没效果」。
6. **不生成渐变缩略图**。库项没有 `gradient.fileName` 时，样式页由 `domain/style-library.gradientSwatch`
   按 `location` 现拼 CSS 渐变显示（`:180`），不需要 vendor 去画 PNG。

## 1. 言语 → 语义

用户的话是验收标准，翻译成代码概念只做一次（`ADR-0003`）：

| 用户怎么说 | 代码里是什么 | 归属 |
|---|---|---|
| 「起始色 / 结束色」 | 色环上 **01 / 02** 两个点的颜色；拖点改的是 LCH 的 `h`（角度）与 `C`（半径），`L` 保持该点原值 | `domain/gradient` |
| 「直接过渡 / 短路线 / 长路线」 | `GradientRoute = 'direct' \| 'short' \| 'long'`：`direct` 在 sRGB 里直插；`short` / `long` 在 LCH(D50) 里沿色相短弧 / 长弧插值 | `domain/gradient` |
| 「算出来的中间色」 | 沿路线在 `t = i/(N-1)` 采样的 HEX 序列，含两端 | `domain/gradient` |
| 「色标精度」 | 采样点个数 `N`，**含两端**，4–32，默认 8 | 页面（夹值）+ `domain`（只保证 ≥2） |
| 「明度」 | 色轮右侧竖条控制当前端点的 **L**；色轮本身只表达 h/C，往圆心拉是「变灰」不是「变深」 | `features/gradient/components/LightnessBar.tsx` |
| 「应用到图层」 | `ys_useGradient`（已有能力，调度通道） | `core/ps/style.applyGradient` |
| 「存进样式」 | 渐变库某个分组末尾追加一项 `{ name, gradient }` | `repo/style-repo.addKuItem` |

**精度与预览的关系**（上一轮踩过的坑）：PS 只在色标之间做直线插值，所以预览必须按 `N` 渲染，
不能写死采样数——`N` 改小预览就变硬，`N=2` 时路线完全失效（只剩两端）。因此下限锁 4。

## 2. 契约

### 2.1 唯一的渐变载荷（复用，不新建）

```ts
// src/domain/image-color.ts:375 / :389 —— 形状已实测（样式页应用中）
export interface GradientPayload {
  angle: number;          // v1 恒 180（不开放）
  type: number;           // 1282306592 = charID 'Lnr '（线性）；见 §2.3
  reverse: boolean;       // v1 恒 true
  align: boolean;         // v1 恒 true
  gradient: {
    name: string;
    smoothness: number;   // 4096
    colors: GradientColorStop[];      // { type: 1433629267, location: 0..4096, midpoint, color{rgb,cmyk,hexValue} }
    transparency: { opacity: number; location: number; midpoint: number }[];
  };
}
export interface GradientLibraryItem { name: string; gradient: GradientPayload; [key: string]: unknown }
```

### 2.2 唯一改动：`createGradientItem` 的入参从「一对」到「N 个」

```ts
// 现在
export function createGradientItem(name: string, pair: [string, string]): GradientLibraryItem

// 改成
export function createGradientItem(name: string, colors: readonly string[]): GradientLibraryItem
```

- 函数体本来就按 `hexes.length` 算 `step`（`:404`），除签名外只有一处新逻辑：`colors.length < 2` 明确抛错。
- `[string, string]` 是 `readonly string[]` 的子类型，现有两个调用点（`commands/style.ts:456`、`:490`）**不用改**。
- **位置只在这里换挡**：`0..1` 的等距位置 → `0..4096` 整数由本函数一次算完，别处不再换算（`ADR-0003`）。

### 2.3 顺带修一处既有不自洽：`type` 是 charID 数字，现在是字符串

`createGradientItem` 现在写的是 `type: '1282306592'`、色标 `type: '1433629267'`（**字符串**）。
这两个数是 PS 的 4 字符 charID：

| 数字 | charID | 含义 |
|---|---|---|
| `1282306592` | `Lnr ` | 线性 |
| `1433629267` | `UsrS` | 用户色标 |
| `1097754476` | `Angl` | 角度渐变（`ys_getGradientInfo:4117` 用它判断要不要生成预览图） |
| `1148022372` | `Dmnd` | 菱形 |

两条消费路径对类型的容忍度不一样：

- **普通图层**：`ys_setGradient` → `Style_setGradient`，`type` 被忽略（`:6080` 写死 `Lnr `）⇒ 字符串也能跑。
- **形状图层**：`Shape_setFillGradient` → `putEnumerated(GrdT, obj.type)`，收的应是 charID ⇒ 传 10 位数字字符串
  **可能**被 ExtendScript 强转、也可能直接报错。`ys_getGradientInfo` 读回来的就是**数字**，所以库里两种类型并存。

落地口径：**统一写成数字字面量**（`1282306592` / `1433629267`），`GradientColorStop.type` 与
`GradientPayload.type` 的类型由 `string` 改成 `number`，读回与构造同一个口径。
形状图层是否真能吃下，列进 §8 验收第 4 条，一次真机问清。

### 2.4 新模块 `src/domain/gradient.ts`（纯函数，零 IO）

```ts
export type GradientRoute = 'direct' | 'short' | 'long';

/** 沿路线取 N 个色标（含两端），返回 #RRGGBB */
export function sampleStops(from: string, to: string, route: GradientRoute, count: number): string[];

/** 色环拖点：按「颜色 + 角度 + 半径比」反算颜色，L 保持 base 的亮度 */
export function colorAtWheel(base: string, hue: number, radiusRatio: number): string;
```

内部私有（不导出，别处不许再写一份）：

- `sRGB ↔ LCH(D50)` 正反变换；
- **色域收色用 CSS Color 4 §13.2（OKLCH local-MINDE）**，不自造策略。
  已实测：5 组端点 × 3 条路线共 15 组固定值与网站**逐点全等**（`pass=15 fail=0`）。
  第一版曾用「保 `L`/`h`、二分降 `C`」——那本身是经典 LCH 收色，但与网站不是同一套，
  高饱和过渡偏差可见（红→绿长路线中点 `#FF37E6` vs `#FF00EF`），故改成标准算法；
- 色相路径：`direct` 不走这里；`short` 取 ±180 内较短弧；`long` 反号；正对立时按端点顺序定方向（与网站一致）。

**十六进制解析必须走 `domain/image-color.hexToRgb`**（`:313` 注明是全仓唯一），本模块不许内联 `parseInt`。

### 2.5 初值不打新的 PS 能力

- 起始色 = PS 前景色：`core/ps/style.getForegroundColor()`（`:72`，能力 `mm_style_getForegroundColor`）。
- 结束色：**vendor 没有「读背景色」的函数**（`jsx/vendor.jsx` 里只有 `Layer_isBackground` 这类图层判断）。
  v1 由 `domain/gradient` 从起始色推一个大反差色（`h + 180`，`L` 与 `C` 保持），不新增能力。
  代价：想换结束色就拖 02；不为一个初值开能力表行。

## 5. 页面结构（对照 `docs/mockup/gradient-lab.html`）

面板宽 300–360（`STYLE.md` 规则 4），一张预览卡 + 一张色轮卡 + 一张设置卡 + 底部动作行：

1. **预览卡**：按 `N` 渲染整条渐变；悬停显示色值与游标，点击复制该色值；下方 `01 / 02` 两个色块 + HEX。
2. **色轮卡**：canvas 画 LCH 切片（亮度抽出去，与网站同一投影），01/02 两点可拖、点空白取最近的点。
   右边一根**竖向明度条**（与圆等高、`align-items: stretch`）：拖它只改当前端点（环上有高亮圈标出是谁）的 L，
   色相与浓度不动。条上的色阶是按该端点 h/C 现算的明度阶梯，拖到哪就得到看见的那个色。
   **为什么必须有这一维**：环是 L 切片，只有 h 与 C 两个自由度，往圆心拉得到的是同亮度的灰，
   深色渐变（L≈20–35）根本产生不出来。
3. **设置卡**：三段并排互斥（`Segment` 语义：选中 accent 实底 + 反白）+ 色标精度数字框（4–32）。
4. **动作**：`应用到图层`（没选图层时置灰）+ `保存到样式`（弹出名称 + 分组）。
5. 状态行用 `MessageBar` 一条，不另造提示。

**表面三档已定**（审查过，与仓库一致）：面板 `--mm-color-bg-base` → 卡片 `--mm-color-bg-input`
→ 凹槽/输入位 `--mm-color-bg-drawer`；间距走六档；圆角 2/4/6；控件高 26；字号 11/12/13。

色环直径取卡片可用区的**短边**（Chrome 103 没有 `min(宽,高)` 的纯 CSS 写法），由组件量一次后交 `--wheel-size` 变量
（`STYLE.md` §14.1 允许的运行时值通道）。

## 7. 失败与边界

| 情形 | 表现 |
|---|---|
| 没选图层 | 应用按钮置灰；消息行「没有选中图层」（灰字，不标红） |
| 应用成功与否 | **调度通道拿不到返回值**（`CONVENTIONS` §4.7）：`dispatchAck` 只认 `1`，失败是 PS 自己弹窗。界面只能报「已发出」，措辞与样式页一致，不假装成功 |
| 选中**形状图层** | 走 `Shape_setFillGradient`，渐变写进形状填充；payload 里的 `angle` / `type` / `reverse` 全部生效 |
| 选中**普通图层** | 走 `ys_setGradient` → `Style_setGradient`（图层样式里的渐变叠加）。**只有颜色和色标位置能写**：`angle` / `type` / `reverse` 三个参数收了不用，函数体写死 `0°` / `Lnr ` / `false`（`vendor.jsx:6079-6083`）。界面也没有这三个控件，所以看到的和拿到的是一致的 |
| 保存时没选分组 | 保存按钮置灰，不发请求 |
| 写库失败 | `toast` 报原因 + `log.warn(code, detail)`；`.bak` 由 `writeTextAtomic` 给 |
| 精度越界 | 输入即夹到 4–32，不静默接受 |

## 8. 验收

1. **单测**：同一对端点、`N=5`，三条路线的输出与网站 `color-core.js` 的实测值逐个 HEX 相等（把值写死在测试里）。
2. **单测**：灰度端点（`#000` / `#fff`）不得被染上色相（网站 `convertStop` 里专门处理过这一点）。
3. **视觉**：面板 300 / 340 两档都不出现滚动条；预览卡、色轮卡、设置卡、按钮行、状态行左边界同一条线。
4. **真机**（需要用户点，本机无 PS）：选一个**普通图层**、一个**形状图层**（纯色或渐变填充），各点一次「应用到图层」，
   确认图层出现渐变且色标数 = 当前精度。形状图层这一下同时回答 §2.3 的 `type` 数字/字符串之争。
   再点「保存到样式」，确认样式页渐变库出现该项并能反点应用。
5. `npm run check` 六道关全绿。

## 9. 未验 / 风险

- **本机没有 Photoshop**（`/Applications` 无 PS，CEP extensions 目录不存在）：真机只能交付后由用户点一次。
- `ys_useGradient` 走调度通道，**成功与失败返回值都是 `1`**，真机上「没效果」只能靠肉眼与 PS 弹窗发现（`TD-01-32` 同一问题）。
- 普通图层的**多色标位置**是否真按 `location` 生效，代码上成立（`Style_setGradient` 逐色标 `putInteger("Lctn")`），
  但仓里还没有实测记录 —— 真机验收第 4 条就是验这一条。
- **形状图层的 `type` 类型**（§2.3）：数字修正之后仍要真机点一次才算数；这条同时影响样式页「把渐变应用到形状图层」，
  不是渐变面板独有。若形状图层实测不通，v1 按「只支持普通图层」收口，界面上不提示形状图层可用。
- 色环用 LCH(D50) 切片，网站另有 8 种色彩空间；v1 只做 LCH，**不引 Culori 依赖**（63KB，引它要单独确认体积）。
  对齐靠自写 CSS Color 4 §13.2 色域映射（约 60 行），单测用网站实测的 15 组固定值钉住。
- **不对齐的部分**（刻意）：8 种色彩空间、`uniformLightness` 均匀明度、`cubic` 缓动 —— 这些开关我们不做，
  对齐了也没有用户路径能触发。
