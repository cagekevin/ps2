## 2. 换了引擎，两个公式必须搬进仓

原 py 自己算字号与段落，百度只给行级框 ⇒ 这两个公式要在仓里重算，**出处是参考脚本，逐字移植**：

| 公式 | 参考脚本位置 | 移植到 |
|---|---|---|
| 字号推断：`size = int((width/字数)*0.7 + height*0.3)`，再 `max(ceil(size/2)*2, 12)` | `:95-100` | `core/ocr/blocks.inferFontSize` |
| 段落合并：按 `top` 升序，`垂直间距 < size*1.5` 且 `|左边界差| < 20` **且两块字号相对差 < 0.3** → 并入上一块，`\r` 连接，`rect` 取并集，**字号沿用第一行**（第三个条件是原脚本没有的，见下） | `:45-75` | `core/ocr/blocks.mergeBlocks` |

差别只有框的来源：py 用四点框取 `min/max`，百度直接给 `location{left,top,width,height}`。

**所有系数在 `src/config.ts`（唯一可调参数表）**：想调排版只改那一个文件，`core` / `domain` / `commands` 都从它 import，jsx 一个常数都不写。

**加了一条原脚本没有的判据**：字号相对差 `|a−b| / max(a,b) >= 0.3` 不合并。
原脚本只判间距与左边界，结果「大标题 + 紧跟的正文」被并成一段、整段按标题字号放大
（真实接口数据：标题 42px、正文 24px，间距 34 < 42×1.5，相对差 0.43 → 现在不合并）。

## 3. 为什么必须 Node `https`（实测，不是推测）

```
$ curl -s -D - -o /dev/null -X POST https://aip.baidubce.com/rest/2.0/ocr/v1/general \
    -H "Origin: null" -H "Content-Type: application/x-www-form-urlencoded" --data "image=x"
HTTP/1.1 200 OK
Content-Type: application/json
Server: bfe
（没有任何 Access-Control-Allow-Origin）
```

对比官方的两条出口（`docs/原版/app.v4.js`）：

| 用途 | 出口 | 代码 |
|---|---|---|
| 自家 API（`zhuli.gaoding.com/api/`） | axios（XHR），POST 可用，带 `Authorization` + `X-CEP-*` | `:5295-5345`（`d`）+ `:5346-5353`（`postRequest`） |
| 第三方无 CORS（百度翻译） | JSONP（插 `<script>`，回调挂 `window`） | `:42782-42810`（`Bv`）+ `:42811-42831`（`Hv`） |

⇒ 官方打自家 API 能 POST，是因为自家服务器回 CORS 头；百度不回，JSONP 又只能 GET。
所以 OCR 的 POST 只能走 Node：新增 `core/http/node-https.ts`，**「无 CORS 第三方接口」的唯一出口**，
只回「状态码 + 正文原文」，业务错误码由 `core/ocr/baidu.ts` 自己映射。

**出口现状（改前 3 个，改后仍是 3 个，逐条只有一个实现）**：

| 出口 | 实现 | 约束（谁能用） | 调用方 |
|---|---|---|---|
| `request` | `fetch` + JSON（`core/http/client.ts`） | 服务端回 CORS 头 | 自家 API（`endpoints.ts`） |
| `postText` | `fetch` + 文本体（同文件） | 服务端回 CORS 头、只回状态码 + 正文 | 云同步 GAS 网关 |
| `nodeGet` / `nodePost`（新增） | Node `http/https`（`core/http/node-http.ts`） | **无** CORS 头 | 百度 OCR（POST）+ 百度翻译（GET，同批迁过来） |

**为什么不是 4 个**：Node 既能 GET 也能 POST，留着 `jsonpGet` 就是「无 CORS 的 GET」两种写法
（`AGENTS` §〇 的两条线）。所以同批把翻译从 JSONP 迁到 `nodeGet`、删 `core/http/jsonp.ts`。

**「收口」的口径（写死，别再漂）**：不是「全仓只留一个函数」，而是 **同一条约束只能有一个出口**。
合并成一个带 `mode` 参数的函数，等于让每个调用方多知道一件事（违反 `CONVENTIONS` §4.3）。
所以做的是：加 `node-http` 一个模块 + 在 `CONVENTIONS` §5 的网络行**逐条写明边界**，
以后新增出口必须同时改那一行。

先改 `CONVENTIONS.md` §5 的网络行，再写代码（`GOVERNANCE` §三）。

## 4. 分组：按内容空白分段（定稿）

原 jsx `screenIndex = floor(top / 1500) + 1` 的两个毛病：短图里 1500 不起作用；长图最后一组可能只剩一条。

```
按 top 升序；gap = 下一块.top − (当前组最后一块.top + 它的 height)
gap > 3 × 当前块字号  ⇒ 开新组「模块 N」
```

- `GROUP_GAP_RATIO = 3` 在 `src/config.ts`（与其它排版系数同一处）：py 的合并阈值是 1.5 倍（段内行距），分段取 2 倍余量。
- 组名仍是「模块 N」（从 1 起，按 top 顺序）。
- 至少 1 组；0 块 = `MSG.ocr.empty`，不建任何组。
- 不读文档高度、不读 1500：分组只依赖识别结果，可单测。

## 7. 入口：批量文字弹窗的「改字」页，第三个按钮

**不新增图标、不新增 tab、不新增结果面板**（2026-11-01 用户裁定）。理由：

1. **结果在画布上**：层建出来就看得见，再做一个「结果列表」是重复展示。
2. **下一步一定是改错字**：OCR 必有错字，而改字的入口就在同一屏（`全部 / 读取` 已经在）。
3. 一个功能一个入口：现有「批量文字」图标就是入口，不为一个按钮再加一个图标。

**形状**（改字页右上动作区，与另两个同形，左起）：

```
[OCR] [全部] [选中]
```

OCR 排最左：它「产出一批新层」，与右边两个「读已有层」不是同一类动作。
「读取」已改名「选中」（原名与「全部」并列时容易被读成「读取全部」）。

点「识别」：

```
导出当前画布（合并可见层）→ 百度云 OCR → domain 布局 → 按坐标建层（一次撤销）
→ 状态行：MSG.ocr.created（「已建好文字图层，可在「改字」页读取后修改」）
```

- **建完不自动读取**：层已经在画布上，读哪一批由用户点「全部」（整个文档）或「读取」（PS 里选中的）决定。
- **识别中**：按钮禁用 + 状态行「识别中…」，**不弹全屏遮罩**（弹窗已经开着）。
- **取消**只取消改字，不删层（层在画布上，`Ctrl+Z` 可撤）。

**默认 tab 改成「改字」**（原来默认「新建」）：OCR 之后几乎一定接着改字；新建是纯手输，反过来切一次成本更高。

**凭证**：设置页「OCR（百度云）」两个输入（AppID / API Key，`secret` 型）+ 保存。
没配时点「识别」由 `readCredentials` 的 `NOT_FOUND` 折成 `MSG.ocr.noCredentials` 显示在状态行，不跳页。

## 9. 替代方案：本地 RapidOCR（百度不可用时才接）

脚本已在 `docs/参考/ocr-image-to-text.py`，不用再到处找。接线三步：

1. 复制到 `ocr/`，加 `ocr/requirements.txt`（`rapidocr_onnxruntime` / `Pillow`），`tools/deploy.mjs` 目录列表加 `'ocr'`。
2. 新增 `core/ocr/rapidocr.ts`：`nodeRequire('child_process').spawn(python3|python, [脚本, 图片, JSON])`，
   读 py 海报模式输出的 JSON（已合并、已给字号）→ 直接映射 `OcrBlock[]`，**不再跑 `mergeBlocks`**。
3. `commands/ocr.ts` 把第 5 步换成 `rapidocr.recognize(imagePath, jsonPath)`，其余不动；凭证那步跳过。

`core/ocr/blocks.ts` 的两个公式此时用不上（py 自己算），但**不要删**：换回云平台还要用。

## 10. 未验（不许当已验证）

1. **百度 `general` 是否恒含 `location`**：缺了丢该行并计入 `dropped`，不猜。
2. **`1.5 × 字号` 与 `|Δleft| < 20` 在百度行框上是否仍然合适**：这是 py 在 RapidOCR 框上定的经验值。
   真机对一次；太碎/太并只改 `core/ocr/blocks` 的常数，不改结构。
3. **字数口径**：py 用 `len(content.replace(" ",""))`；百度 `words` 可能含全角空格与标点，字号会略小。
   真机对一次再决定要不要剔标点（仍只在 `blocks.ts`）。
4. **4MB 上限**：大画布 q8 可能超；降质量循环（8→6→4）要真机确认降到 4 仍可识别。
5. **token 有效期**：`expires_in` 约 30 天，内存缓存不落盘；面板重开重取一次。
6. **CMYK 导出 JPG 的颜色**：`saveAs(JPG)` 转 sRGB（与原一致），黑字清晰度真机看一眼。
7. **字体**：思源黑体（`DEFAULT_CREATE_FONT.hjm`）不一定装；设不上层照样建，会 toast `MSG.fontMissing`（与「批量文字」新建同一句）。
