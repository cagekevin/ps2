## 0. 事实表（地址与协议照抄，一字不改）

### 0.1 地址即账号

```
https://script.google.com/macros/s/AKfycbyNJHgNZMci2kIY0jfhozriJYwPkw4phoUZh7nWwW1rw3ZlJaWg282EygOEnyxyka6X/exec
```

出处 `ps/src/config/cloud.ts` 的 `CLOUD_SYNC_GAS_URL`。落到 `src/core/http/endpoints.ts` 的 `CLOUD_SYNC_URL`。

**2026-10-30 实测（代理 7897，未登录态）**：`POST {"action":"pull_data"}` → `401` + `text/html`（「网页未找到」）；
`GET` 同地址 → `302` 到 `accounts.google.com/ServiceLogin?continue=<本地址>`。
**地址不是凭证**——部署要求 Google 登录态。浏览器能下载是因为浏览器已登录，CEP 面板的 `fetch` 没有登录态，
真机同样拿到 401（`AUTH`）。要让它可用，必须把部署权限改成「任何人」，属 Google 侧操作。

### 0.2 协议（Google Apps Script 网关）

| 项 | 值 | 出处 |
|---|---|---|
| 方法 | `POST`，`Content-Type: text/plain;charset=utf-8` | `cep/cloud/transport.ts:101` |
| 请求体 | `{"action":"push_data","data":<快照>}` / `{"action":"pull_data"}` | `:96-118` |
| 响应信封 | `{status:'SUCCESS', data}`；空库 `data: null`；失败 `{status:'ERROR', error:'…'}`（HTTP 仍 200） | 云端脚本 `doPost`（2026-10-30 实测） |
| 超时 | 20s | `transport.ts` `TIMEOUT_MS` |

### 0.3 快照形状

```jsonc
{

  "schema": 1,

  "updatedAt": 1761700000000,
  "units": {

```

- 出处 `ps/src/domain/cloud.ts:36-51`。`file.path` 以 `/` 开头（相对用户目录）。
- **只放这两个 unit**。`push_data` 是整份覆盖，云端原来是什么就被这份替换 —— 这是既定行为。

### 0.4 失败码：沿用本仓 `ErrorCode`，不新增

| 参考实现 | 我们用 | 条件 |
|---|---|---|
| `CLOUD_NOT_CONFIGURED` | `VALIDATION` | 地址为空 |
| `CLOUD_NETWORK` | `NETWORK` / `TIMEOUT` | 连不上 / 5xx；20s 超时 |
| `CLOUD_PERMISSION` | `AUTH` / `FORBIDDEN` | 401 / 403 |
| `CLOUD_RATE_LIMITED` | `NETWORK` | 429，`detail` 带 `HTTP 429` |
| `CLOUD_BAD_RESPONSE` | `CORRUPT` | 解不出 JSON / 缺 `units` / `{error}` |
| `CLOUD_COLLECT_FAILED` | 原码 `IO_ERROR` / `NOT_FOUND` | 本地读不到，`detail` 带文件名 |
| 空库下载 | `NOT_FOUND` | `rev === 0`，`reason` 为「云端还没有数据」 |

### 0.5 砍掉了什么（相对参考实现）

| 参考实现 | 我们 | 理由 |
|---|---|---|
| 自动同步（防抖 60s / 最大等待 5min / 首轮 30s / 退避 1-2-5-15min） | 删 | 人工点两个按钮 |
| `pending` 落盘（后台失败痕迹） | 删 | 没有后台任务 |
| `change-sync`（repo 写成功 → 标记待同步） | 删 | 没有自动推送 |
| 按 unit 增量推送 | 删 | 整包 |
| `mergeUnits`（保留云端其它 unit） | 删 | 只同步这两类，云端不该有别的 |
| `SyncDiff` / `diffSnapshot`（三个差异列表） | 删 | 只保留「哪个 rev 更新」 |
| `preview` 命令 | 删 | 上面的比较在上传里顺手做了 |
| `clearLedger` 命令 | 删 | 想强推用 `force` |
| 5 个 unit → 2 个 | 是 | 只同步样式页与动作页 |

## 1. 范围

### 1.1 同步什么

| unit | 文件 | 内容 |
|---|---|---|
| `style.library` | `/sj_kuStoreInfo.ini` | 样式库索引（颜色 / 渐变 / 图层样式 / 字体样式的分组与条目） |
| `action.library` | `/sj_dzStoreInfo.json` + 索引里列出的每个 `/sj_dz*.json` | 动作库索引 + 每个仓库文件 |

- 全部是 JSON，`encoding: 'json'`、`inline` 直传。
- **图片不同步**（`kuStyle/*.psd|png`、`Gradient/*`）：二进制 base64 会让整包翻几十倍。

### 1.2 只有一处防御

```
拉云端 → cloudRev
if (cloudRev > 台账.rev && !force)  →  返回「云端更新，确定覆盖？」，页面弹确认
else                                →  直接 push / 直接写回
```

- 这是**唯一**的判定。没有差异列表、没有逐键合并、没有「本地有 N 项云端没有」。
- 下载不做比较：点了就覆盖本地（写前 `.bak` 是 `core/storage` 的行为，不是这里加的防御）。
- 台账不存在时按 `rev = 0` 处理：云端 rev > 0 就会提示一次「云端有数据，确定覆盖？」。
- **云端为空**（服务端 `data: null`）按 `rev = 0` 的空快照处理：上传不提示、直接传；
  下载返回 `NOT_FOUND`「云端还没有数据」，一个文件都不写。

### 1.3 不做

| 项 | 原因 |
|---|---|
| 自动 / 定时同步 | 人工点 |
| 字体相关的 4 个 unit | 本次只同步样式与动作 |
| 预览图 / PSD | 体积 |
| 并发写保护 | GAS 不做 CAS；两端同时传，后写胜（不处理） |
| 下载前差异确认 | 用户点了下载就是要覆盖 |

## 3. 底层

### 3.1 `core/http/client.ts` 加 `postText`

```ts
/**
 * 裸文本 POST：给 GAS 网关用。
 *
 * 为什么不走 `request()`：它按 `EndpointKey` 查表拼 URL、按 JSON 解析；
 * GAS 是「账号 URL + 文本体 + 可能返回 HTML 登录页」。fetch 仍然只在本文件。
 */
export function postText(url: string, body: string, options?: { timeoutMs?: number })
  : Promise<{ status: number; text: string }>;
```

- 20s 超时；`fetch` 抛错 → `NETWORK`。不在这里判云错误码。
- 不要 `response.json()`：GAS 会返回 HTML。

### 3.2 `domain/cloud.ts`（纯函数）

```ts
export interface SyncFile { path: string; size: number; content: { kind: 'inline'; data: string; encoding: 'json' } }
export interface SyncUnit { schema: number; hash: string; files: SyncFile[] }
export interface CloudSnapshot { type: 'psz_sync'; schema: 1; rev: number; updatedAt: number; units: Record<string, SyncUnit> }
export interface CloudLedger { rev: number; syncedAt: number }

export const STYLE_UNIT = 'style.library';
export const ACTION_UNIT = 'action.library';

export const EMPTY_SNAPSHOT: CloudSnapshot;                                    // 空库（data:null）→ rev 0
export function buildUnit(files: { path: string; text: string }[]): SyncUnit;  // hash = md5(按 path 排序后拼接)
export function parseGatewayData(text: string): Result<unknown>;               // 信封 → data；ERROR → CORRUPT
export function decodeSnapshot(raw: unknown): Result<CloudSnapshot>;           // 严格校验
export function decodeLedger(raw: unknown): CloudLedger | null;                // 坏值按「没同步过」
export function needsOverwrite(cloudRev: number, ledgerRev: number): boolean;  // 唯一的判定：cloudRev > ledgerRev
```

- `needsOverwrite` 是**唯一**要单测的判定：`(1,0) → true`、`(1,1) → false`、`(0,0) → false`。
- 没有 `diffSnapshot`、没有冲突分类、没有 `mergeUnits`。

### 3.3 `repo/cloud-repo.ts`

| 函数 | 行为 |
|---|---|
| `collectStyleUnit()` | `style-repo.readIndexText()` → `buildUnit`；读不到 → 原码 |
| `collectActionUnit()` | `action-repo.collectBundle()` → `buildUnit`；任一读不到就失败 |
| `applyStyleUnit(unit)` | 解析校验 → `style-repo.writeIndexRaw()` |
| `applyActionUnit(unit)` | `action-repo.applyBundle()`（全量校验 → 写仓库文件 → 最后写索引） |

**这四个函数只是壳**：文件读写与顺序在 `style-repo` / `action-repo`。
本文件**不许自己拼 `sj_*` 文件名、不许自己 `readTextAt`**。
文件名常量从两个 repo import（`STYLE_INDEX_FILE` / `ACTION_INDEX_FILE`），本文件只加协议要求的 `/` 前缀。

**台账与网络不在本文件**（2026-10-30 落地时按分层改）：
`repo` 不许 import `core/http` / `core/prefs` / `store`（`CONVENTIONS` §3 依赖方向）。

| 职责 | 落点 |
|---|---|
| 台账解码（坏值 → `null`） | `domain/cloud.decodeLedger` |
| 台账读投影 | `store/cloud.load()` |
| 台账写、读 `rev` | `commands/cloud` 的内部函数 |
| `refreshPages()` | `commands/cloud` 的内部函数（写回成功后调两个 store 的 `load()`） |

### 3.4 `store/cloud.ts`

```ts
interface CloudState {
  ledger: CloudLedger | null;
  busy: 'upload' | 'download' | null;
  load: () => void;          // 只读 prefs
}
```

### 3.5 命令（2 条）

| # | 命令 | 参数 | 行为 |
|---|---|---|---|
| 1 | `upload` | `{ force?: boolean }` | 拉云端 → `needsOverwrite(cloudRev, ledger?.rev ?? 0)` → 需要确认就返回 `needs-confirm` → 否则 push 两份 unit → 写台账 |
| 2 | `download` | 无 | 拉云端 → 校验两个 unit → 写回 → 刷新 store → 写台账 |

- **命令不弹窗**：`upload` 返回 `{ status: 'needs-confirm', cloudRev }`，页面弹 `Confirm`，确认后带 `force: true` 再调一次。
- 返回值：`Result<{ status: 'done' } | { status: 'needs-confirm'; cloudRev: number }>`；`download` 返回 `Result<void>`。

### 3.6 数据流

```
设置页 → commands/cloud → repo/cloud-repo（收集 / 写回）→ core/storage
                       ↘ core/http.postText（pull_data / push_data）
store/cloud ← prefs（台账）
```

三条规则：

1. 上传前先 pull：**只为了拿 `rev`**（不合并、不算差异）。
2. 台账只在成功后写；失败不改台账。
3. 下载写回后刷新两个 store（文件换了，页面还拿着旧投影）。

## 6. 验收

### 6.1 机器

```
npm run check
```

单测：`buildUnit` 的 hash 与文件顺序无关；`decodeSnapshot` 缺 `units` / 类型错 → `CORRUPT`；
`needsOverwrite` 三态；`applyActionUnit` 载荷缺仓库文件时报错且不写任何文件。

### 6.2 真机（6 步）

1. 设置页看到「云同步」，地址已配置（不显示完整 URL）
2. 首次上传 → 提示「云端数据更新（或首次）」→ 确认 → 成功，状态出现时间
3. 改样式页一个分组名 → 再上传 → 不提示（`cloudRev == ledger.rev`），直接成功
4. 另一台机器上传后，本机点上传 → **提示「云端数据更新」**（唯一那处防御）
5. 点下载 → 本地被覆盖，两个页面立即显示云端内容（不刷新页面）
6. 断网上传 → `NETWORK` 文案，台账不变

### 6.3 失败场景

| 场景 | 期望 |
|---|---|
| 地址为空 | `VALIDATION`，不发请求 |
| 429 | `NETWORK`（`detail: HTTP 429`） |
| 响应不是 JSON | `CORRUPT` |
| 本地索引读不到 | 原码，**不上传** |
| 下载写回失败 | 已写文件由 `.bak` 兜底，台账不变 |

## 8. 已定决策

1. 地址照抄，放 `endpoints.ts`，注释写「地址即账号」。
2. 只人工点两个按钮：无定时、无后台、无退避、无 pending。
3. 只同步 `style.library` + `action.library`；图片不同步。
4. **只有一处防御**：`cloudRev > ledgerRev` → 提示覆盖；其余一律不判。
5. 下载不做比较，点了就覆盖（`.bak` 兜底）。
6. 台账进 `core/prefs`。
7. 命令返回 `needs-confirm`，确认框在页面。
8. 入口只在设置页。
9. 失败码沿用 `ErrorCode`，零新增。
10. 云同步不碰文件：只经 `style-repo` / `action-repo` 的四个出口。
11. 收集读原文、写回整包（不 re-serialize）。
12. 下载后刷新两个 store。
