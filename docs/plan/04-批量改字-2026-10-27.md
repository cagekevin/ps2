# 04 · 批量改字（进字体面板，不占导航）

> **读者：改代码的人。** 按 `GOVERNANCE` 的分层与门禁执行；格式对齐 `01` / `02` / `03`。
> **需求来源：用户口述，原版没有这个功能。** 没有官方对照清单，只有用户定死的边界（§0.2）。
> 状态：计划。代码未开始。运行时结论一律「待真机」。

## 0. 先读这一页

### 0.1 用法（同 03）

**本文的契约已核过现状代码，默认照做。** 只有三种情况回源码 / 回真机：

| 情况 | 例子 |
|---|---|

### 0.2 用户定死的四条边界（不许扩大）

| # | 边界 | 含义 |
|---|---|---|
| 1 | **只换字，不动样式** | 只读写 `contents`；`font` / `size` / `leading` / `tracking` / `color` / `justification` 一次都不碰 |
| 2 | **只处理单一样式层** | 全层同字号那种。混合样式的层改完会被统一，用户明确"不在乎、小概率" |
| 3 | **一个纯文本大框，回车 = 一个图层** | 没有列表、没有图层名、没有样式标记 |
| 4 | **不做 run 回填 / 富文本** | 不重建 `textStyleRange`，不读区间样式 |

### 0.3 落点（用户已否决"加导航项"）

**入口 = 字体面板顶部第二行的第 4 个图标；点开是弹窗，不是嵌在页面流里的面板。**

```
字面板 › 顶部图标（第 1 行）  翻译 / 拆分文本 / 创建按钮
（第 2 行）                  复制 / 粘贴 / 方向 │ 批量改字   ← 新增，第 4 个
                                                 ↓ 点/右键
      ┌──────────────── 弹窗（遮罩铺满面板）────────────────┐
      │ 批量改字（5 个图层）                                │
      │ ┌────────────────────────────────────────────────┐ │
      │ │ textarea（55vh 高，可纵向拉）                    │ │
      │ └────────────────────────────────────────────────┘ │
      │  ← 平时这里什么都不显示，只有出错才出一行            │
      │                                        [取消] [确认] │
      └────────────────────────────────────────────────────┘

**只有两样信息**：几个图层、两个按钮。成功不报数、不弹 toast，直接关。
```

**为什么入口在字体面板**：它就是"处理文字"的地方，语义最近；导航栏是原版 11 项菜单，加第 12 项会破坏与原版的一致性（`nav-config.ts` 头注释写明"名称、快捷键、图标全部与原版一致"）。

**为什么呈现用弹窗，不用页面内面板**：

| 理由 | 说明 |
|---|---|
| 高度 | 页面内只能给 260px，弹窗能给 55vh |
| 专注 | 遮罩挡住其它内容，用户只做这一件事 |
| 不占流 | 字体面板已经很长（快选 + 属性 + 图标 + 对齐 + 层级），常驻区块会一直占着 |
| 一次性 | 读完改完就关，符合"任务"心智，不是"常驻设置区" |

**代价（必须接受，写在这里免得后面抱怨）**：

| 代价 | 说明 |
|---|---|
| 宽度仍受限于面板 | 弹窗铺满面板，但横向空间取决于用户把 CEP 窗口拉多宽；`resize: vertical` 只能拉高 |
| 必须先切到字体面板 | 不能像导航页那样从任何地方直达 |
| 顶部图标 6 → 7 | `02` 计划的数字对账要同步改（见 §6 M2） |

## 1. 范围

### 1.1 v1（做）

| 块 | 内容 |
|---|---|
| 读 | 当前文档**全部文本层**（递归进组，图层面板从上到下），一层一行 |
| 编辑 | 用户直接在 textarea 改 |
| 写 | 按行对应层，**只写改过的**；一次 `evalScript`，包成一条历史 |
| 校验 | 行数必须相等、不许空行、层内换行用 `↵` 承载 |
| 提示 | **只在有问题时显示一行**（行数不等 / 空行 / 有层没写成 / 段落文本改长可能溢出）；成功一律不显示 |

### 1.2 不做（明确排除）

| 项 | 原因 |
|---|---|
| 混合样式层保护 | 边界 2，用户不在乎 |
| run 级样式回填 | 边界 4 |
| 图层名 / 逐层勾选 / 预览 | 边界 3 |
| **粘贴多行文本** | 行数校验会直接拒绝（见 §4.2）。v1 只支持逐行改；需要"整段替换"的 v2 再开 |
| 自动扩框 | 只提示不修 |
| 只读选中层 / 过滤隐藏层 | v1 读全文档 |

### 1.3 判定口径

- `features/font-panel` 的组件只 import `commands` / `domain` 类型 / `components`，**零底层**。
- 行 ↔ 层的对应**靠读取时记下的 `layer.id`**，不靠"重新遍历第 n 个"。
- 「改过」= 字符串不等，不是"点过这个框"。

## 2. 底层

### 2.1 jsx：自有 `jsx/main.jsx`，不是 vendor

原版没有这个功能，**没有现成 jsx 可调**。照现有规范（`mm_<域>_<动作>` + `mm_safe` 包装 + 返回 `JSON.stringify`）新增两个：

```js
/**
 * 读全部文本层（递归进组，按图层面板从上到下）
 * → JSON: {
 *     layers: [{ id: string, text: string, kind: 'point'|'paragraph',
 *                locked: boolean, hidden: boolean }],
 *     skippedLocked: number, nonText: number
 *   }
 */
function mm_text_readAll()

/**
 * 批量写回（一次调用，包成一条历史）
 * ← 入参：JSON 数组 [{ id: string, text: string }]
 * → JSON: { ok: number, failed: [{ id, reason }] }
 */
function mm_text_writeAll(patchesJson)
```

实现要点（**照这个来，别自由发挥**）：

| 点 | 做法 | 为什么 |
|---|---|---|
| 递归进组 | `layer.typename === 'LayerSet'` 就递归 | 文本层常在组里 |
| 顺序 | 组内自上而下；`layers` 顺序即图层面板视觉顺序 | 与用户看到的一致 |
| id | **`String(layer.id)`** | ExtendScript 数字精度 15 位，直接传会变科学计数 |
| 只取文本 | `layer.kind === LayerKind.TEXT` | 其它层跳过，计入 `nonText` |
| 锁定层 | 读时标记；写时跳过并进 `failed` | 锁定的改不了，不能谎报成功 |
| 换行 | 层内 `\r` → `↵` 由 **domain** 做，jsx 不处理 | 见 §2.2 |
| 一条历史 | `app.activeDocument.suspendHistory('批量改字', 'mm_text_doWrite()')` | 用户 Ctrl+Z 一次全撤回 |
| 参数传递 | patches 存 `$.global.__mm_textPatches`，`mm_text_doWrite` 从全局读 | `suspendHistory` 第二个参数只能是脚本字符串 |

**通道**：`core/cep/bridge.callJsx`（现有唯一入口），不新建通道。
**超时**：写 = `WRITE_TIMEOUT`（60s），读 = 默认 30s。
**登记**：`core/ps/init.ts` 的 `VENDOR_FUNCS` **不动**（那是 vendor 表）；自有 jsx 由 `loadJsx(CORE_FILE)` 后 `probe` 检查，把 `mm_text_readAll` / `mm_text_writeAll` 加进 `probe` 的清单（照现有 `mm_layer_getState` 的做法）。

### 2.2 domain：只做转义

```ts
// domain/text-batch.ts
export interface TextLayerSnapshot {
  layers: { id: string; text: string; kind: 'point' | 'paragraph'; locked: boolean; hidden: boolean }[];
}
export interface WriteReport { ok: number; failed: { id: string; reason: string }[] }

/** 层内换行 → ↵，层与层之间 \n。保证「一行 = 一层」 */
export function encodeLayers(layers: TextLayerSnapshot['layers']): string;

/** 拆回「行 → 层」；↵ 还原为 \r。三种失败都要返回，不许静默 */
export function decodeDraft(
  draft: string,
  layerCount: number
): Result<{ lines: string[] }>;
```

`decodeDraft` 必须能报三种错：**行数与层数不等** / **有空行** / **整体为空**。

### 2.3 commands：两条

```ts
// commands/text-batch.ts
export function readAllTexts(): Promise<Result<TextLayerSnapshot>>;
/** 只传改动过的；空数组直接成功，不调 jsx */
export function writeTexts(patches: { id: string; text: string }[]): Promise<Result<WriteReport>>;
```

类型定义放 `domain/text-batch.ts`，不新增第五层。

### 2.4 页面 / 组件归属

两层：**弹窗外壳进 `components/`**（它能被别的批量编辑复用），**业务面板挂在 `features/font-panel`**。

```
components/TextAreaDialog/          新公共范本：遮罩 + 标题 + 大 textarea + 两个按钮 + 可选的一行错误
├─ index.tsx                        只管"弹窗的样子与关闭"，不知道 PS、不知道 commands
└─ text-area-dialog.css

features/font-panel/
├─ components/TextBatchPanel.tsx    业务层：读 / 改 / diff / 写回，渲染 <TextAreaDialog>
├─ useTextBatch.ts                  四个状态 + 两条命令
└─ FontPanelPage.tsx                第二行图标插入（见 §3.1）
```

**为什么不复用 `components/InputDialog`**：那个是原版 `$inputBox` 的复刻——单行输入、位置固定在
`left: calc(50vw - 90px); top: 30%`，语义是"输一个名字"。批量改字要的是**居中大窗 + 多行 + 两个按钮**，
硬套会让 `InputDialog` 长出 4 个可选 props，变成兼职。

状态只有四个：`draft` / `snapshot` / `status` / `busy`。**不建 store**：进页面读、离开即弃。

### 3.2 数据流

```
[点图标] commands.readAllTexts
   → core/ps/text-batch → callJsx('mm_text_readAll')
   → domain.encodeLayers → 打开弹窗并填入 textarea
[确认] domain.decodeDraft(draft, 层数)
   → 逐行与原文本比对，收集 patches（只留改动行）
   → commands.writeTexts(patches)
   → core/ps/text-batch → callJsx('mm_text_writeAll', [patches])
   → 成功直接关窗；失败在按钮上方显示一行原因
```

## 4. 交互与校验

### 4.1 三步

| 步 | 用户动作 | 界面表现 |
|---|---|---|
| 1 | 点顶部图标 | 图标转圈；成功后弹窗打开，textarea 已填好，标题写「5 个图层」 |
| 2 | 在 textarea 里改 | 什么都不做（不实时 diff，避免卡） |
| 3 | 点「确认」 | 先校验，再写；**成功直接关，不报数、不 toast**；失败则留在弹窗里，按钮上方出一行原因 |
| 4 | 点「取消」/ 遮罩 / Esc | 直接关，不写；已改的内容丢弃（弹窗是"一次性任务"） |

「确认写回」在 **textarea 为空** 时禁用（防止误点清空）。
弹窗**不提供"重新读取"**：点图标就是重读，关掉再点比加个按钮清楚。

### 4.2 三条硬校验

| 校验 | 结果 |
|---|---|
| 行数 ≠ 读取时的层数 | **拒绝**，按钮上方一行「行数从 5 变成 6，只能改字不能增删行」 |
| 任意一行为空 | **拒绝**，按钮上方一行「第 3 行是空的」 |
| 全部为空 | **拒绝**（按钮已禁用） |

> **代价要讲明白**：用户从别处粘贴一大段多行文字，会被行数校验直接拒绝。
> 这是"回车 = 图层"这个模型的必然结果，不是 bug。要整段替换的，v2 再单独设计。

### 4.3 溢出提示（textarea 的结构性限制）

`<textarea>` **不支持逐行着色**，所以标不了"这一行变长了"。

v1 做法：
- 写回前在**按钮上方那一行**提示：「第 3、5 行比原来长，段落文本可能溢出」
- 判定：`新字数 > 原字数 × 1.15`，且 `kind === 'paragraph'`
- 只提示，**不阻止写回**（用户自己判断）

要逐行标红就得上 `contenteditable`，v1 不做（成本远大于收益）。

### 4.4 失败与撤销

**成功是静默的，失败才说话。**

| 情况 | 界面 |
|---|---|
| 全部写成 | **直接关弹窗**，不报数、不 toast |
| 部分层没写成（锁定 / 出错） | 弹窗**不关**，按钮上方一行：「有 1 个图层被锁定，未修改」 |
| 整次失败（超时 / 脚本异常） | 同上，一行原因，允许再点「确认」重试 |
| 校验不过（行数 / 空行） | 同上，一行原因，光标不动 |

- 单层失败不影响其它层（jsx 内部逐层 try/catch）
- **撤销**：`suspendHistory` 包成一条，Ctrl+Z 一次全部回退；真机验收专门点一次

## 6. 验收

### 6.1 机器

```
npm run check   # typecheck + lint + lint:css + 范本 + 导航 + 单测
```

新增单测（`domain`）：
- `encodeLayers`：3 层 → 3 行；层内有换行 → `↵`
- `decodeDraft`：行数不等 → 失败；空行 → 失败；`↵` 往返还原成 `\r`

### 6.2 真机（6 步，全部待验）

1. 文档里有 3 个文本层 → 点图标 → 弹窗打开，3 行，内容与图层一致
2. 只改第 2 行 → 确认 → **只有第 2 层变**，第 1、3 层不动
3. 改完看字号/字体/颜色/行距：**一处都没变**（截图对比）
4. 手动加一行 → 确认 → 被拒绝，提示行数从 3 变 4
5. 某层内有换行 → 显示 `↵` → 不改它直接确认 → 换行仍在
6. 改 2 层后按一次 Ctrl+Z → **两层同时回退**（一条历史）

## 7. 风险

| 风险 | 影响 | 处理 |
|---|---|---|
| `suspendHistory` 的脚本字符串参数与全局变量在严格模式下冲突 | 历史不合并，Ctrl+Z 要按多次 | M0 先在真机试；不行就退成「每次写前存快照」，并在 UI 说明撤销粒度 |
| 弹窗宽度仍受面板宽度限制 | 长文案横向挤压，用户抱怨"太窄" | 弹窗铺满面板（`calc(100% - 32px)`）+ textarea `55vh` 可纵向拉；真要宽就升级成独立页（那时再加导航项） |
| 弹窗与 `IconPanelGroup` 的互斥无关 | 弹窗打开时再点别的图标，面板会开在弹窗后面 | `TextAreaDialog` 自带遮罩（`--mm-z-input-box`），点击穿透被挡住；**关闭前不允许操作页面** |
| 图层组递归顺序错（先子后组） | 读取顺序与图层面板不一致，用户对不上 | M0 单测不覆盖（jsx 跑不在 node），**真机第 1 步专门核对顺序** |
| 锁定层 / 隐藏层 | 改不了或改了看不见 | 锁定层跳过；**只有出现跳过才提示一行**（平时不显示统计）；隐藏层照读照改 |
| 字体缺失的层 | 改字不受影响（不碰 font），但用户可能误以为会修好 | 界面不提字体；字体问题归字体面板 |
| 用户粘贴多行文本 | 被行数校验拒绝，可能觉得"不好用" | §4.2 已写明这是模型代价；v2 再设计"整段替换" |

## 8. 已定决策（不再询问）

1. **入口放字体面板**，不占导航（用户 2026-10-27 明确否决第 12 项）；**呈现用弹窗**，不用页面内面板。
2. **只换字不动样式**；混合样式层不保护。
3. **一个 textarea，回车 = 一层**；不要图层名、不要列表。
   **界面只留「几个图层 + 取消/确认」，成功不报数、不出状态行**（用户 2026-10-27：成功/跳过这些都没用）。
4. **读全文档文本层**，不做"仅选中"开关。
5. **行数必须相等**；粘贴多行会被拒绝。
6. 读写在 `jsx/main.jsx`（自有），不加 vendor 函数。
7. 组件挂 `features/font-panel`，不建独立 feature。
