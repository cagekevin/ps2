## 1. 两个场景（决定后面所有契约）

| | 场景一 新建 | 场景二 改字 |
|---|---|---|
| 数据源 | 无，纯用户输入 | 文档里的既有图层 |
| 生命周期 | 草稿，关掉即弃 | 文档镜像，重开要能重读 |
| 失败后果 | 少建几层，重试即可 | 文字写错图层，不可逆 |
| 提交 | 建 N 层，按默认排版排好 | 只写有改动的层，位置样式不动 |

两者共用入口与弹窗，**数据不共享**（切 tab 不传值）。这是上一版 mockup 最大的 bug：两个模式接成一根管子，切 tab 丢字、切回来行数对不上。

## 2. 数据流契约（核心）

### 2.1 读：两个按钮，一次快照

| 按钮 | 集合 | 说明 |
|---|---|---|
| 全部 | 文档里所有文字层（递归进组，图层面板从上到下） | 不带任何筛选 |
| 读取 | **点击那一刻** PS 选中集合里的文字层 | 非文字层在 jsx 里直接过滤，**不提示、不计数**；没选中就是空表 |

- 读是一次性快照：读完列表不动，**再点按钮才是下一次读**（重读直接替换，不弹确认）。
- 智能对象内部的文字层读不到（PS 不允许脚本进入），这类层不出现在列表里，也不提示。

### 2.2 jsx 返回形状

```jsonc
// mm_text_readAll(scope)   scope: 'all' | 'selection'
{
  "layers": [
    { "id": "1234", "name": "图层 12", "text": "第一行\r第二行",
      "kind": "point" | "paragraph", "locked": false }
  ]
}
```

| 字段 | 规矩 |
|---|---|
| `id` | **`String(layer.id)`**。ExtendScript 数字精度 15 位，裸传会变科学计数 |
| `text` | PS 的层内换行是 `\r`，原样交出，转义在 domain 做 |
| `name` | 只用于界面显示（哪一层），**不参与身份**（实测有 4 个同名层） |
| 顺序 | 组内自上而下，即图层面板的视觉顺序 |
| 空表 | `{"layers":[]}`，不报错 |

**返回怎么回来**（`docs/JSX-通道与自写指南.md` §4）：jsx 里**直接 `return` 对象**，`callJsx` 外层会 `JSON.stringify` —— 不要手动 stringify，也不要在 jsx 里 try/catch 兜错（外层已经兜了；`mm_safe` 只负责写 `%TEMP%\maomao-jsx.log`）。

### 2.3 转义：一行 = 一层

```
层内换行 \r  →  ⏎  (U+23CE)
层与层之间    →  \n
```

`domain/text-batch.encodeLayers()` 正向、`decodeDraft()` 反向。码点写死 `\u23CE`，不要用 `↵`（U+21B5）——两者字形接近，混用会出现「看着一样但比对不上」。

### 2.4 写（改字）

```jsonc
// mm_text_writeAll(patchesJson)   一次调用，一条历史
[{ "id": "1234", "text": "改过的第一行" }]
```

**入参到 jsx 侧是字符串**：`toJsxArg`（`bridge.ts:119`）把数组 `JSON.stringify` 后用单引号包，jsx 第一行 `JSON.parse(patchesJson)`；`undefined` 会被 `callJsx` 直接拒绝，空值给 `''` 或 `[]`。

- **只传改动过的层**：`text` 与读取值逐字比对，相等就不传；空数组直接成功，不调 jsx。
- 行数 ≠ 层数 → **前端拦下，不调 jsx**（逐行对应断了，不知道该写到哪一层）。
- 层在 PS 侧被删 / 被锁 → 该层进 `skipped`，其余照写；**只有出现 skipped 才在界面说一句**。
- 撤销：`suspendHistory('批量文字', 'mm_text_doWrite()')` 包一条；参数存 `$.global.__mm_textPatches`（`suspendHistory` 第二参只能是脚本字符串）。

### 2.5 写（新建）

```jsonc
// mm_text_createAll(configJson)
{
  "lines": ["第一行", "第二行"],
  "font": { "hjm": "SourceHanSansCN-Regular",
            "mz":  "Source Han Sans CN Regular",
            "zz":  "Regular" },
  "baseSize": 92,        // 层级字号第 1 档，从字体面板设置读
  "ratio": 0.5,          // 首末比，代码里一个常量
  "align": 0             // 段落对齐：0 左 / 1 中 / 2 右
}
```

- 入参同样是**字符串**：jsx 第一行 `JSON.parse(configJson)`。
- 排版方案见 §4，**全部在 jsx 里算**，前端不传每层字号。
- 一条历史、一次 `evalScript`。
- 字体缺失（`zt_setFontName` 返回 `{err:1}`）→ 该层保留 PS 默认字体，**不阻断建层**，界面说一句。

### 2.6 失败语义（只在这些时候说话）

| 情况 | 表现 |
|---|---|
| 无文档 / 读失败 | 弹窗底部一行（弹窗是「点图标先开、再点全部/读取」，所以失败发生在窗内，不关窗） |
| 行数 ≠ 层数 | 弹窗底部一行红字，确认禁用 |
| 没有改动 | 确认禁用（不解释） |
| 部分层没写成（锁定 / 已删除） | 弹窗不关，底部一行：「N 个图层未写入（已锁定或已删除）」 |
| 全部写成 | **直接关窗，不报数、不 toast** |

非文字层跳过、隐藏层、智能对象——**一律不显示**。

### 3.1 能力表怎么写（三个函数同一套，照 `JSX-通道与自写指南` §7）

```ts
// core/ps/capabilities.ts —— 三行，字段照邻居抄。
// `layersOf` 写在 core/ps/text-batch.ts（本域私有解析器），**不进 raw.ts**：
// raw.ts 只放「≥2 个能力会用」或纯结构工具，单消费者就近放（指南 §8）。
textReadAll:  { fn: 'mm_text_readAll',   gate: 'core', channel: 'direct', timeout: READ_TIMEOUT,
                parse: strictPayload({ accept: layersOf }) },
textWriteAll: { fn: 'mm_text_writeAll',  gate: 'core', channel: 'direct', timeout: WRITE_TIMEOUT,
                parse: lenientVoid(MSG.textBatch.writeFailed) },
textCreateAll:{ fn: 'mm_text_createAll', gate: 'core', channel: 'direct', timeout: WRITE_TIMEOUT,
                parse: lenientVoid(MSG.textBatch.createFailed) }
```

七条硬约束（写错就是「门是绿的、调用直接 `EvalScript error.`」）：

| # | 约束 |
|---|---|
| 1 | `gate: 'core'` **只能配 `channel: 'direct'`** —— 类型挡住 dispatch，别想借调度器拿历史组 |
| 2 | 自写函数的撤销组**必须在 jsx 里自己包** `suspendHistory`，`core/ps` 的 TS 侧不许写 |
| 3 | 三个名字必须同时进 `core/ps/init.ts` 的 `CORE_FUNCS`；**不进 `CORE_REQUIRED`**（缺了只禁这三个能力，不牵连整门） |
| 4 | 漏登记不会静默：`funcMissing` 查不到名字 ⇒ 门绿但调用落 `EvalScript error.`，排查方向会跑偏（指南 §9 第 3 条） |
| 5 | 前置用约定值 `'no-doc'`（已在 `raw.ts` 的 `RAW_FAILURES` 里），**不新增约定值**；新增必须同时加进那张表 |
| 6 | 返回结构实测前用 `passthrough`，实测后换成具名解析器；字段校验只写在 `accept` 里，薄函数不再判一次 |
| 7 | `init.test.ts` 的对账会自动兜住 3；跑 `npm run check` 即可 |
| 8 | 这三个**进表**是对的：判据是「它是不是对外动作」——用户点图标直接触发 ⇒ 是。域内被别的函数消费的查询才退 `callDirect`（指南 §7.8 判据二），别把 `mm_text_readAll` 也退出去，那会让 `text-batch` 反向依赖表 |
| 9 | 机器闸：`check:jsx` 扫 `core/ps/*.ts` 里**以字面量名**调 `callJsx` / `callDirect` 的地方，名字不在白名单就红；`check:cycles` 卡运行时环（类型环只报不拦）；`capability.test` 断言 `mm_` 前缀必须 `gate: 'core'` |

## 4. 新建的默认排版（一套，不给用户选项）

| 项 | 取值 |
|---|---|
| 字号 | 首行 = 层级第 1 档 `ztHierarych[0]`（默认 92），末行 = 首行 × 0.5，中间等比：`r = 0.5 ^ (1/(N-1))`，第 i 行 = 首行 × `r^(i-1)` |
| 落差 | 首末比 2:1，**只有一个常量 0.5**（要更平改 0.6、更陡改 0.4），不再引第二套层级表 |
| 顺序 | 第 1 行在最上，向下堆叠 |
| 对齐 | 段落对齐「左」，`zt_setTextAlignment(0)`，每层一次；与官方默认 `align=0` 一致 |
| 间隔 | 自动，按上一行字号算 |
| 字体 | 思源黑体 CN / Regular，`zt_setFontName('SourceHanSansCN-Regular', 'Source Han Sans CN Regular', 'Regular')` |
| 落点 | **不算绝对坐标**：第一层不设 `position`，用 PS 新建文字层的默认位置（用户实测：拖入图片就落在视图正中，新建文字同理）；后面每层相对上一层按 `上一行字号 × 1.6` 往下排，横向沿用第一层的 x（左边缘对齐）。这样不用去猜「视图中心」怎么算，也不多引一条 vendor 对齐能力 |
| 历史 | 一次确认 = 一步 `suspendHistory` |

**任意行数都成立**：3 行 → 92 / 65 / 46；6 行 → 92 / 80 / 70 / 61 / 53 / 46；20 行 → 92 平缓降到 46（每级 -3.6%）。

**依据**：官方 `zt_smartTypesetting`（`app.v4.js:39921`，参数 `{ sence, type, align, fontSize, interval, spacing, scale }`）的 `type`（常规 / 强烈 / 接近 / 相同）就是落差强度控制；上表相当于「接近」档。官方那张固定层级表（92/48/36/24/15/12）落差 7.7 倍太陡，且超过 6 行没有第 7 档。

**实现顺序**：先 `npm run probe:ps` 探 `zt_smartTypesetting` 在不在 vendor 里——在就直接调它、参数照上表；探不到再按公式自己算（行距 = 上一行字号 × 0.4）。

## 6. 验收

### 6.1 机器

```
npm run check     # typecheck + lint + lint:css + check:templates + check:nav
                  # + check:jsx + test，末尾 scripts/post-check.mjs
```

`check:jsx` 是本功能最可能踩的一道：它扫 `core/ps/*.ts` 里**以字面量名**调 `callJsx` / `callDirect` 的地方，名字不在白名单就红。

**环没有闸**：`check:cycles` 与 `dependency-cruiser` 都已卸载（`ADR-0007` 改成人工判据），所以环只能靠结构保证 ——
解析器单独放 `text-batch-raw.ts`（它只依赖 `types` 与 `raw.ts`），`capabilities` 引它、`text-batch` 引 `capabilities`，
两条边方向相反但不闭合。**不许把解析器挪回 `text-batch.ts`**，那一步就会成环。

新增单测（`domain`）：

- `encodeLayers`：3 层 → 3 行；层内 `\r` → `⏎`
- `decodeDraft`：行数不等 → 失败；`⏎` 往返还原成 `\r`
- `buildPatches`：只留改动行；全等 → 空数组
- `planCreate`：N=3 / 6 / 20 的首行、末行、单调性

### 6.2 真机（8 步，全部待验）

1. 文档有 3 个文字层 → 点图标 → 「全部」→ 3 行，内容与图层一致
2. 在 PS 里选 2 层 → 点「读取」→ 只有 2 行，且顺序与图层顺序一致
3. 选中里夹一个形状层 → 列表里没有它，**也没有任何提示**
4. 只改第 2 行 → 确认 → 只有第 2 层变，字号 / 字体 / 颜色 / 行距一处没变（截图对比）
5. 某层内有换行 → 显示 `⏎` → 不改它直接确认 → 换行仍在
6. 手动加一行 → 确认 → 被拒，红字「行数 3 → 4」
7. 新建 3 行 → 确认 → 3 层，字号 92 / 65 / 46，左对齐，思源黑体，整组在视图中心
8. 改 2 层后按一次 Ctrl+Z → 两层同时回退；新建同理一次全撤

## 7. 风险

| 风险 | 影响 | 处理 |
|---|---|---|
| `suspendHistory` 的脚本字符串 + 全局变量在严格模式冲突 | 撤销粒度变成一层一次 | M0 先真机试；不行退成「每次写前存快照」并在界面说明撤销粒度 |
| `zt_smartTypesetting` 不存在于 vendor | 排版走自算分支 | M0 先 `probe:ps`；自算分支的单测已覆盖 |
| 排版走官方（vendor `dispatch`）而建层是 core `direct` 自包 `suspendHistory` | 一次「新建」会被拆成两条历史，Ctrl+Z 要按两次 | 二选一：要么排版也自己算（一条历史、一个函数），要么建层后另起一条明确的「排版」调用并在界面说明。**不许两条撤销语义并存** |
| 官方有现成排版函数却又自己写一套 | 同一能力两个实现，下一个人必抄错（指南 §7.1） | 探针能探到就只调官方；探不到才自算，且把「为什么自算」写进 §9 |
| 图层组递归顺序错（先子后组） | 列表顺序与图层面板不一致 | jsx 单测跑不了，真机第 1 步专门核对顺序 |
| 弹窗宽度受面板宽度限制 | 长文案横向挤压 | 弹窗铺满面板；原文列省略号 + title 悬停看全文 |
| 用户粘贴整段多行文本 | 行数校验直接拒绝 | 这是「一行 = 一层」的模型代价，不是 bug；要整段替换另开 v2 |
| 智能对象内文字读不到 | 用户以为漏层 | 不提示（用户要求）；文档里写明这是 PS 限制 |
| 锁定层 / 已删除层 | 写不进去 | 进 `skipped`，界面说一句，不谎报成功 |

## 8. 已定决策（不再询问）

1. **落点 = 替换「调整文本方向」**，不新增第 4 个图标，不占导航；图标与同排完全一致，无高亮。
2. **两个 tab：新建 / 改字**，数据不共享，切 tab 不传值。
3. **改字只有两个按钮：全部 / 读取**；选择动作发生在 PS 里，面板不再给「全部 / 选中 / 当前」三档。
4. **留空 = 不改**；行数必须等于读到的层数；没有改动时确认禁用。
5. **非文字层静默过滤**，不显示跳过统计；只有真会写错层时才报。
6. **新建默认排版只有一套**（§4），不给用户选项；用户不满意自己调。
7. **只换字不动样式**：改字模式只读写 `contents`，字体 / 字号 / 颜色 / 行距一次都不碰。
8. **jsx 写在 `jsx/main.jsx`**（自有），不加 vendor 函数；批量在 jsx 内循环，一次 `evalScript`。
