## 0. 这一页的核心不是 UI，是两条契约

1. **表达式标记**：`%n` / `%nn` / `%%n` / `%%nn` / `%n=` / `###` —— 我们只负责「删旧标记 + 拼新标记」，
   **求值在 PS 侧**（`cmm_batchName`）。猜错一个字符就是整批图层改错名。
2. **`.cmm` 预设文件**：`JSON.stringify(preset)`，就一种格式。
   原版还有个 `<z>` / `<>` 分隔的旧格式——**不兼容**：我们没有那个年代的旧文件，为一个不存在的输入写解析器是白花钱。

## 1. 范围

### 1.1 v1

- 模式：**默认**（一条表达式）/ **替换**（原文 `=>` 新文本）
- 表达式：点输入框或右侧图标弹出 6 个标记，选中即拼进输入框
- 执行：回车或「应用」→ 批量重命名（`cmm_batchName`），成功/失败都写历史
- 预设：分组的折叠 / 新建 / 改名 / 删除 / 拖动排序；组内预设的新增 / 修改 / 删除 / 拖动排序；点预设填进输入框
- 图层颜色标记：7 色 + 清除（`cmm_setLayerColor`）
- 预设导入导出：`.cmm`（只有 JSON 一种格式）
- 空态 / 读取失败 / 写盘失败
- **Ctrl+点击分组**：原版 `showGroupMenu` 里有这个分支（Ctrl 多选 → 「批量添加重命名组」），
  v1 只提示「自由面板未上线」，不写文件（与字体面板同一句文案、同一策略）

### 1.2 不做

| 项 | 原因 |
|---|---|
| 表达式求值（`%n` 怎么变数字、是否补零、`###` 拼哪儿） | 在 PS 侧 jsxbin 里，我们只能「只发不读」；猜错就是改名改错 |
| 云端同步（`syncRenameFileToServe`） | 协议未定，与 `03`/`05` 的云端项同状态 |
| 埋点（`cmm_002` / `重命名图层页_*`） | 本仓没有 tracker |
| 自由面板**写入**（Ctrl+多选批量加入） | 面板未落地；v1 只提示（见 §1.1 最后一条） |
| 全局菜单态 `$menu.getStatus()` | 用 `useDismiss` + `ContextMenu` 即可 |
| 页面级组件测试（参考实现有 8 条 `pages/rename.test.ts`） | 本仓没有页面测试设施，测试只覆盖 `domain`/`repo`/`core` |

### 1.3 判定口径

- 「预设」= 一条表达式字符串（如 `%n背景`）；「分组」= 放预设的数组项；**第 0 组是「最近使用」，由程序写**。
- 「保存」= 写 `sj_cmmRename.ini`（预设仓库）；执行重命名**不改**这个文件，只往第 0 组插历史。
- 「导入」= 把 `.cmm` 的内容**整体替换**预设（不是追加）——参考实现就是这么做的。

### 3.2 `domain/rename.ts`（纯函数，零 IO）

```ts
export interface RenameGroup { name: string; show: boolean; list: string[] }
export type RenamePreset = RenameGroup[];
export type RenameMark = '%n' | '%nn' | '%%n' | '%%nn' | '%n=' | '###';

export const RENAME_MARKS: ReadonlyArray<{ mark: RenameMark; text: string }>;
export const RENAME_LAYER_COLORS = 7;          // 色板数据，见 §4.4

export function clearMarks(text: string): string;
export function insertMark(current: string, mark: RenameMark): string;
export function checkExpression(text: string): string;      // 空串 = 通过，否则提示文案
export function buildReplaceExpression(replace: string, newtext: string): Result<string>;  // 见下

export function isGroupEditable(index: number, length: number): boolean;  // index >= 1 && < length
export function toggleGroupAt(preset, index): RenamePreset;
export function addGroupAt(preset, name, afterIndex?): RenamePreset;
export function renameGroupAt(preset, index, name): RenamePreset;
export function deleteGroupAt(preset, index): RenamePreset;
export function addItemAt(preset, groupIndex, text): RenamePreset;
export function changeItemAt(preset, groupIndex, itemIndex, text): RenamePreset;
export function deleteItemAt(preset, groupIndex, itemIndex): RenamePreset;
export function pushHistory(preset, expression): RenamePreset;            // 去重 + 插最前 + slice(0,8)

export function parsePreset(text: string): Result<RenamePreset>;          // JSON → 校验（无旧格式分支）
export function serializePreset(preset: RenamePreset): string;            // JSON.stringify
export function seedPreset(): RenamePreset;                               // 最近使用 5 + 序列 4
export function decodeRenamePreset(raw: unknown): Result<RenamePreset>;   // 文件边界
```

**四条硬规则**（写进单测）：

1. **第 0 组不可改名 / 删除 / 加项**：`isGroupEditable(index, length)` 一处判，模型层守，不靠 UI 隐藏。
2. **删标记必须按 `%%nn → %%n → %nn → %n= → %n` 顺序**，且**全删**（用 `split().join('')`，不是只删第一处）。
3. **导入只替换不追加**；结构不对就 `CORRUPT`，**不许像原版那样直接赋值**（原版坏文件会白屏）。
   只有 JSON 一条路，读不出来就是坏文件，不再猜别的格式。
4. **替换表达式两侧必 trim**：`a => b` 与 `a=>b` 等价；任一侧 trim 后为空 → `VALIDATION`
   （清单 §二 要求「解析必须处理 `=>` 两侧空白」）。

### 3.7 数据流

```
页面 → commands/rename → repo/rename-repo → repo/json-file → core/storage
                     ↘ core/ps/rename（cmm_batchName / cmm_setLayerColor）
store/rename ← repo（只读投影）
```

四条硬规则：

1. `batchName` 的**先写历史再执行**（参考实现 `commands/rename.ts:48-50`）：失败也留历史，与原版一致。
2. 预设类命令成功后 `store.load()`；页面不做乐观更新。
3. `.cmm` 导入是「先解析 → 校验 → 再整体替换」，任何一步失败都不写文件。
4. 导出与导入都只有一种格式（`JSON.stringify` / `JSON.parse`），没有历史包袱。

### 3.8 契约总表

**形状（5 个）**：`RenameGroup` / `RenamePreset` / `RenameMark` / `Result<T>`（外部）/
以及 store 投影（§3.4 那 4 个字段）。**不存在第三种形状**：`.cmm` 解析出来就是 `RenamePreset`，
预览里的「模式」「颜色区展开」是 **prefs 的两个布尔**，不进数据形状。

**prefs 契约**（只读 `core/prefs`，不写官方 `sj_*.json`）：

| 键 | 值 | 缺省 |
|---|---|---|
| `rename.mode` | `0` 默认 / `1` 替换 | `0` |
| `rename.showColorSign` | `boolean` | `false` |

**错误码**：
| 码 | 触发 |
|---|---|
| `CORRUPT` | `sj_cmmRename.ini` 结构坏；`.cmm` 不是合法预设 |
| `IO_ERROR` | 写预设 / 写 `.cmm` / 选路径失败 |
| `VALIDATION` | 空表达式、空组名、空预设文本、第 0 组被改、下标越界 |
| `PS_UNREADY` / `PS_REJECTED` / `PS_ERROR` | 沿用 `core/ps` 既有语义 |

**重读**：预设类与 `batchName` → `store.load()`；`setLayerColor` 不重读（只改 PS 画面）。

**未定项**：`cmm_batchName` / `cmm_setLayerColor` 返回结构（只发不读）、表达式求值语义、通道是否该走调度（§3.1）。

### 4.5 通用下拉（原版 `dropDown` / `gm`）怎么替代

清单 §一 说本页 2 个组件：`Rename` + `dropDown`（通用下拉，`props.text` 驱动、单选/多选、右越界处理）。
`dropDown` 有 9 条 class，其中一条是**固定定位的加号**（`right:20; bottom:42; 18×32; #006fff`）。
逐条替代：

| 原版 dropDown 能力 | 我们用什么 |
|---|---|
| 弹层壳（`position:fixed`、168 宽、`rgba(64,64,64,.95)`、`.5px` 边框、阴影、圆角 4） | **`ContextMenu`**（已有壳，深色 + 阴影） |
| 菜单项（`context` 行：5px 10px、`#ddd` 底、黑字） | `ContextMenu` 的 `label` / `onSelect` |
| 首/次图标（`firstsvg` / `secondSvg`，9/14px） | `ContextMenu` 目前无图标位：**v1 不加图标**（只有文字），登记 B-11 |
| 删除图标（`therrSvg`） | 用菜单项文字「删除」 |
| 「加号」浮标（`add-wrap`，右下 18×32 `#006fff`） | **不做浮标**：加分组/加预设用底栏按钮与组内「+」按钮 |
| 单选 / 多选、`props.text` 驱动 | 一处是「表达式标记」单选菜单（`ContextMenu`）；一处是「过滤子图层」勾选（`ContextMenu` 里放 `CheckBox`，单选项） |
| 右越界处理 | `useFloatingPosition` 已内置翻转/夹取（`ContextMenu` 内部用） |

**判定**：`dropDown` 是通用件，但本页只用它两次；`ContextMenu` 已覆盖壳与定位，
所以**不为本页新造下拉**。代价是菜单项暂时没图标（B-11），等有第二个页面也需要图标时再给 `ContextMenu` 加。

**手势**：左键 = 折叠 / 填表达式 / 执行；右键 = 组与预设项的菜单；

**过滤开关的联动**（清单 §二 第 3 条）：`isFilter = 选中项数 == 1` —— 下拉里只勾一项时过滤开关才显示（原版如此）。
我们只有「过滤子图层」一个勾选项，所以恒为真 → 开关**常显**，但在代码里保留这条判据以免以后加第二项时忘掉。

**拖拽两处**：分组排序（轴 y）、组内预设排序（轴 x，含跨组）。落点统一 `domain/reorder.applyListDrop`。

### 7.2 真机（10 步）

1. 进 `/rename`：出现「最近使用」「序列」两组，序列展开
2. 点「%n」预设 → 输入框变成 `%n`
3. 再点「%%n」→ 输入框只剩 `%%n`（旧标记被删干净）
4. 输入 `%n背景` 回车 → 当前图层的子图层按序改名

7. 点色块 → 图层显示对应颜色；点清除 → 颜色消失
8. 新建分组 / 改名 / 删除；拖拽分组与预设 → 重进保持
9. 导出 `.cmm` → 再导入 → 预设回来
10. 拿一个坏 `.cmm`（不是 JSON）导入 → 报 `CORRUPT`，预设不变

## 8. 风险

| 风险 | 处理 |
|---|---|
| 表达式求值猜错（`%n` 是否补零 / `###` 位置） | **我们不求值**，只拼串；真机验证一轮 |
| `cmm_batchName` 直调失败（官方派发表走 `jsxHistory`） | 改一行走 `runVendor`；已标 UNVERIFIED |

| 面板宽度导致 7 色块换行 | 色块固定 24 + `flex-wrap`；比原版 `vw` 计算更稳 |

## 9. 已定决策

1. 求值交给 PS，我们只拼串。
2. 第 0 组不可改 / 删 / 加项，模型层守。
3. `.cmm` 后缀与文件名照抄（`sj_cmmRename.ini` / `重命名.cmm`）。
4. 导入整体替换、先校验。
5. 底栏 / 折叠 / 输入 / 勾选 / 弹窗 / 右键 / 空态 / 拖拽全部复用公共件，**不新建**。
6. 37 高模式条是页面私有组件，不做公共件。
7. 色板 7 色进常量，不进主题 token。
8. 埋点与云同步不做。
9. 只发不读两个 jsx 的返回值。
10. 加页头「重命名」（与其他页一致）。
