# 选中图层前置操作清单（2026-11-01）

> 是什么：所有「先选中特定图层才能执行、否则弹『未选中/选错图层』提示」的操作的唯一点名清单。
> 唯一入口：`core/ps/capabilities.ts` 的 `require` 字段（执行器第一步判定，不通过直接终止，见 `core/ps/capability.ts:155`）+ `core/ps/layer.ts` 的 `require*` 判定函数（GOVERNANCE §4.1 范本「PS 图层·前提判断的唯一出口」）。
> 谁在用：要把「没选中就弹提示」改成「没选中就置灰不可点」时，本清单是改动范围的上界。
> 禁止：任何「先选图层」操作的门控写第二套（命令层自己调 `getLayerState`/`getSelectionCount` 重判即第二套）。
> 历史：`commands/vectorize.ts` 曾这样写过一次（TD-07-5），2026-11-01 已收口到 CAP `require`。

## 2. 第二类：作用于当前选区、不弹「未选中」提示、由 jsx 自己处理（是否纳入变灰待定）

这批操作对「当前选中图层」生效，但没选中时 jsx 自行返回约定值 / 静默 no-op / 弹对话框，**不触发本仓的「未选中」提示**。要不要一起置灰需你拍板（建议先只做第一类）。

- 常用页 v2：`zoom`（无选区 jsx 返回约定值）、`flip`、`correctBlur`、`swapWireframeFill`、`embedImage`/`embedMultipleImage`/`importMultipleImage`、`toLinkSmartObject`、`linkSmartObjectToSmartObject`、`optimizeDoc`、`batchOptimizeDoc`、`customBuildTransform`、`exportImage`/`exportFirstLevelLayers`/`exportSecondLevelLayers`/`exportPsdImage`、`referenceWidth`、`clearGuide`、`sliceByGuide`、`openDirectory`、`imagePath`、`psdList`
- 样式：`useStyleColor`（遍历选中层，单选多选同一调用）、`applyGradient`
- 矢量化：`vecExport`（jsx 返回 `need-one`）、`vecReplace`
- 重命名：`batchName`、`setLayerColor`（作用于当前选区，未选中时行为未验证）
- 批量文字：`textReadAll`/`textWriteAll`/`textCreateAll`（作用于选区或文档）
- 智能填色：`smartFillColor`/`smartFillLineColor`/`smartReferenceLine`
- 动作：`callAction`/`getActionList`
- 模板（作用于条目/目录，不依赖选区）：`templateThumb`/`templateUse`/`templateOpen`/`templateOpenDir`

## 3. 变灰落地必须解决的三件事

1. **「没选中」与「选错类型」是两种状态，被 `require` 混在一起**。A/C 类在「选了形状却要文字」时也会报错。变灰规则建议统一成「**前置满足才亮**」，否则只盖得住一半报错。
2. **选中数量不在 store**。`useAppStore` 只暴露 `layerKind`/`layerName`（`store/app.ts`），没有选中数。B 类（≥2）、D 类（≥1）、E 类（==1）要置灰，**必须先在 `layer-watcher` 把选中数写进 store**（新建切片字段，不能塞进别人的切片，GOVERNANCE §二 #6）。A/C/F 类可仅靠现有 `layerKind` 判。
3. **「没选中」在 store 的真实表现**：`layer-watcher` 读失败时**保持上次状态、不置 `null`**（`app/layer-watcher.tsx:69-82`），`null` 只在初始值出现。无选区时 jsx 返回的 kind 被归为 `'unknown'`（`core/ps/layer.ts:40`，待真机确认）。所以「没选中」≈ `layerKind === 'unknown'`，而模板现有 `layerKind !== null` 只盖「无文档/未读」、**盖不住「未选中」**——这是现网模板置灰的缺口，修正时要一并处理。
