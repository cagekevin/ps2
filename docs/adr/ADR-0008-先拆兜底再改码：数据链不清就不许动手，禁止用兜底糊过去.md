# ADR-0008 · 先拆兜底再改码：数据链不清就不许动手，禁止用兜底糊过去

- **状态**：生效
- **结论**：改 bug 的第一步不是改行为，而是拆掉沿途兜底、把数据链摆清（谁产生 → 怎么变形 → 谁消费）；兜底数量必须净减、不许净增。兜底把失败原因与数据形状一起抹平，改一次糊一次，最终没人敢改。
- **日期**：2026-11-02
- **裁定人**：用户
- **触发**：同一批缺陷里，两条「修了两次都没修好」的排查都卡在被兜底吞掉的失败原因上

## 背景

仓里长期存在一批「能跑、过测、所以没人动」的兜底：`nodeRequire` 的 `catch {} → null`、`mm_safe` 只回 `e.message`、`storage.getFs` 把 `Result` 重包成 `null`、`commands.assertExportPath` 判不了目录就 `return ok(undefined)`、`decodeLibrary` 的 detail 只有 `root`。它们当初都是为了「别让面板崩」，代价被推给了下一个人。

代价在 2026-11-02 一次集中兑现：

- 矢量化只报「引擎没加载成功」，真因是 `WebAssembly.Compile is disallowed on the main thread`（Chromium 禁止主线程同步编译 >4KB wasm）。中间被 `catch {} → null` 埋掉，连查两轮才露出来。
- 动作面板「文件无法识别」查了两轮，真因是仓库文件被写成读视图 `{"groups":[…],"dropped":[]}`；而 `detail` 只有 `root`，指不出是三个仓库文件里的哪一个。
- 矢量化报「您只能从最前面的文档复制图层」，因为没有行号，只能猜；补上 `@line` 后一轮定位到 `jsx/main.jsx:611` 的 `duplicate`。

既有 `ADR-0003`（同一个失败只变形一次）管的是**形状**，`ADR-0004`（结构优先）管的是**手段**，没有一条管**动手顺序**。于是「先加个 try/catch 让它别崩」永远比「先把数据链摆清」省事，直到没人敢改。

## 判据（它凭什么成立 / 为什么不成立）

兜底的定义（本条只用这一个）：**让「失败」与「没有」长同一个样子的写法**。它同时抹掉两样东西 ——

| 抹掉的 | 后果 | 本仓取证 |
|---|---|---|
| 失败原因 | 诊断力归零，只能靠猜或复现 | `nodeRequire` 的 `catch {} → null` 让 11 个消费点分不清「没有 Node 宿主」与「wasm 编译被拒」 |
| 数据形状 | 类型力归零，两种数据都能过编译 | `getFs` 把 `Result` 重包成 `null`，9 处调用点各造一句 `'fs:null'` |

这两样正是**下一次改码的输入**。它们被抹平后，「改对了」与「改了但被兜底吞掉」在观测上同形 —— 测试绿、日志静、行为没变。本轮实证：删掉 `catch {}` 之前，矢量化两次「修好」其实一次都没生效。

反向判据（加之前必答）：**删掉这个兜底，功能会变吗？** 不会 ⇒ 它只是掩盖，不是容错。

## 决议

1. **顺序不可换**：拆兜底 → 把数据链写清（一段话或一张表：谁产生 → 怎么变形 → 谁消费）→ 再改行为。数据链说不清就不许动行为。
2. **兜底只许净减**：本轮 diff 里「静默 `catch` / 失败归一空值 / 判不了就当通过 / `??` 掩缺失字段」的处数必须净减（X → Y，Y < X）。净增即打回。
3. **失败必须带原因**：`code` / `reason` / `detail` 三张词表各一个名字（`ADR-0003` + 形状收口刀 10）；`detail` 至少带模块名、行号、errno 之一，缺了就算没做完。
4. **重包必须逐字段说明**（刀 14）：`Result → null`、`Result → ok(undefined)` 都是重包，要么原样透传，要么在注释里写明故意丢了哪个字段、为什么。
5. **落点（本轮按此改完，可当样本抄）**：
   - `src/core/cep/node.ts` — `nodeRequire` 返回 `Result<T>`，`detail` = `node:<模块名>:<异常>`；6 个文件 11 处消费点同批迁完。
   - `jsx/main.jsx` 的 `mm_safe` — 返回 `error:<原话> @line <行号>`；`src/core/cep/bridge.ts` 的 `LINE_MARK` 拆成 `reason`（原话给用户）/ `detail`（含行号给排障）。
   - `src/repo/action-repo.ts` — `decodeLibrary(raw, fileName)` 的前缀改必填，8 个调用点全带文件名。
   - `src/core/storage/index.ts` — `getFs()` 返回 `Result`，9 处调用点原样上抛；`exists()` 是布尔探针，文件头写明为何不回 `Result`。

## 后果

- ✅ **收益**：真因一轮可定位。本轮三次都靠这条从「一句人话」直接跳到现场 —— `@line 611` 指向 `duplicate`、`node:…:WebAssembly.Compile is disallowed…` 指向 wasm target、`decodeLibrary` 的 detail 指向具体仓库文件。改完的代码下次还能改，因为失败不再被压成一句安慰话。
- ⚠️ **代价 / 回潮风险**：拆兜底会让**既有失败开始暴露**（原本被吞的错误出现在日志与 toast 里），短期噪声变大；`Result` 会向上传染（`rasterToSvg` 因此变 `async`，调用链跟着改）。这两种「变难看」是预期成本，**不许**因为难看把兜底加回来。
- ⚠️ **例外（照形状收口刀 4，不算兜底）**：文件本不存在（`ENOENT` / 未见过）是正常态，给默认值不算兜底；回滚 / 清理路径（导入回滚、日志 dump、写前读本地）可尽力而为，但**不许返回业务值**，且文件头要写明为何可以不抛。
- 📌 **违反时的判据**（怎么发现又回去了）：
  1. diff 里出现 `catch {}`、`catch { return null }`、判不了就 `return ok(...)`、`?? 默认值` 掩缺失字段 ⇒ 违反。
  2. 兜底处数净增（改前 X、改后 Y，Y ≥ X）⇒ 违反。
  3. 日志出现「加载失败 / 无法识别 / 未知错误」，而 `detail` 里没有模块名、行号或 errno ⇒ 违反。
  4. 说不清「这次改的是哪条数据链」就开始改行为 ⇒ 违反。
