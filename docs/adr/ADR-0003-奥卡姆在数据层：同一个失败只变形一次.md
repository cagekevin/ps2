# ADR-0003 · 奥卡姆在数据层：同一个失败只变形一次

- **状态**：生效
- **结论**：冗余防御＝同一失败被多次转形或重复记录。防御只由生产者提供，消费者只转发；加之前过删除测试，删掉功能不变就不加。
- **日期**：2026-10-28
- **裁定人**：用户（「奥卡姆剃刀，不要那么多防御」「防御必须是生产者提供的，消费者只可以转发」）
- **触发**：同一失败出现两条日志、两层各判一次，消费者开始猜生产者

## 背景

同一个失败在链路上曾有五种存在形式：`Result` / `[]` / `null` / 默认值 / 一条日志。改一处要顺着五种形态找五遍。

## 判据

**冗余防御**：防的事「不会发生」或「发生了也不需要它」，或产出的形态与上一处重复。

| # | 判据 | 怎么验 |
|---|---|---|
| 1 | **一次法则**：同一失败只判一次、只记一次 | 数 `if (status === 'error')` 的层数；`grep` 同一日志文案 |
| 2 | **判别位不落地**：`error` 不许折成 `[]` / `{}` / `null` / 默认值 | 调用方用判 `length` / `?? 默认值` 顶替失败 ⇒ 违约 |
| 3 | **防御归属**：只由生产者提供，**消费者只转发** | 消费者里出现判空 / 改码 / 换文案 / 补默认 ⇒ 违约 |

判据 3 是核心：消费者一旦有了自己的防御，就必然要猜生产者的形状，同一个失败于是有了第二份解释。

## 决议

### 一、加防御前三问（答不出就不加）

1. 上一处已经记过 / 判过？⇒ 不加。
2. 会把 `code` 折成值？⇒ 不加，改为让生产者提供带判别位的形状。
3. 删掉它，用户能做的事和坏数据的可见性会变吗？都不变 ⇒ 不加。

### 二、防御的位置

| 角色 | 允许 | 禁止 |
|---|---|---|
| 生产者（`repo` / `core/ps` / `core/cep`） | 判空 / 缺失 / 坏，给 `Result` + `code` | 把失败折成值 |
| 消费者（`commands` / `store` / `hooks` / `components` / `features`） | **只转发** | 判空、改码、换文案、补默认 |
| 渲染层 | 按 `code` 决定「怎么说」（显示什么、给不给重试） | 改数据形状 |

### 三、删除测试

删掉它跑一次：功能不变 + 坏数据仍可见 ⇒ **删**；功能不变但坏数据不可见 ⇒ 改成「生产者提供」的形态；功能变了 ⇒ 它是能力，按 `ADR-0002` 判。

删不掉的三个候选（行为差异 / 唯一判据载体 / 概念对称）记在 `daily/架构日志/01-跨区-数据流对账-2026-10-28.md` 的判非债表，别重试。

### 四、不透明第三方（jsxbin）

**「生产者」指本仓契约层，不是 vendor。** vendor 读不了不构成「消费者可以做防御」的理由，只构成「必须有防腐层」。

| 角色 | 是谁 |
|---|---|
| 不透明依赖 | `jsx/vendor.jsx`（JSXBIN），只调用不解释 |
| 防腐层（唯一允许猜的地方） | `core/ps/capability.ts` + `raw.ts` + `capabilities.ts` |
| 消费者 | 只转发 `Result`，不碰 raw 字符串、不判 `{err}` 信封 |

**正确防法是换判据，不是加防御**：返回值不可判定 ⇒ 改判调用前可判定的前置条件。实现：能力表 `require` 字段 + 执行器调用前判（一处）；实测 `lenientVoid` 28 处对 `requireTextLayer` 28 处，一一对应。

新增 / 改 vendor 能力：① 真机确认真实返回；② 确认不了配 `require`；③ **不许**把判返回值的逻辑写进 `commands` / `store`。

**什么算「猜」、什么不算**：

- `core/ps` 返回 `Result<unknown>`、消费者把它交给 `domain.decodeXxx(unknown)` —— **合规**：`decode*` 的入参本来就是 `unknown`（`CONVENTIONS §1.1`），收窄是解码层的职责；
- 消费者自己 `isRecord(x) && typeof x.family === 'string'`、`Array.isArray`、判 `length` —— **违约**：这是在猜 vendor 的形状，必须搬进 `raw.ts` 的具名解析器；
- 形状没实测就写死 —— **也不许**：用 `passthrough`，等真机样本再收。
- **不透明载荷原样搬运** —— **合规**：写路径把 vendor 给的整份 `data` 存进库、不挑字段不重建（官方 `app.v4.js:50768` 对渐变就是这么做的）。前提是①搬运路径上不判字段；②读回时的收窄有唯一解码器。

**守卫**：`src/core/ps/vendor-guess.test.ts` 扫全仓 —— `raw` 解析器只允许 `core/ps` 内导入，`callJsx` / `evalScript` 只允许 `core/ps` / `core/cep` 内导入；注入越界必红。

## 后果

- ✅ 失败只有一种形态，改判别位只改一处；排障顺着链路走，不用筛重复文案。
- ⚠️ 会拒掉一批「看起来更保险」的消费者分支；日志变少，排障靠上下文。
- 📌 **违反时的判据**（怎么发现「又回去了」）：同一失败两条日志 / 同一判据两个 `if` / 消费者出现 `??` 补默认或判 `length` / 改一个失败要动三层以上。
