# ADR-0007 · 环是症状职责错位才是病：报环先改职责，拆环手段不算解

- **状态**：生效
- **结论**：环是症状：出现循环依赖先定位「谁被当成了不该当成的东西」（域内基础设施被当对外能力／底层反向依赖上层／feature 互引），改职责。抽 barrel、挪 spec、延迟 require 只是摆平方向，环会换个形式长回来。
- **日期**：2026-10-31
- **裁定人**：架构师（取证后自定）
- **触发**：新增或移动模块、把函数收进能力表、跨层引用、想为解环抽文件或加动态 import 时

## 背景

2026-10-31 把 `layer` 的两个查询（`getLayerState` / `getSelectionCount`）收进能力表，理由是「解析只是缺个具名解析器」。随即出现运行时环：

```
capabilities.ts → layer.ts         （表要 requireSelection 做 spec.require）
layer.ts        → capabilities.ts  （要 CAP.layerState 才能 callCapability）
```

第一次的修法是把 spec 挪进 `layer.ts`、中央表用 `...LAYER_CAPABILITIES` 展开 —— **依赖方向被摆平了，职责一点没动**：`layer` 仍是「能力 + 前置判断提供者」双角色。用户当场指出：环通常是症状而非疾病，只拆环不动职责，环会换个形式长回来。

## 判据（它凭什么成立 / 为什么不成立）

**环的成因只有两类，都指向职责错位**：

1. **底层依赖上层** —— `core` 认识 `features`（`.dependency-cruiser.cjs` 的 `no-core-to-features` 直接拦）
2. **域内基础设施被当成对外能力** —— 这次就是：`getLayerState` 被 `requireLayerKind` 消费、页面从不直接触发，收进表就逼 `layer` 反向 import 表

**为什么「拆环手段」不算解**：抽 barrel（`index.ts` 纯 re-export）、挪 spec、延迟 `require` / 动态 `import()`，改的都是**依赖方向**，不是**依赖关系**。职责错位还在 ⇒ 下次往表里加同一个域的东西，环原样长回来（只是换了一对文件）。

**没有自动防线（2026-10-31 修正）**：`tsc` 不查环。仓里装过 `dependency-cruiser` 并配了 10 条规则（环 / 越层 / 孤儿 / 解析不到 / 引测试…），**实测 7 条从未命中**，34 个依赖 + 一份配置的成本大于收益 ⇒ 已卸载、`check:cycles` 已从 check 链移除。

> 原作 ⇒ 现作：「闸＝`npm run check:cycles`」⇒「无闸，靠评审」。为什么：一个从来没响过的闸与没有闸在当下等价；而真正抓到这个环的是用户看代码，不是工具。需要查环时临时 `npx madge --circular --extensions ts,tsx src`（用一次装一次，不常驻）。

所以本条 ADR 规定的正是「发现之后的动作」—— 这本来就是机器验不了的那一半。

## 决议

**报环后先答一句「哪个模块的哪个职责错了」，答不出就不许动 import 语句。**

| 允许 | 禁止 |
|---|---|
| 把域内基础设施退回 `callDirect`（不进表） | 抽 barrel / `index.ts` 纯 re-export |
| 跨层引用改成依赖注入，或把被依赖的部分上移 | 延迟 `require` / 动态 `import()` 绕开 |
| 拆掉两个 feature 的互相引用（共同依赖下移） | 把 spec / 类型搬到「没有环的那一侧」了事 |
| 承认某函数是域内私有，解析器写进本域模块 | 给扫描器加例外白名单 |

**本次落点**：`src/core/ps/layer.ts`（两个查询退回 `callDirect`，解析器留在本域）、`src/core/ps/capability.ts`（文件头判据补「是不是对外动作」）、`tools/check-jsx-entry.mjs`（白名单同步）、`.dependency-cruiser.cjs`（三条规则）、`package.json` 的 `check:cycles`。

## 后果

- ✅ 运行时环 0（427 模块 / 1379 条依赖）；`layer` 不再认识能力表，**表里每一项都真的是「用户能触发的动作」**
- ✅ 判据从「解析形状」升级为「是不是对外动作」—— 更硬，且能解释为什么有的进表有的不进
- ⚠️ 域内查询走 `callDirect`，不享受表的统一解析 → 靠 `layerStateRaw` / `selectionCountRaw` 两个**域内**解析器补；它们不许进 `raw.ts` 公共清单（否则每个加能力的人多认两个一辈子用不上的名字）
- 📌 违反时的判据（**人工，无自动闸**）：① 报环时没人说得出「哪个模块的哪个职责错了」就直接改了 import；② `git diff` 出现三种指纹之一 —— 新增 `index.ts` 纯 re-export、`await import()` 只为绕环、spec 从中央表搬到域模块；③ 想查环时临时 `npx madge --circular --extensions ts,tsx src`
