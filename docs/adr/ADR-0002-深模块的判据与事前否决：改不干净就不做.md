# ADR-0002 · 深模块的判据与事前否决：改不干净就不做

- **状态**：生效
- **结论**：深模块＝调用方所需知识少于实现内部。事前四问任一不过就不做；旧写法删不净、只靠泛型通用、调用方仍要判空坏，一律不做。
- **日期**：2026-10-28
- **裁定人**：用户（「列第二条 ADR」+ 补充「做不成或更差就别做」）
- **触发**：2026-10-28 把「抽公共文件」当作「做深模块」，抽了 `channel.ts` 却留两处手写订阅表

## 背景

「深模块」常被当成「抽象得好的模块」的口头评价，于是出现三种冒名顶替：

- 把两个文件里的同一段代码抽到一个文件 —— 那是**消重复**，接口和内部一一对应，深度为零；
- 加一层泛型 + 配置对象，调用方仍要知道每个分支 —— 那是**加壳**，复杂度没搬走；
- 抽到一半，旧写法还留着 —— 那是**半收口**（`ADR-0001`），比不做糟十倍。

结果：模块数涨了、调用方没变简单、后来者看到两份样本。

## 判据（它凭什么成立 / 为什么不成立）

**定义**：深模块 = 调用方为**正确使用**它所需要的知识，少于实现内部藏起来的知识。

不是「代码行数多」、不是「文件独立」、不是「有测试」。

**五条判据，全过才敢自称深模块**：

| # | 判据 | 怎么验（可复现） | 不通过的样子 |
|---|---|---|---|
| 1 | 调用方不出现生产方的**结构知识** | 读调用方代码：有没有判 `length > 0`、拼路径、判字段名、判文件格式 | 调用方还在判「空数组 = 坏」 |
| 2 | **同一知识只出现一处** | `grep` 该判据，命中 1 处 | 模块内判一次、调用方再判一次 |
| 3 | 接口**不随实现变化** | 换缓存格式 / 换通道 / 加一种文件状态，调用方要不要改 | 加一种状态就要改调用方 |
| 4 | 复杂度是**搬家**不是蒸发 | 调用方分支数下降 N，模块内分支数增加 M（M ≥ N） | 调用方分支没少 |
| 5 | **有会红的检查** | 每条语义有测试或探针，注入旧实现会红 | 只有注释说明「这里已经收口了」 |

**反例（本仓真实）**：

- `readSystemFontCache` 改前：调用方要判 `status === 'ok'` **且** `fonts.length > 0`，哨兵分支再判一次 → 判据 1、2 不过 = 浅。
- 改后：调用方只判 `status === 'ok'`，「空 / 缺失 / 坏」三种语义全在 repo → 五条全过 = 深。

## 决议

### 一、事前四问（动手前 5 分钟，任一答不出就不做）

| # | 问 | 不做的信号 |
|---|---|---|
| 1 | 调用方现在必须知道什么？（逐条列出来） | 列不出具体条目 ⇒ 没有可藏的东西 |
| 2 | 抽出来后它会少知道哪几条？（必须点名） | 答「更好维护 / 更清晰」= 没有收益 |
| 3 | **旧写法能不能全删干净？** | 不能（还要留着兼容 / 留一处没改）⇒ **直接不做** |
| 4 | 这个模块需要几个互不相关的概念才能表达？ | > 2 个，或必须靠泛型 + 字符串字段名 ⇒ 是壳不是模块 |

第 3 条是硬否决：**删不干净就不做**。删不干净做出来的，就是半收口。

### 二、事后判定（做完立刻验，不过就回滚）

| # | 检查 | 不过怎么办 |
|---|---|---|
| 1 | `grep` 旧写法 / 旧签名 = 0 | 补完，不许「留一处以后再说」 |
| 2 | 调用方分支数比改造前少（给出改前改后数字） | 没少 = 搬家 = 回滚 |
| 3 | 同一能力只剩一个可抄样本（`ADR-0001` 第 1 项） | 回滚 |
| 4 | 每条语义有会红的检查 | 补测；补不出就回滚 |

**回滚优先于保留半成品**：深模块做一半 = 三种状态并存（用新件的 / 长得一样的手写 / 新来不知道抄哪个），这比不做糟十倍。删掉新件、恢复旧写法，是合法且正确的收尾。

### 三、什么时候不做深模块

- 只有 1 个调用方，且它本来就不需要知道内部细节 —— **已经够深**，别加壳；
- 抽出来必须靠泛型 + 字符串字段名才能通用 —— 是壳；
- 抽出来会让调用方跨层（违反 `CONVENTIONS §3` 依赖方向）—— 换位置不叫变深；
- 抽出来需要保留旧实现兼容 —— `ADR-0001` 已禁止，此处同样成立。

## 后果

- ✅ 收益：只有真深的模块会被抽出来；抽一半的情况在动手前就被第 3 问挡住。
- ⚠️ 代价：会拒掉一批「看起来能做」的抽取（本仓今晚只做成 1 个真深模块，另外 2 个是消重复/减宽，按本 ADR 不许叫深模块）。
- 📌 违反时的判据（怎么发现「又回去了」）：
  - 有人用「抽了公共文件 / 加了参数 / 有单测」当深模块的证据；
  - 改造后调用方分支数没下降；
  - 旧写法还在（`grep` 能命中）；
  - 模块新增了泛型参数或配置对象，但调用方仍要判空 / 判坏。
