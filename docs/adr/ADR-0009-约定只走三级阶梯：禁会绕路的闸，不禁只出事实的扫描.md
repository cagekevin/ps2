# ADR-0009 · 约定只走三级阶梯：禁会绕路的闸，不禁只出事实的扫描

- **状态**：生效
- **结论**：结构/类型优先，唯一范本其次，文档最后；代码检查只用现成命令。禁的是「判代码对错、据此报错或阻断、且能被换个位置绕过」的扫描闸；只输出事实或参考结论、恒 exit 0、不进检查链的扫描可建。
- **日期**：2026-11-08
- **裁定人**：架构师（取证后自定 · 2026-11-08 按用户裁定制订）
- **触发**：—

## 背景

模板仓库带进了 `scripts/check-any-honesty.mjs`（本仓 `scripts/` 里仍有这个文件，但从未接进 `check` 链），AGENTS 也沿用了「能做成闸就做成闸」的措辞。那个仓里还写过一个 14 条正则规则的 `check-conventions.mjs`（本仓没有这个文件，git 历史里也没有）。两次都指向同一件事：扫描式闸会把人引向「让检查通过」，而不是「让错误写不出来」——注释里解释 `throw new Error` 会被误报，真正的结构问题却照样能绕过去。

**但这不等于「凡扫描一律不许」。** 2026-11-08 用户裁定：扫描本身不是问题；问题是把它做成「AI 不这样写就报错」的闸，尤其是靠正则查「某处不许出现 X」——AI 直接换个文件写同样实现即可绕过，闸没拦住，还多一套维护。只输出客观事实（谁引用了谁、真实退出码、残留位置）供人／AI 参考的扫描，可以建。

## 判据（它凭什么成立 / 为什么不成立）

- ADR-0004：能让写错编译不过，就不写文档。扫描闸只是文档的自动朗读版，不是结构。
- 本仓 `npm run check` 只用现成工具：`tsc --noEmit` → `eslint` → `stylelint` → `vitest run`，另有三个结构对账脚本（`check-templates` / `check-nav` / `check-jsx`）与只复述事实的 `post-check.mjs`。再写一个判定「合规／不合规」并阻断的**源码正则扫描器**，就多一套解析器和一套误报豁免，最后变成第二本账。
- **一条禁令若能被 AI 换个位置写同样实现绕过去，它就是「反向闸」**：价值为负 —— 没让错误写不出来，只教会 AI 绕路。典型：某文件不许出现 `fetch` ⇒ 第二处 `fetch` 写到别的文件；不许用 `process.cwd` ⇒ 换个包装函数照样落。
- 有些东西 TS 确实禁不掉（全局 `fetch`、`console`、`process.cwd`）。对它们，正确答案不是「加扫描」，而是「让第二处没有必要存在」：把 url / 凭据 / 超时收进闭包，把 cwd 解析收进唯一样本。
- 只出事实的扫描不进任何判定链，误报只是多看一眼；它不产生「必须照做」的动作，因此没有绕行激励。

## 决议

**约定落点只有三级，没有第四级：**

1. **写不出来**：类型、判别联合、私有构造、工厂、端口类型、穷尽 `switch` + `never`。能用这一级就只用这一级。
2. **抄不错**：只保留一个范本文件，AGENTS 只写「照哪个文件抄」。不再写第二份等价说明。
3. **写清楚**：前两级都做不到时才写文字，并注明为什么只能靠文字（通常是 TS 管不到的全局对象或流程）。

**检查边界：**

- 代码检查只用现成命令：`tsc --noEmit`、`eslint`、`stylelint`、`vitest run`（完整链路见 `package.json` 的 `check`）。
- ADR / 债务 / 架构索引脚本是流程工具，可以用来检查文档账本，**不得用来判断代码写得对不对**。
- **不建「闸」**：任何判定代码合规、并据此报错 / 非零退出 / 拦提交 / 进 `check` 的扫描脚本，一律不建；尤其是正则写的「某处不许出现 X」禁令。
- **允许「只出事实」的扫描**：只输出客观事实或参考结论，自身恒 `exit 0`、不进 `check`、不接提交钩子、不要求 AI 照做。`check-conventions.mjs` 本仓从未有；`check-any-honesty.mjs` 仍在 `scripts/`（模板仓遗留），**未接进 `check`** —— 它判定 any 的写法属「可绕过」，不得接回检查链。
- 显式 `any` 不再靠脚本拦截：外部输入一律 `unknown` 进解析函数，公共签名不留 `any` —— 入口是 `src/types/json.ts` 的 `parseJson`、`src/types/guards.ts`（`isRecord` / `isArrayOf`）、`src/types/decode-list.ts`，`src/` 现为 0 处 `any`。平台边界只有一处：`window.__adobe_cep__` 由 `src/core/cep/bridge.ts` 的 `declare global` 声明类型，且只在该文件内取用。
- 全局 `fetch` 禁不掉：`src/core/http/client.ts` 的 `request` / `postText` 在内部取 token（`getToken`）、持有超时常量、地址经 `endpoints.ts` 的 `resolveUrl` 拼出，调用方只给 key；新增接口只动 `src/core/http/endpoints.ts`。

**边界补充：出事实 ≠ 机器闸。**

| 工具 | 产出 | 不做什么 |
|---|---|---|
| `probe.mjs` | 负例证据：临时改坏一处 → 跑 `npm run check` → 断言确实红 → 无条件还原 | 不选测试、不缓存、不拦提交，也不接进 `check` |
| `mv-sync-refs.mjs` | 数据流事实：谁 import 谁、串残留引用在哪、搬移会影响哪些文件 | 不判合规、不出通过/失败结论 |
| `post-check.mjs` | 回执：把 `AGENTS.md` 里的交付四问原样打印给正在交付的人 | 不判断代码对错，自身恒 exit 0，读不到就静默跳过 |

`extract-detours.mjs` / `ts-strict-detail.mjs` 仍在 `scripts/`（模板仓遗留），本仓没有它们的消费场景、也没有调用点；它们不进 `check`，不影响本结论。

**【2026-11-08 修正留痕】** 原结论写作「自创扫描脚本一律不建」；按用户裁定收窄为「只禁会绕路的闸，不禁只出事实的扫描」。原因：原措辞会把「只输出事实、供人参考」的观察工具一并误杀，而这类工具没有绕行激励。

## 后果

- ✅ 不再维护第二套解析器与豁免名单；检查失败只可能来自类型、lint、结构对账、测试。
- ⚠️ `console`、`process.cwd`、默认导出这些只能靠范本与评审，回潮时不会被自动发现。
- 📌 **违反时的判据**（怎么发现「又回去了」）：新增判定合规并阻断的 `src/` 扫描脚本；新增「某处不许出现 X」的正则禁令；`check` 链出现自写的源码正则检查；同一状态出现第二个解析函数；`src/core/http/client.ts` 之外出现 baseUrl / 凭据 / 超时。
