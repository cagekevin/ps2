# ADR-0004 · 结构优先于 ADR：能让写错编译不过，就不写文档

- **状态**：生效
- **结论**：最优是让这件事没有第二处可做；其次才让写错编译不过。「抄不错」只是次优，ADR 最后。（其余各条都属「文档留痕」级，能结构化就别靠）
- **日期**：2026-10-28
- **裁定人**：用户（「结构上不可能，别人永远抄不错，永远大于落 ADR」）
- **触发**：一晚连落三条 ADR 后，发现其中两条本该用类型或入口解决

## 背景

本条是「一处真相」的**载体面**（总纲见 `ADR-0001`）：同一处真相，能靠结构守就别靠文档。判据写成文档靠「读到的人会遵守」，写成结构靠「写错编译不过」——后者不依赖自觉。

一晚出现过两次「本来想写 ADR」：读同步/写异步（类型已挡）、视图/原始不许混用（做不成，删 `records` 会破坏拖拽真实下标）。两条都不该占编号。

## 判据

**升级阶梯**（从强到弱，优先用上面的）：

| 级 | 手段 | 为什么强 |
|---|---|---|
| 0 | **消灭需求** | 这件事没有第二处需要做：吸收进唯一入口 / 表驱动 / 内建默认值 |
| 1 | **类型 / 入口** | 写错编译不过，不依赖任何人自觉 |
| 2 | **唯一产出点** | 拿不到第二份材料（例：`raw.ts` 是唯一解析处） |
| 3 | **测试扫描** | 能红，但可以被绕过或被误删 |
| 4 | **ADR** | 靠人读到、且靠人记得 |

**级 2 就是「别人抄不错」，它是次优**：默认了「第二处存在」，只是让样本唯一。
最优是级 0 —— 那个位置根本不存在，连抄这个动作都没有。

两档在本仓的实例：

| 约束 | 级 | 为什么升不上去 |
|---|---|---|
| `mutateJsonFileOr` | **0** | 「失败往哪放」被入口吸收，不再有「闭包捞失败」这个模式 |
| 能力表 `parse` | **0** | 新增能力填表即可，不必抄一个能力函数的写法 |
| `SETTINGS_FILE`、`raw.ts` 唯一 | **2** | 两个 repo 都要写、多个能力都要解析 = 需求真实存在，只能让材料唯一 |

**判据两问**（按顺序问）：
1. **这件事能不能不需要第二处？** 能 ⇒ 合并 / 表驱动 / 内建，做到级 0。
2. 不能（需求真实存在，两处都必须做）⇒ 退一级：让它**抄不错**（级 1/2），而不是写 ADR。

答不出「为什么升不到 0 或 1」⇒ 才写 ADR，并在正文里写明结构为什么做不到。

## 决议

### 一、新增 ADR 前必答两问

**① 这件事能不能不需要第二处？② 不能的话，为什么不能用类型 / 入口解决？**

- 两问都答不出（跨全仓行为、语义判断、需要人做取舍）⇒ 写 ADR；
- 任一答得出 ⇒ 不写 ADR，去改结构。

### 二、已有 ADR 可被结构替代时，替换并撤销

结构一旦能挡，ADR 就是冗余 —— 按 `ADR-0001`（同一件事只留一个样本），撤销该条并留一句迁移说明。
ADR 越少越好，不是越多越好。

### 三、什么只能靠 ADR

「半收口」「深模块的深度」「消费者不该补判断」都属于**语义判断**，类型表达不了；跨文件的取舍（优先级、范围、命名）同理。

## 后果

- ✅ ADR 数量收敛；约束变成编译错误或唯一入口，不再依赖「下一个 AI 会不会读」。
- ⚠️ 代价：结构改造比写文档贵；短期只能靠 ADR 的地方要明确标注原因。
- 📌 **违反时的判据**（怎么发现「又回去了」）：
  - 新增 ADR，但答不出「为什么结构做不到」；
  - 同一个约束既有 ADR、又有结构（两份真相）；
  - 用「测试扫描」代替了本可以做的类型约束（测试能被删，类型不能）。

> 本条是元规则，别单读 —— `ADR-0001`（半收口比不做更糟）/ `ADR-0002`（深模块的判据与事前否决）/ `ADR-0003`（奥卡姆在数据层）/ `ADR-0005`（一个能力一个入口）/ `ADR-0006`（改码按下一个 AI 读不读得懂为准）都属「文档留痕」级，能升为类型 / 入口 / 结构就别靠它们。
