# ADR-0001 · 半收口比不做更糟：做完必须自列检查项并全部过关

- **状态**：生效
- **结论**：同一能力只能剩一个可抄样本；抽取／改签名／改模块必须同批收完。每完成一件事自列检查项，全过才算做完。
- **日期**：2026-10-28
- **裁定人**：用户（明确同意，「这条可以列为 ADR」）
- **触发**：一晚内出现三次半收口（越权写 ADR、体检扫全仓、抽公共件只抽两处），用户说体检时需要以这个 ADR 结论为准。

## 背景

2026-10-28 一晚之内出现三次「半收口」：

- 没经用户同意就把判据写成 ADR（越权）；
- 体检范围从「本轮改动」扩到全仓，查了一堆无关文件；
- 抽了 `channel.ts`，却只收 `toast` / `loading` 两处，`core/auth` 与 `components/Confirm` 还各留一份手写订阅表。

三次都不是「没做」，是「做了一半」。做一半比不做严重：后来者看到两份样本，不知道该抄哪份；越抄越乱，最后没人能判断哪个是「现在」。

## 判据（它凭什么成立 / 为什么不成立）

一句话：**这轮改完，下一个人（或 AI）动同类能力时，会照哪一个抄？**

- 只有一个答案 ⇒ 合格；
- 两个及以上 ⇒ 不合格，**且比不收口更糟**。

为什么不能用「有没有 bug」当首要目标：

- 机器闸（ESLint / typecheck）只能拦「符号不唯一」，拦不住「语义半收口」（抽了一个、留一个）；
- 本仓已付过学费：`emitAppEvent` 转正后仍有两套失败表达、`sj_set.json` 文件名写两份、`toast` / `loading` 逐行同构；
- 判据不写下来，每个 AI 都会按「主要几条改完 = 完成」交付。

落点：`docs/GOVERNANCE.md` §7.0（体检首要目标）与 §7.5（半收口当场修完，不许拆成两次）。

## 决议

每完成一件事，交付前必须自列下面 6 项并逐项给证据；任一不过 = **没做完**，不许写「已完成」。

| # | 检查项 | 证据形态 |
|---|---|---|
| 1 | 同一能力只剩一个可抄样本 | `grep` 命中数 N → 1 |
| 2 | 旧签名 / 旧调用点 / 旧描述归零 | `grep` 0 + `tsc` 0 |
| 3 | 新增 / 改名 / 删除的模块已进 `CONVENTIONS §3` 目录树与 `GOVERNANCE §4.1` 清单 | 逐条对照 |
| 4 | 文档写的边界有机器闸拦；没有就登记一债 | `npm run lint` 真红过 |
| 5 | 每条「改好了」都有会红的检查，且先红真红过 | 注入旧实现 → 红 → 还原 |
| 6 | 范围外的发现另开一债，不混进本次 | `debt.mjs list` |

**半收口的五种形态**（见一次修一次，不许排期）：

1. 抽了公共件，同类手写实现还剩一处；
2. 改了签名 / 返回值，旧调用点还在；
3. 新增 / 改名 / 删除模块，没进目录树与范本清单；
4. 文档写了边界，机器闸却没拦（假护栏）；
5. 宣称「已收口」但只改了主要几条。

## 后果

- ✅ 收益：后来者永远只有一个样本可抄；半收口在交付前被拦下，而不是靠下一轮审计翻出来。
- ⚠️ 代价：每件事多花 10–20 分钟做证据；抽公共件时被迫同批改完所有调用点，不能「先抽两处试试」。
- 📌 违反时的判据（怎么发现「又回去了」）：
  - 交付说明里出现「主要改完了 / 剩下的后面再说 / 顺手也改好了」；
  - 同一能力存在两个可抄样本（`grep` 能找到两份）；
  - 宣称「已收口」但只改了主要几条；
  - 文档写了边界而 `eslint` / `typecheck` 拦不住。
