# ADR-0001 · 半收口比不做更糟：做完必须自列检查项并全部过关

- **状态**：生效
- **结论**：同一能力只能剩一个可抄样本；抽取／改签名／改模块必须同批收完。每完成一件事自列检查项，全过才算做完。（入口见 `ADR-0005`，深模块见 `ADR-0002`，可读性见 `ADR-0006`，勿单读）
- **日期**：2026-10-28
- **裁定人**：用户（明确同意，「这条可以列为 ADR」）
- **触发**：一晚内出现三次半收口（越权写 ADR、体检扫全仓、抽公共件只抽两处），用户说体检时需要以这个 ADR 结论为准。

## 总纲（这 6 条判据只讲一件事）

**同一个东西，仓里只能有一处「说得清、抄得对、破坏得了就报错」的真相。** 分三层：

1. **只许一处**：不许第二份样本 / 第二条线 / 第二处判断。本条＝底线；入口面见 `ADR-0005`（一个能力一个入口）、知识面见 `ADR-0002`（深模块的判据与事前否决）、失败语义面见 `ADR-0003`（奥卡姆在数据层）。
2. **这一处要读得懂**：见 `ADR-0006`（改码按下一个 AI 读不读得懂为准）——集中 ≠ 可读，职责分清。
3. **先改入口，再谈守**：见 `ADR-0004`（结构优先于 ADR）——让错误写法编译不过 / 结构上不可能发生；靠 lint 或文档禁止才没人用错，说明入口设计不合格，先改入口，不是加规则。

## 背景

2026-10-28 一晚之内出现三次「半收口」：

- 没经用户同意就把判据写成 ADR（越权）；
- 体检范围从「本轮改动」扩到全仓，查了一堆无关文件；
- 抽了 `channel.ts`，却只收 `toast` / `loading` 两处，`core/auth` 与 `components/Confirm` 还各留一份手写订阅表。

三次都不是「没做」，是「做了一半」。做一半比不做严重：后来者看到两份样本，不知道该抄哪份；越抄越乱，最后没人能判断哪个是「现在」。

## 判据（它凭什么成立 / 为什么不成立）

一句话：**这轮改完，下一个人（或 AI）动同类能力时，会照哪一个抄？**

- 只有一个答案 ⇒ 合格；
- 两个及以上 ⇒ 不合格，**且比不收口更糟**。

为什么不能用「有没有 bug」当首要目标：

- 机器闸（ESLint / typecheck）只能拦「符号不唯一」，拦不住「语义半收口」（抽了一个、留一个）；
- 所以「补一个闸」不是收口动作：它只证明当下没踩坏，不证明没有第二条线；把约束放进类型与唯一入口，才让后来者抄不错。
- 本仓已付过学费：`emitAppEvent` 转正后仍有两套失败表达、`sj_set.json` 文件名写两份、`toast` / `loading` 逐行同构；
- 判据不写下来，每个 AI 都会按「主要几条改完 = 完成」交付。

落点：`docs/GOVERNANCE.md` §7.0（体检首要目标）与 §7.5（半收口当场修完，不许拆成两次）。

## 决议

**2026-11-07 修正（用户裁定）**：原第 4 项「文档写的边界有机器闸拦；没有就登记一债」⇒ 现「边界靠入口保证，缺闸不算违规」。
原因：闸拦不住语义半收口；靠 lint 禁止才没人用错，说明入口设计不合格（`CONVENTIONS §0.5` 原则一）。把「没闸」登记成债，会逼出为销债而新增闸的动作，与「要改入口，不是加规则」相反。总纲第 3 条、半收口形态 4、后果判据与第 5 项验证口径同批修正。

每完成一件事，交付前必须自列下面 6 项并逐项给证据；任一不过 = **没做完**，不许写「已完成」。

| # | 检查项 | 证据形态 |
|---|---|---|
| 1 | 同一能力只剩一个可抄样本 | `grep` 命中数 N → 1 |
| 2 | 旧签名 / 旧调用点 / 旧描述归零 | `grep` 0 + `tsc` 0 |
| 3 | 新增 / 改名 / 删除的模块已进 `CONVENTIONS §3` 目录树与 `GOVERNANCE §4.1` 清单 | 逐条对照 |
| 4 | 边界靠入口保证（写错编译不过 / 结构上不可能）；**缺闸不算违规，不得因缺闸登记债** | 举出错误写法并说明它为什么写不成；已有闸只核对其仍有效 |
| 5 | 每条「改好了」都验证过错误写法确实出错；验证不要求落地成闸 | 临时注入旧实现 → 观察到预期失败（编译错 / 运行错 / 结果不符）→ 还原 |
| 6 | 范围外的发现另开一债，不混进本次 | `debt.mjs list` |

**半收口的五种形态**（见一次修一次，不许排期）：

1. 抽了公共件，同类手写实现还剩一处；
2. 改了签名 / 返回值，旧调用点还在；
3. 新增 / 改名 / 删除模块，没进目录树与范本清单；
4. 只写文档 / 加规则声明边界，入口却仍能写出错误用法（假收口）；
5. 宣称「已收口」但只改了主要几条。

## 后果

- ✅ 收益：后来者永远只有一个样本可抄；半收口在交付前被拦下，而不是靠下一轮审计翻出来。
- ⚠️ 代价：每件事多花 10–20 分钟做证据；抽公共件时被迫同批改完所有调用点，不能「先抽两处试试」。
- 📌 违反时的判据（怎么发现「又回去了」）：
  - 交付说明里出现「主要改完了 / 剩下的后面再说 / 顺手也改好了」；
  - 同一能力存在两个可抄样本（`grep` 能找到两份）；
  - 宣称「已收口」但只改了主要几条；
  - 用文档或 lint 声明了边界，入口却仍能写出错误用法（说明该改入口）。

> 单读本条会误判 —— 深模块的「事前否决」见 `ADR-0002`（深模块的判据与事前否决）；「旧入口先删」见 `ADR-0005`（一个能力一个入口）；「写全了却没人看得懂」见 `ADR-0006`（改码按下一个 AI 读不读得懂为准）；能结构化就别靠本条，见 `ADR-0004`（结构优先于 ADR）。
