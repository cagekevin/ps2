# 图层 原文
替换（每行对应上面一层；留空 = 清空该行）
每行一个文字图层

新建：一个输入框，一行一层 → 确定 → 文档里多出 N 个文字图层。排版按下面那套默认方案自动做，用户不满意再自己调。

改字：「全部」读整个文档的文字层；「读取」读点按钮那一刻 PS 里选中的文字层（非文字层直接过滤）→ 下栏逐行改 → 确定写回原来那些层，位置样式都不动。

留空 = 清空该行。框内即该行最终文字；空行是把那行清空，算改动（全空 = 全清，不拦）。行数必须等于读到的层数。

层内换行显示成 ⏎（读入转换、写回还原），所以「一行 = 一层」恒成立，段落层也能改。

蓝条 + 整行高亮 = 光标所在行对应的那一层。

落点：替换原来的「切换方向」按钮（zt_switchFontDirection），那个功能不用了。跟同排其他图标完全一致：26 格 / 图标 20 档 / 同 hover，没有蓝底、没有任何入口标记。

图标：入口用 icon-nav_piliangtaoban（sprite 里唯一带「批量」语义的），同排 5 个用字体面板现成的 iconchaifen / iconanniu / iconfanyi / iconfuzhiwenziyangshi / iconniantiewenziyangshi。全部 20 档。

入口图标的尺寸坑：它是 nav 图标，sprite 里画在 128..912 / 164..896，四周留白比工具图标大一圈，直接套 0 0 1024 1024 会比同排小 15%。这里用紧 viewBox 80 90 880 880 把它撑到同样的视觉大小 —— 不许改成给按钮单独调 font-size，那会让同排出现第二档图标尺寸。

新建的默认排版（一套公式，行数任意）

  • 首行字号 = 层级第 1 档 ztHierarych[0]（默认 92），末行 = 首行 × 0.5。
  • 中间等比：r = 0.5 ^ (1 / (N-1))，第 i 行 = 首行 × r^(i-1)；不足 6pt 按 6pt 兜底。
  • 首末比 0.5 是唯一可调常量（要更平就 0.6、更陡就 0.4），代码里只写这一个数，别再引第二套层级表。
  • 顺序：第 1 行在最上，向下堆叠。
  • 对齐：就是 PS 属性面板那三个按钮（左 / 居中 / 右），管的是每个文字层自身的段落对齐，跟画布无关。默认「左」，每层建好后调一次 zt_setTextAlignment(0)；所有层同一个值，不按层级区分。与官方默认 align=0 一致。
  • 间隔：自动，按上一行字号算（官方 autoCountInterval 默认开）。
  • 字体：思源黑体 CN / Regular —— 建层后逐层 zt_setFontName('SourceHanSansCN-Regular', 'Source Han Sans CN Regular', 'Regular') 应用。字体缺失就保留 PS 默认、状态行说一句，不阻断建层。来源：官方快捷字体默认第一项（app.v4.js:40154）。
  • 颜色：取字体面板当前设置。
  • 落点：整组垂直居中于当前视图中心，向下堆叠；每层左边缘从同一条竖线起排（这是图层定位，不是上面那个对齐按钮）。
  • 历史：一次确认 = 一步 suspendHistory。

任意行数都成立：3 行 → 92 / 65 / 46；6 行 → 92 / 80 / 70 / 61 / 53 / 46；20 行 → 92 一路平缓降到 46，每行只差 3~4%，不会突然断层。行数只决定步长，落差始终是 2:1。

依据：官方 zt_smartTypesetting（app.v4.js:39921）里 type（常规 / 强烈 / 接近 / 相同）就是控制落差强度的 —— 上表相当于「接近」那一档，不用官方的固定层级表（6 档 92→12 落差 7.7 倍，太陡，而且超过 6 行就没有第 7 档可用）。实现顺序：先 npm run probe:ps 探这个函数在不在 vendor 里，在就直接调它、参数照上表；探不到才自己算（行距 = 上一行字号 × 0.4）。

做这一版时踩过的错，下一个 AI 别再犯

  • 整份重写：把用户要优化的 mockup 换成自己那套。只许在原文件上改，删错误逻辑，不删能力。
  • 假业务样例：拿「主标题 / 副标题 / ￥199」当数据，等于把适用范围缩到某个假想 PSD。图层名用 PS 真实命名，文字与图层名无关，界面不出现业务场景。
  • 一行 = 一层：段落层内部就有换行，按 \n 拆行会整体错位、把字写到别的层。层内换行用 ⏎ 占位。
  • 替用户定落点：编「第一行在最上 / 按行距向下堆叠 / 插入当前组内 / 用面板字号」。位置、样式、顺序交给 PS 原生。
  • 把自由换成选项：用「全部 / 选中 / 当前」三档代替用户在 PS 里自己多选。选择发生在 PS 里，面板只给「全部」「读取」两个按钮。
  • 假按钮：三档作用范围只换提示文案、数据一动不动。按钮必须真换数据，否则删掉。
  • 一层一格输入框：不能全选、不能整段粘贴、不能连着打字。用一个 textarea 逐行改。
  • 多余的提示与流程：跳过计数、结果页、二次确认、丢弃拦截、空态文案。非文字层直接过滤不提示；只在真会写错层时才报（行数不符、目标层已不存在）。
  • 留空语义：框内即最终文字，空 = 那行清空，算改动（全空 = 全清，不拦）。标签、计数、禁用三处一致，不报「第 N 行是空的」。
  • 没改动也能提交：会把相同的字重写一遍、触发 PS 重排。改动数为 0 时确定禁用。
  • 两模式共用一份内容：切 tab 丢字、切回来行数对不上。两个模式数据不共享。
  • 双向绑 scrollTop：两栏高度不同，钳位后互相回写，textarea 自己跳回上面。只单向按光标行 scrollIntoView。
  • 为了对齐硬把 textarea 设成不折行：行号映射靠数 \n，跟折行无关；wrap=off 只是把长文本逼成横向滚动，白砍自由度。列表省略显示即可，textarea 正常折行。
  • 凭样例推规则：从「第 1 行是标题」反推通用行为。顺序只传递、不解释。
