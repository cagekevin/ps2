## 2. 三条命令（按顺序，都在仓库根）

```bash
npm run check                                  # 先确认还是全绿
npm run deploy                                 # 65 个文件 → CEP 目录；探针读的是部署目录那份
npm run probe:ps -- --group=text --ensure-text  # 会改文档，用测试文档
```

第三条现在只支持 Windows（PS COM）。**没给 macOS 加分支**：这台机器连 PS 都没装，加了也验不了，交一段没人跑过的平台代码不如不交。

`--group=text` 会跑这四条（都是只读或空参数，不动文档内容）：

```
mm_text_readAll("all")                                        → {"layers":[...]}
mm_text_readAll("selection")                                  → {"layers":[...]} 或 {"layers":[]}
mm_text_writeAll(JSON.stringify([]))                          → {"ok":0,"failed":[]}
mm_text_createAll(JSON.stringify({lines:[],sizes:[],font:{},align:0})) → {"ok":0,"fontMissing":false}
```

四条参数都是空数组 / 空配置，**不会改文档内容**，所以没有文字层的文档也能跑。

## 5. 已知限制（不是 bug，别当 bug 修）

- 智能对象内部的文字层**读不到**（PS 不允许脚本进智能对象），列表里不会出现，也不提示。
- 锁定层读得到、写不进，写回报告里进 `failed`，界面说一句「有图层没写成」。
- 行数必须等于读到的层数：粘贴一整段多行文本会被拒（「一行 = 一层」的模型代价）。
- 新建只给一套默认排版（首行 = 层级第 1 档、末行 ×0.5、左对齐、思源黑体），没有选项 —— 用户不满意自己调。
